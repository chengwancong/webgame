**B2 实施细节（2026-10-09 补充，回答“具体目标是什么”）**

1. **致命一击**：`packages/simulation/combat-review.ts` 已记录最近 5 次受击（来源、技能名）。取**最后一次**受击作为致命一击，在 contracts 的回顾结果里新增字段（敌人名、技能名、伤害、伤害类型、附带状态、提示句）。其余受击不在主界面列出，最多放进折叠区。
2. **一句行为说明（应对提示）**：在 `packages/content/chapter-combat.ts` 的 `MonsterSkillDef` / `BossSkillDef` 加一个可选字段 `hint`：玩家语言，≤20 字，说这招怎么来的（例：“它会绕到你身后出手”“地面发红后会炸开”）。给 `monsterSkills` 和全部 Boss 技能逐条填写。没填的技能按技能类型/伤害类型从一张通用表取默认提示（按类型，不按技能 ID 硬编码），并让内容校验对缺 `hint` 的技能给出告警清单。附带状态（减速、眩晕等）以小标签显示在招式名旁边，不另写句子。
3. **建议按钮**：服务端按死因类型选出最多 3 条建议，客户端只渲染。建议的映射规则写成一张表（放在内容源或 rules）：
   - 近身爆发 / 背刺 / 被围 → 控场技能、生存天赋、强化护甲
   - 远程 / 地面范围 → 生存天赋、强化护甲（可加“留意地面红圈”提示句）
   - 元素伤害或持续伤害 → 对应抗性装备、生存天赋
   - 没死但超时，或对首领打不动 → 强化武器、输出天赋、换更强的主手

   每条建议带跳转目标（技能页 / 天赋页 / 强化页），按钮文字 ≤6 字。
4. **删除玩家可见的测量数据**：“有输出秒数”“事件记录 x 秒”“占比”“秒伤/DPS”不再出现在结算页。`apps/api/src/dungeon-diagnostics.ts` 里的统计（需求 DPS、实际 DPS、净承伤）保留，它们是数据，只是不直接显示；可用于服务端选择建议（例如实际 DPS 远低于需求 → 输出类建议优先）。
5. **钥匙进度**：显示具体钥匙碎片名 + 当前/所需 + 一句“哪里会掉”。
6. **测试**：致命一击取值、`hint` 回退、建议映射各写定向测试；禁用词测试中的结算页命中清零。

- 信息取舍：玩家此刻要回答的那个问题优先，其余放进折叠区或 Tooltip 第二行。
