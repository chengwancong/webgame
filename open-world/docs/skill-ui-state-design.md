# 技能界面状态设计

本文件记录用户确认并已落地的状态约定。用户要求未激活时只有激活，已激活时只有升级；激活可以按等级条件或按技能书条件进行。

## 技能生命周期

资格与激活是两个不同维度。每个技能由配置指定激活方式；达到等级条件或拥有指定技能书，只决定能否执行激活。成功响应确认之前仍是未激活。

当前等级方式采用达标后手动激活；基础三项出生时已激活。以后若增加自动激活配置，必须由服务端确认后直接进入已激活，不能由界面按等级预测。

| 技能状态 | 详情显示 | 技能操作 | 装配权限 |
| --- | --- | --- | --- |
| 未激活，等级条件未达成 | 所需等级、当前等级、无资源消耗 | 激活，禁用；说明缺少等级 | 不可装配 |
| 未激活，等级条件达成 | 已达成等级条件、无资源消耗 | 激活，可执行 | 成功确认后才能装配 |
| 未激活，缺少指定技能书 | 书名、需要数量、持有数量及缺少数量 | 激活，禁用 | 不可装配 |
| 未激活，指定技能书足够 | 书名、实际激活消耗、持有数量 | 激活，可执行 | 成功确认后才能装配 |
| 已激活，未满级，升级资源足够 | 当前等级、下一级预览、升级报价、持有资源 | 升级，可执行 | 可以装配 |
| 已激活，未满级，升级资源不足 | 升级报价、分别不足的资源与缺少数量 | 升级，禁用 | 仍可以装配 |
| 已激活，满级 | 当前等级、已满级；无下一级及升级费用 | 升级，禁用并标明已满级 | 仍可以装配 |

未激活的详情不显示当前技能等级1/5、升级预览、升级费用或升级按钮。已激活的详情不显示激活方式、激活消耗或激活按钮。其他技能卡片可以展示自身未激活条件，不与当前所选技能的操作混淆。

等级激活无资源扣除；技能书激活需消耗配置指定的技能书数量，不能擅自叠加等级、金币或灵石条件。设计稿用一本技能书作为示例，实际数量与具体技能的激活方式等待配置确定。

## 请求状态

- 报价未加载、加载失败、报价失效：显示相应原因，禁用技能操作；不把未知费用显示为0。
- 激活中／升级中：操作按钮显示对应处理中状态，禁用重复提交。锁定本次操作的技能与报价，切页不改变请求目标。
- 成功：以服务端确认状态更新技能、等级、钱包与技能书；激活成功后出现升级操作，可以装配，但不自动塞入装配草稿。
- 明确失败：保留之前生命周期状态与装配草稿，显示失败原因；刷新报价和资源后决定是否可重试。
- 超时、响应丢失、结果未知：显示结果待确认，禁用再次扣费操作；先核对原操作回执。未确认前不报告成功，也不报告资源已返还。
- 不同账号、控制权失效、离线：显示恢复连接或控制权提示；保留草稿，禁用持久操作。

## 即时装配与快速定位

2026-10-03 用户确认：底部技能槽只用于快速定位，切换到技能所在分类并显示详情，不执行卸下。定位时清空搜索与可用性筛选，确保目标卡片可见。右侧根据该技能当前状态显示“装配”或“卸下”，点击后沿现有 skills 命令提交并等待服务端回执，立即更新底部装配和战斗快捷栏。

取消草稿、保存按钮与退出保存确认。技能列表也只负责查看，不保留直接装卸的复选框。升级与激活保留原有生命周期；装配不受升级金币是否足够影响。仍最多装配4项、至少保留1项；未激活、技能位已满、副本构筑冻结和连接未恢复时，禁用对应操作并说明原因。

提交期间禁止重复写入；失败保留服务端已确认装配，网络结果待确认时沿原有 outbox 与回执恢复，再显示真实状态，不把未确认操作当作成功。

## 视觉约定与验收

切换技能与交互状态须遵循根目录 [项目.md「状态切换与布局稳定」](../../项目.md#状态切换与布局稳定)。连续选择已激活与未激活技能，包含滚动后的条目，核对卡片和详情图标尺寸、内容对齐、选中边框与列表滚动位置；长名称不得挤压详情图标。技能页的实机回归入口为 `tools/accept-skill-selection-layout.mjs`，与生命周期验收分别覆盖布局稳定和功能状态。

保持当前V2现代卡通奇幻视觉与分类分页，技能页不展示角色立绘。激活与升级共用一个次要技能操作位置；装配／卸下为浅金色，同尺寸、同字体、同圆角。禁用态保留按钮身份并辅以文字原因；状态不能仅由颜色表达。

设计稿至少展示等级激活、技能书激活、已激活升级、满级；条件不足与资源不足的差额必须正确，不能画出同时激活和升级。持久激活已通过skillRanks的条目存在性记录，并实现skills/activate命令；skillAccess明确区分eligible与activated，不再以等级资格代替激活。
