# Grok 测试服跑测指南

## 可直接粘贴的提示词

```text
请测试《深渊行者》测试服：https://43-165-179-11.sslip.io/
访问用户名和口令：向用户索取。不要把口令写入报告、截图、公开链接或日志。

始终使用同一个持久浏览器会话和一个标签页，保住 cookie。不要在每一步新建浏览器、清 cookie 或重复登录。
游戏账号用你自己的用户名，从 qa_grok1 开始；若该号已有别人的测试进度，用 qa_grok2 等新的名字。游戏当前只要求用户名，不要求游戏密码。

首次登录必须走完创建角色与开场武器三选一，确认角色已经创建并进入游戏，再测试任务、背包和地图。登录成功但 /api/character 返回 404 表示尚未建角色，不代表登录坏了；回到建角色界面继续完成流程。
只开一个游戏标签页，不让多个页面争抢同一个角色控制权。
标签页挂后台超过 2 分钟后回来，若出现“恢复连接”，点击一次恢复，等待界面恢复后继续；不要用不停刷新、重开浏览器或反复登录替代恢复。
若明确提示另一设备正在游玩，不自动抢占别人的角色，记录提示并使用自己的测试号。

按正常玩家操作推进开场、任务与战斗，观察首次加载、操作等待、掉线恢复、场景切换、存档与重复领取保护。不要用控制台改角色、钱包、等级、任务或奖励，也不要清空数据库。
每个问题必须按以下格式记录：
步骤：从哪个页面开始，依次点击什么，是否刚从后台回来。
期望：应出现什么状态或反馈。
实际：实际提示、错误码、卡住位置和持续时间。
截图时间：带时区的时间；截图避开口令和 cookie。
角色名：本次角色名，同时写游戏账号。
补充：浏览器版本、是否刷新后仍复现、复现次数；网络慢与帧率低分别记录，不混为一个结论。

最终报告先列阻断游玩的问题，再列普通问题；未亲自完成的流程标注未验证，不把 HTTP 200 或登录成功当作可玩验收。
```

## 运维说明

- basic auth 是站点入口口令，游戏测试号是另一层身份。不要将口令嵌入分享 URL，避免浏览器历史和截图泄露。
- 请求 `/api/health` 不需要入口口令，可检查服务与 client/protocol/rules/assets/db 版本；其他 API 和素材需要入口认证。
- 不在本机运行 `tools/probe-quest.mjs`：现有实现固定 `headless:true`，还带有旧任务流程与全自动历练假设。此次不把它包装成已验证的远端探针，也不增加未经验证的 `--base`；Grok 使用上述可见持久浏览器流程。
- 发版与数据库操作由运维脚本处理；跑测只操作自己测试号的游戏 UI。
