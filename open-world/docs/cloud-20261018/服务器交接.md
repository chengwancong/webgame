## 2. 日常发版

在本机仓库根 `abyss-walker-rewrite/` 下执行。**不要走 GitHub 拉代码**：服务器没有部署密钥，也不需要。

```bash
# ① 服务端：打包 HEAD → 上传 → 重建 api
P=open-world
git archive --format=tar HEAD $P/package.json $P/pnpm-lock.yaml $P/pnpm-workspace.yaml $P/tsconfig.json $P/.dockerignore \
  $P/apps/api $P/apps/web/package.json $P/apps/desktop/package.json $P/packages $P/config $P/deploy | gzip > /g/webgame/aw-deploy/server-src.tgz
scp /g/webgame/aw-deploy/server-src.tgz abyss-staging:/tmp/
ssh abyss-staging "cd ~/abyss && rm -rf open-world/apps open-world/packages open-world/config && tar -xzf /tmp/server-src.tgz && echo $(git log -1 --format=%h) > SOURCE_COMMIT"
ssh abyss-staging "cd ~/abyss/open-world/deploy && docker compose up -d --build api"
```

```bash
# ② 前端（在 open-world/ 下）：只跑 vite，输出到仓库外；不要跑 pnpm build 里会改工作区的素材生成步骤
node node_modules/vite/bin/vite.js build --config apps/web/vite.config.ts --outDir G:/webgame/aw-deploy/web-dist --emptyOutDir
```

③ 上传前端，二选一：
- **只改了代码**（常见）：只传 html 和 `assets/` 下的 js/css，几秒钟：
  ```bash
  cd /g/webgame/aw-deploy/web-dist && tar -cf - *.html $(find assets -maxdepth 1 -type f \( -name '*.js' -o -name '*.css' \)) | ssh abyss-staging 'tar -xf - -C ~/abyss/open-world/deploy/web-dist'
  ```
- **美术也变了**：整包传到 `web-dist.new`，换名后**必须** `docker compose up -d --force-recreate api`（目录换了 inode，旧容器看不到新文件）。

④ 验证：`curl -s https://43-165-179-11.sslip.io/api/health` 看 `versions`（client / protocol / rules / db）是否为新值。
⑤ 推镜像：`node open-world/tools/cloud-mirror.mjs`。

旧的 js 文件会留在 `web-dist/assets/`，不影响运行（文件名带哈希）；需要时整包重传清理。

## 3. 常用运维

```bash
ssh abyss-staging 'cd ~/abyss/open-world/deploy && docker compose ps'
ssh abyss-staging 'cd ~/abyss/open-world/deploy && docker compose logs api --since 30m' > /g/webgame/aw-deploy/api-log.ndjson   # pino JSON，拉回本机分析
ssh abyss-staging 'cd ~/abyss/open-world/deploy && docker compose exec -T db psql -U abyss -d abyss -c "select count(*) from ow_controls"'
ssh abyss-staging 'cd ~/abyss/open-world/deploy && docker compose exec -T db pg_dump -U abyss abyss | gzip' > /g/webgame/aw-deploy/db-$(date +%Y%m%d).sql.gz
```

改口令：`docker run --rm caddy:2 caddy hash-password --plaintext '新口令'`，把结果里的 `$` 改成 `$$` 写进 `.env` 的 `AW_GATE_HASH`，再 `docker compose up -d caddy`，同步更新本机凭据文件。
切正式模式：`.env` 设 `AW_MODE_NODE_ENV=production`、`AW_TEST_LOGIN=0`（`main.ts` 会拒绝 production 下开 QA 开关）。

## 4. 约束（必须遵守）

1. **素材不进 Git**：美术只随 `web-dist` 直传服务器。授权未清（APK 提取的金币动画、三个外部 Spine 素材包），见 `素材盘点.md`。
2. 口令/私钥不写进仓库、文档、聊天；`.env` 保持 600。
3. 开发期没有真实玩家，测试服数据库可以清档，但清之前先 `pg_dump` 备份。
4. 用户电脑负载敏感：本机一次只跑一个重任务（构建、vitest、带 PG 的测试不要并行）；不要在本机跑 headless 浏览器探针。
5. 提交只带自己改的路径（`git commit --only -- <路径>`）；仓库里常有别的会话没提交的改动，别动。
6. 重要信息、原始日志、截图只留本机 `G:\webgame\aw-deploy\`，仓库里只提交结论。
7. 用户主要面向**海外玩家**（Steam / Google Play），选区域、CDN、支付都按海外考虑。

## 5. 已知问题与最近修复

- **后台标签页掉线（已修，5d390296）**：Chrome 会把后台标签页的定时器压到约每分钟一次，15 秒心跳赶不上 45 秒租约，一直 409 CONTROL。现在租约 150 秒（`apps/api/src/app.ts` 的 `controlLeaseSeconds`），切回前台立即续期；如果租约已过期，自动 `recover` 重新拿控制权（另一台设备在玩时仍弹接管面板）。修复前就开着的旧标签页需要刷新。
- **API 日志看不到真实 IP**：所有请求的 `remoteAddress` 都是 Caddy 的 172.18.0.4。要在 Fastify 配 `trustProxy`（只信任 compose 内网），再在日志里看 `X-Forwarded-For`。
- **Grok bot 跑测姿势**：它之前反复登录后拿到 404（还没建角色），从没调用过 `/api/control`，cookie 也没保住。要让它：用一个持久浏览器会话，用自己的用户名（例如 `qa_grok1`），先走完开场的武器三选一建角色，只开一个标签页。basic auth 可以写在 URL 里（`https://用户:口令@域名/`），口令由用户提供给它。
- 镜像 823MB，含 devDependencies（tsx 直跑源码），以后可以改成多阶段构建瘦身。
