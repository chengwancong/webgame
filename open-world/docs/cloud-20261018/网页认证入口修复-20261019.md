## 表单 Origin 冲突修复

用户实测提交后出现 Origin rejected。代码发现入口同时发送 Referrer-Policy: no-referrer，并要求 POST Origin 严格等于本站；浏览器 HTML form 导航受该 policy 影响，会发送 Origin: null。之前手工设置 Origin 的 HTTP 检查没有覆盖这一浏览器行为。
改为 strict-origin，仅发送来源而不披露路径或查询，保持 HTTPS 同源表单的 Origin。来源相等校验、空来源拒绝、CSRF 签名和 Cookie 匹配均保留，没有增加来源白名单或允许 null。
新增响应头回归检查及 Origin:null 拒绝检查，并在实际 Caddy 集成中检查传出的 policy。标准依据：https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Referrer-Policy#effect_on_the_origin_header 。
原始用户请求头未提供，因此安全登录工具是否另外改变来源仍需云端复测；此修改修复的是已确认的入口配置冲突。

修复提交 04d4cb50 已发布为 web-gate-1792394129708。实际公网 GET 响应为 200、Referrer-Policy: strict-origin；16 项认证回归、真实 Caddy 集成及 12 项公网 HTTP 检查通过。证据在 G:/webgame/aw-deploy/web-gate-1792394129708/。当前聊天浏览器工具仍超时，云端 Dot 的表单提交和完整冒烟未代验。复测必须重新加载登录页，已打开的旧文档仍可能保留旧 referrer policy。
