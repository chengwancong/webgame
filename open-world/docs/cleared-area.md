# 清场后不自动重刷

客户端0.7.8修复了原地清场后刷新整批敌人的行为。原来的15秒心跳会在没有存活敌人时申请战斗授权；服务端在全部击杀且经过25秒后创建新怪物轮次，授权到期也会创建新轮次。

现在心跳仅维持控制和临期授权。清空、构筑变化、到期续接、重连均保留同一授权的击杀记录和报告序号；规则版本更新更换授权时也沿用敌人实例ID与已击杀状态。野外重新进入请求只有在原区域已清空且满足已有刷新间隔时才创建新一轮；首领由明确进入请求创建新挑战。登录恢复、断线恢复与返回安全点不作为新一轮进入。

此调整不改变奖励公式、掉落概率或容量；金币、经验、地面战利品、原回执与奖励记录都继续保留。协议8、规则ow-11、数据库10保持。

验证入口：`node tools/verify-battle-result-db.mjs`（独立真实PostgreSQL的41项检查）、`vitest run tests/combat-permit.test.ts`（5项战斗续接检查）、`node tools/verify-cleared-area.mjs`（真实浏览器心跳、装备升级与断线恢复）。清场夹具通过正式战斗报告发放奖励，未在浏览器直接修改怪物状态；不代表全程自然战斗的平衡测试。

实机与发布记录：`../docs/reviews/open-world/cleared-area-20261002/`。

验收通过：清空32只敌人的实例等待35秒（两次真实心跳）仍为空；强化装备与断线恢复后也为空，授权ID与轮次未变。规则更新后继续结算剩余敌人时，只将新授权内新增击杀计入时间校验，不把旧击杀误当新收益。最终构建前后246个源文件指纹一致；8611构建页与8612开发预览均通过无密码登录和刷新恢复，常驻服务运行，67个已有账号／角色及508条回执／流水保留。
