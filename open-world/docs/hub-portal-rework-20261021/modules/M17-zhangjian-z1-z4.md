# M17 借鉴杖剑传说：出战方案 / 部位强化 / 宠物上阵 / 航区探索度（Z1–Z4）

> 上位：`../zhangjian-reference.md`（2026-10-23 用户：按 Z1→Z4 开做，设计和前端 Claude，服务端和美术交 GPT）。
> 依据（盘点结论，2026-10-23 按代码核对）：
> - 装备强化记在装备上：`gear.rank`，上限 `gearMaxRank`（普通 5 / 魔法 8 / 稀有 12 / 传奇 15），在 3/6/9/12/15 级触发词缀节点 `reinforceAffixNode`。
> - 技能栏 `s.skills`（1–4 个），按武器记忆 `weaponLoadouts`；天赋在 `progression.talents`，重置要花钱。
> - 怪物只有护甲，没有元素抗性或弱点；玩家有元素抗性。风栖怪 72% 物理伤害，雾铃 60% 毒素。
> - 玩家 83 个技能：物理 46，火 / 冰 / 电 / 毒 / 暗各 5，奥术 12。
> - 宠物：18 个家族（6 岛 × 零 / 轻 / 重），每个家族 3 个形态、9 个流派皮肤，每个流派带一种元素。运行时图集（`/art/starsea/pets/v3/<家族>/actor.webp + actor.json`）可以直接给 Phaser 用，动作有 idle / idle2 / move / attack / knock。目前没有任何玩法代码。
> - 航图现在开放风栖、雾铃，共 20 个节点；港口状态是 `ow_hub_state` 里的 JSON。

## 0. 一句话

战斗还是全自动，但打之前要动脑：看清这片海怕什么，切到合适的方案，带上合适的宠物；强化不会因为换装白费；回头把打过的航区摸干净，挂机收益更高。

## Z1 出战方案 + 元素克制可见

### 玩家体验
1. 星门航图点开一个节点，卡片多一行：`敌人多用 物理 · 弱 雷电`（两个元素小图标）。
2. 当前方案打不出弱点元素、而另一套方案能打出来时，卡片下方出现一行：`方案二能打出雷电弱点`，旁边一个「切换」按钮。抗性低于 10% 时改提示：`物理伤害为主，护甲偏低`或 `毒素抗性 0%`。一次只出一行，优先提示弱点。
3. 角色面板顶部有三个方案标签「方案一 / 二 / 三」。点标签就切换（免费）；当前有改动没保存，标签上显示一个小点，点「保存到方案」覆盖。方案名可改（≤6 字）。
4. 在副本里不能切换（按钮置灰，提示「回港或在航图上切换」）。

### 规则
- **方案内容**：装备（6 个普通部位 + 武器盘）、技能栏、天赋分配、宠物阵容（Z3）。
- **切换**：按方案内容逐项尝试装回。装备不在背包（已分解、已卖）就把那个部位留空；技能不合法（武器不对、未激活）就去掉；天赋点数超过当前可用就不动天赋。不合法的项在回执里列一行，例如「方案二：护手已不在背包」。
- **天赋免费**：切换方案改天赋不收重置费；在天赋面板里直接重置照旧收费。这正是方案的意义——提前配好、随时免费切。
- **怪物弱点**：每个航区一份元素表（`packages/content/hub-elements.json`）。节点可以覆盖航区。该航区副本里所有怪（含首领）受到弱点元素伤害 ×1.25。只加不减：没有弱点元素的配置照常打，不吃亏。
- **元素表（初值）**：

| 航区 | 敌人主要伤害 | 弱点 |
|---|---|---|
| 风栖 | 物理 | 雷电 |
| 雾铃 | 毒素 | 火焰 |
| 赤炉 | 火焰 | 冰霜 |
| 霜镜 | 冰霜 | 火焰 |
| 沉星 | 暗影 | 奥术 |
| 龙眠 | 毒素 | 冰霜 |
| 深潮 | 奥术 | 暗影 |

- **"打得出"怎么算**：技能栏里有一个技能的伤害类型等于弱点，或者上阵宠物的元素等于弱点（Z3）。

### 数据与接口（契约在 `packages/contracts/zhangjian.ts`）
- 角色状态加 `loadouts?: {active:0|1|2; slots:[Loadout,Loadout,Loadout]}`，`Loadout = {name, equipment, weaponGrid, skills, talents, pets}`。
- `POST /api/loadout` `{op:'save'|'apply'|'rename', index, name?, command_id}` → 回执 `{applied, skipped:string[]}`。
- 节点视图 `ChartNodeView` 加 `elements:{threat, weakness}`；`GET /api/loadout` 返回三个方案的摘要（含每个方案能打出的元素，用来出提示）。

## Z2 部位强化 + 共鸣

### 玩家体验
1. 工坊强化的对象从「这件装备」变成「这个部位」：头盔 +7 就是头盔位 +7，换一件新头盔还是 +7。
2. 部位等级不能超过当前那件装备品质的上限：穿普通头盔（上限 5）时显示「+7（本件生效 +5）」。
3. 全身 6 个部位都到 +3 / +6 / +9 / +12 / +15，分别点亮共鸣一到五档。工坊顶部一排六个格子，下方是共鸣进度条：「共鸣 2 档：再把 2 个部位升到 +9」。
4. 装备卡上原来的「+N」改成「词缀节点 n/5」，表示这件装备已经吃到几个强化节点。

### 规则
- `slotRanks: Record<6 个普通部位, number>`，初始 0。
- **生效等级** = min(部位等级, 当前装备品质上限)。主属性强化按生效等级算（`primaryReinforcement`）。
- **强化**：该部位必须穿着装备；部位等级 < 当前装备上限才能升；费用按 `gearUpgradeCost({rank:部位等级, ilvl:当前装备})`，规则不变。
- **词缀节点跟着装备走**：装备自己的 `gear.rank` 改成「已吃到的节点进度」。穿上装备、或强化部位以后，若生效等级 > gear.rank，就从 gear.rank+1 逐级补到生效等级，每过一个节点（3/6/9/12/15）调用一次现有的 `reinforceAffixNode`。gear.rank 只升不降。效果：新装备穿上就能补齐节点，这就是"养格子"。
- **共鸣**：取 6 个部位里**最低**的等级，≥3/6/9/12/15 分别为 1–5 档。每档给 +2% 攻击、+2% 护甲、+2% 最大生命（累计，满档 +10%）。数值进 B 批次做一次推导、一次验证。
- **迁移（开发期）**：每个部位取背包、仓库里该部位所有装备的 rank 最大值，作为部位等级；装备的 gear.rank 保持原值（当作已吃节点）。多出来的不退。
- 批量分解保护里的「已强化」条件改成「词缀节点 >0」。

### 数据与接口
- 角色状态加 `slotRanks?`；`POST /api/gear/upgrade` 改为 `POST /api/slot/upgrade {slot, command_id}`（旧路由保留，转成对该装备所在部位的强化）。
- `resolveBuild` 读部位等级算主属性，再加共鸣（规则层函数 `slotEffectiveRank`、`resonanceTier`、`resonanceStats`）。

## Z3 宠物上阵

### 玩家体验
1. 风栖关口首通，结算页多一行「新伙伴：风绒」，回港后港口的宠物摊位亮红点。
2. 宠物页：左边是已拥有的宠物，右边是阵容——1 个「上阵」、2 个「助阵」。每只宠物有 9 个流派可以随便切，流派决定它的元素（锋刃=物理、余烬=火焰、冰川=冰霜……）。
3. 进副本后，上阵宠物跟在角色身后，每隔几秒放一次技能（播 attack 动作、打出元素伤害）；助阵宠物不出场，只给被动加成。
4. 宠物跟着打副本升级：幼年 1–9 级，10 级长成成年，20 级觉醒，换更大的模型。

### 规则
- **来源**（10-23 用户：先做可玩性，不考虑商业化）：三档只是稀有度，全部靠玩法获得。对玩家显示为常见 / 稀有 / 传说；内部 id 仍是 free / light / heavy，不改存档。
  - 常见：该岛关口首通。
  - 稀有：该航区探索度 100%。
  - 传说：该航区狩猎节点与关口都首通（先后不限），规则 `huntPet`。老角色已满足条件的登录时补发。
- **强度**（10-23 用户：数值只按普通非付费玩家的体验做）：三档就是不付费玩家按进度依次拿到的宠物，强弱跟着获取先后走（常见→稀有→传说），不设付费比例或占比上限。当前系数约 50:74:100，先保留。以后验收只看体感：同进度下宠物有没有存在感，换宠物有没有差别。
- **经验**：副本结算时上阵宠物拿本场角色经验的 100%，助阵 50%；等级不超过角色等级，上限 30。
- **方案**：阵容（上阵、助阵、各自流派）存在出战方案里，跟 Z1 一起切。

### 数据与接口
- 角色状态加 `pets?: {owned: Record<家族id,{level,xp,flow}>; lineup:{active?:家族id; support:家族id[]}}`。
- `GET /api/pets`、`POST /api/pets {op:'lineup'|'flow', ...}`；关口首通、探索 100% 时由服务端发放。
- 宠物定义 `packages/content/pets.json`：18 个家族 → 岛、档位、名字、运行时 id 前缀、9 个流派→元素。

## Z4 航区探索度

### 玩家体验
1. 航图上每个航区标签旁多一个圆环：「风栖 探索 64%」。点开看清单：节点首通 9/10、秘藏 6/9、锁门 0/2。
2. 每个节点的副本里藏一个「秘藏」宝箱：不在主路上，靠近 5 格内才闪光。全自动不绕路去开（沿用 2 格规则），想要就手动或半自动走过去。
3. 风栖有 2 道「雾锁门」，要雾铃关口首通拿到的「铃钥」才能开，门后是一个小房间和一个大宝箱。雾铃的 2 道「炉锁门」要赤炉的钥匙，赤炉开放前开不了，清单上写「需要后续航区的钥匙」。
4. 探索度到 50%：该航区码头派遣产出 +25%；到 100%：+50%，并获得该岛稀有宠物（Z3）。

### 规则
- **计分**：节点首通每个 1 分，秘藏每个 1 分，锁门每道 2 分。航区探索度 = 已得分 / 总分。
  - 风栖：10 节点 + 9 秘藏（关口节点不放）+ 2 门 × 2 = 23 分。
  - 雾铃：同结构 23 分；赤炉开放前雾铃最多 19/23 ≈ 83%。
- **秘藏**：每个非关口节点固定 1 个，位置由节点 id 定种子，放在离主路 4–8 格的可走格；只能开一次（按角色记录）。内容：该航区 T1 材料 ×3 + 10% 一张图样。
- **锁门**：放在指定节点最后一段。持有钥匙才可交互；打开后永久记录，门后小房间刷 1 个宝箱（该航区 T2 材料 ×1 + 金币）。
- **钥匙**：关口首通发放的钥匙道具（铃钥 = 雾铃关口，炉钥 = 赤炉关口……），不占背包，不能交易。
- **码头加成**：`hubDock` 结算产出时乘以该航区探索加成（1 / 1.25 / 1.5）。

### 数据与接口
- `HubState.explore: {caches: string[]; doors: string[]; keys: string[]}`（JSON，不改表结构）。
- 内容 `packages/content/hub-explore.json`：每个航区的秘藏节点表、锁门（节点、段、需要的钥匙）、钥匙来源。
- 区域视图 `ChartRegionView` 加 `explore:{score,total,percent,parts:{nodes,caches,doors},milestones}`；节点视图加 `cache?:{found:boolean}`、`door?:{key,keyOwned,opened}`。
- 副本场景物件：`hub-cache`（秘藏，状态 hidden/glint/opened）、`hub-door`（锁门，locked/open）。由服务端放进副本房间，前端按 propState 渲染。
