## 1. 目标
- 新角色只走新流程：开场 → 拾星港 → 星门 → 节点；全程不出现野外、不出现被跳过的任务步骤。
- 旧系统**冻结不删除**：开关关掉、入口隐藏、数据留着。等新结构试玩成立后，再另行决定清理（A3）。
- 开发期一次清档，清之前先备份；四个版本号按规则各自升级。
- 后端按批交给 GPT，每批连续做完；前端和设计由 Claude 做。

## 2. 玩家体验
- 玩家（目前只有开发者和测试号）登录后从新的开场开始，看不到任何旧野外、旧岛屿页、旧悬赏板的入口或红点。

### 3.2 清档
- 依据：开发期没有真实玩家，旧号冲突直接清档（dev-period-wipe-ok）。
- 范围：**全部角色的进度**（声望、任务、星潮海进度、野外状态、外观收集、装备与钱包）。旧进度和新结构混在一起，必然会出现 `skipped-by-freeze` 步骤，违反「新角色正式流程不允许出现 skipped」。开发登录是「输入账号即自动创建」，账号名可以保留。
- 步骤：
  1. 确认没有其他会话在用常驻库（看协作中心与正在运行的会话）；
  2. 备份整库，备份文件只留本地，不进 Git；
  3. 清角色数据，升 db 版本（3.3）；
  4. 重启服务，核对 `/api/health`、`/api/content` 版本，用内置浏览器真实登录一次进港口。
- 这是开发期一次性的清档，不是绕过登录问题的手段（AGENTS 的禁止条款仍然有效）。

### 3.5 每批的验收
1. 新角色从开场打到当批范围内最后一个关口首领，自动驾驶断言 `skipped-by-freeze` 步骤数 = 0。
2. 冻结的系统在界面上没有入口和红点；接口调用返回冻结错误，不报异常。
3. `/api/health`、`/api/content` 的四个版本与网页客户端一致；真实登录进港口。
4. 类型检查、内容校验、`pnpm config:check`、相关定向测试通过；数值批次附 `pnpm spine:check` 的残差报告（只对新增超出负责）。
5. 留档只提交结论；原始明细、截图、数据库导出只留本地。

## 4. 规则要点
- 冻结 = 不再生成新实例、新任务目标；旧数据可读；进行中的正常结算后退出（沿用 J10）。
- 新角色的正式流程不允许出现 `skipped-by-freeze`；清档后不会有旧档，所以这个标记在改版后实际不会出现。
- 任何「删除」都只是标 `frozen` 或关开关，代码和配置行都保留到 B7。
