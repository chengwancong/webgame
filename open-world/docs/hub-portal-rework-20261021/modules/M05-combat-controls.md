# M05 战斗与操作

> 上位：03 大纲 §5（基本沿用，只列改动）。参考：R1（主城不放战斗）、R8（短时段完整收益）、魔渊之刃 / DNF（副本内战斗，城镇里只走路）。
> 依据：`packages/contracts/dungeons.ts`（操作模式 manual / semi / auto）、技能栏 4 栏（`loadoutLimit` ≤ 4）、`docs/ux-audit-20261020.md` UX-A05 / A07、记忆中的已定方案（回响爆发只在开场和首领战、16:9 等比舞台、世界内只用方向箭头）。

## 1. 目标
- 战斗手感、技能、伤害公式**一概不动**，只改「战斗在哪里发生」和「进出战斗」的衔接。
- 三种操作模式在所有副本类型里行为一致。
- 去掉野外特有的操作负担（疾跑、传送点、迷雾、找路）。

## 2. 玩家体验
1. 在港口里只能走路和交互，按键提示只有「E 交互」和菜单。
2. 进副本后战斗操作出现，技能栏 4 栏和上次一样，操作模式记住上次的选择。
3. 段与段之间，画面上一个方向箭头指向通道或传送门，不画地面路线。
4. 打完首领，全自动会自己捡东西、走进传送门；手动和半自动由玩家走过去。

## 4. 规则要点
- 操作模式、出卡、自动选卡、拾取、进传送门全部是服务端判定；客户端只发「切换模式」「选卡」「交互」输入（沿用 `DungeonInput` 的 mode / interact）。
- 自动选卡的规则写死在服务端，不读客户端偏好，结果写进结算页的「本场构筑」。
- 镜头、箭头、小地图都是纯渲染层改动，不影响服务端状态；镜头受「减少动态效果」设置控制。

## 7. 待定
- 全自动自动选卡的等待时长。默认 8 秒；半自动和手动不自动选，等玩家选（实时模式下出卡不暂停战斗，沿用现状）。
- 半自动是否也做「目标完成后自动拾取」。默认：不做，保留半自动「我来走位」的意义。
