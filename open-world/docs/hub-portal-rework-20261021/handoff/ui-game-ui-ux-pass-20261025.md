# game-ui-ux 战棋界面优化（2026-10-25）

用户明确要求依据 [game-ui-ux](https://github.com/gamedev-skills/awesome-gamedev-agent-skills/blob/main/skills/disciplines/game-ui-ux/SKILL.md) 优化界面。本轮读取该技能及 `references/layout-and-flow.md`，将参考分辨率、焦点层、上下文信息和事件驱动更新落实到现有 DOM/SVG 战棋页。没有安装整套技能包或新增运行依赖。

源码提交：`42e2a7e3c2677855b76cc275ea431e2b291fb33e`。

## 玩家可感知的变化

1. 不可施放的技能也能 Tab 聚焦或点击查看原因；它只打开详情，不再输出施放操作。普攻/技能的原有额度限制和服务端校验保留。
2. 选中技能后，在指令附近显示真实名称、已有消耗/范围/冷却信息，并提供详情入口；缺字段不补造数值。空闲时按剩余额度提示“点选亮格移动”“选择普攻或技能”等。
3. 结束行动、撤退、结算和结果弹层按优先级只有一个模态层接收输入；背景 inert，Tab/Shift+Tab 留在当前弹层，关闭后恢复原焦点或有效回退位置。
4. 方向键在技能栏里切换技能焦点，上键回棋盘、下键到行动按钮；详情和战报滚动时不再暗中移动棋盘游标。长按快捷键不会反复切换托管或技能选择。
5. 状态、技能和单位详情固定标题与关闭区，只滚动正文。内容更新保留焦点和同一详情的滚动位置，换技能不会继承另一项的滚动。
6. 不变的 HUD、网格和覆盖层不再反复重建 DOM，保留已加载头像；鼠标经过棋盘时保留键盘格子焦点。倒计时仍按真实截止时刻刷新显示，不改战斗时钟。
7. 1280×720 舞台继续等比 letterbox，按容器实际尺寸与安全区重算；去掉 0.25 最小缩放造成的窄窗裁切。使用 ResizeObserver/resize 事件，不逐帧轮询布局。
8. 新命令入口统一检查在线状态；断线时快捷键、二次点目标或确认不会新提交战斗命令。此前已提交但回执丢失的命令仍走原幂等恢复流程。

## 样例与边界

- 静态页增加 `tactical-compact-skill-context`，本组现有 7 种状态。它挂载实际控制器，使用明确标注的冻结数据，不请求 API 或推进战斗。
- `low` 可检查不可用原因；`long` 可检查正文滚动和固定关闭；`skill-context` 可检查长消耗/范围与详情入口。
- 保留奶白浅金公共组件、现有资源和固定舞台。没有重新绘制场景或更改上一轮美术。
- 新增美术占位：无。
- 本轮主要覆盖鼠标与键盘。未进行实际手柄、手机软键盘或跨设备视觉验收，不把等比缩放数学测试称为移动端适配完成。
- 当前沙盒仍不提供蓝量、宠物与攻速进度等完整投影；相关缺口不在本轮伪造或改动。

1. 打开沙盒、进入战斗、断线后重试和结束返回，核对默认焦点与回退位置；不要因等待或重绘而掉到页面 body。
2. 打开结束/撤退确认，连续 Tab/Shift+Tab；确认不能点到或键盘触发背后的棋盘、托管、技能。
