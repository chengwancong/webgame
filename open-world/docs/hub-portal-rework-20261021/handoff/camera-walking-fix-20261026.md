# 镜头与行走优化 · 2026-10-26

用户反馈镜头抖动、走路卡顿。本轮按实际触发链路修复，不调整移速、镜头前瞻强度、战斗数值、建筑阻挡或素材品质。

## 已定位并处理

1. **主城经过地标会暂停走路。** `starsea-controller` 发出到达上报后，通用 `write()` 的 processing 旗标会暂停本地世界，直至本机记录和网络回执完成。现在仅安全场景、没有战斗 permit、不改构筑的 `quest / arrive` 在后台完成；写锁、outbox、回执、失败停止与其他暂停原因都保留。野外战斗、自动拾取和授权续期仍沿用原冻结规则，未一刀切取消保护。
2. **副本手动移动在每次收包前后忽快忽慢。** 预测校正目标原先一直固定在最新快照加固定提前量，100ms 两次快照之间目标不前进。现加入接收后经过时间，最多外推250ms；断流后收敛回权威缓冲位置，不持续越走越远。
3. **顶墙时画面被推入／穿过墙体，随后回拉。** 原本普通预测走导航，但 blend 校正绕过碰撞。现在预测、提前目标和校正均调用已有共享 `moveBody`，并读取正式人物半径。
4. **输入与实际移动速度不一致。** 预测原先写死 WASD，真实命令则消费重绑定按键。现正式命令与预测共用 `movementInput()`；使用共享模拟器的实际移动速度，包含现有加速、减速和旧减速字段。原每tick浮点运算顺序保留在 `movementStep()`，没有更改计算参数或回放顺序。
5. **镜头与角色每帧共享同一预测位置。** 英雄显示位置每帧只求一次；其他单位仍用原网络缓冲，本地场景仍用原固定tick插值。保留此前正确的时钟分流：网络使用真实经过时间，本地使用与其插值一致的 Phaser delta。
6. **普通跨地块可能误用40ms进图预算。** 改为只在首次加载、实际大跳位到缺块时进入启动模式；普通走路追上缺块最多使用原12ms紧急预算。静态前景摆件 bounds 缓存到创建时，不再逐帧重算；固定血条／地面标记层深度只在创建时设置。画质和纹理尺寸不变。

## 真机复核

静态验收入口 `/u4-u6-qa.html` 新增「移动 · 100ms快照匀速／快照到达间隔不齐／顶墙后松手」三组，可暂停和重播。样例调用实际预测、缓冲与镜头函数，无API或存档；画布为位置示意，非实机FPS验收。

1. 主城持续走过、折返经过NPC／地标边缘，留意是否还出现等待上报的停步；同时确认到达任务仍正常更新。
2. 副本持续按方向键、短点按、松手、掉头，检查人物与镜头是否周期性回拉；重绑定按键后复查。
3. 持续顶墙与贴墙走，检查显示位置不穿墙，松手不从墙内弹回。
4. 加速、减速、受控恢复时检查移动速度与镜头一致；切后台、打开面板、断线时不残留预测输入。
5. 野外跨地块并折返，核对地表不缺失，诊断里的普通走路 `buildBudgetMs` 不再误变40；该预算不能中断单个同步绘图步骤，不等于硬帧耗时上限。
6. 若仍有周期性停顿，分别记录是否伴随自动拾取／授权续期、地块首加载或大量新角色出现。这几类与设备帧时间需单独实测，不能仅凭源码推断主因。
