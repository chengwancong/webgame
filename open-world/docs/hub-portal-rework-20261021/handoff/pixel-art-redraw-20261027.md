# 像素美术重绘交接（PX0–PX9）· 2026-10-27

## 为什么重做

第 1、2 轮是把现有厚涂美术用程序压成方块（`docs/pixel-mode-20261027.md`）。用户看过后的结论是"这种不算像素风"，因为：
- 方块里还是厚涂的渐变和细碎高光；
- 角色由骨骼部件拼成，旋转、缩放以后像素格就歪了；
- 没有像素画该有的造型取舍：大轮廓、少色阶、手点的高光和描边。

这轮改为**按像素画规范重新绘制全部游戏内美术**。设置里的"像素画风"开关保留：开了用像素美术，关了用原画风。原素材一张都不改、不删。

## 一、硬规格（所有批次通用）

| 项 | 规定 |
|---|---|
| 像素画布 | 舞台 1280×720，**1 美术像素 = 2 舞台像素**，等效 640×360 低分辨率画布。整数放大，最近邻采样 |
| 角色尺寸 | 人形主角/NPC 身高 44–48 px，画格 64×64；普通怪 32–56 px；精英按同模板 ×1.25 重画（不许直接放大）；首领 96–128 px，画格 ≤160×160 |
| 建筑/道具 | 按现在游戏里的显示尺寸（舞台像素）÷2 定画布。显示尺寸从代码和 manifest 里量，不按源图尺寸 |
| 地表 | 16×16 图块（=32 舞台像素），按地形类型做自动拼接（47 块 blob 或 16 块 wang，二选一，全项目统一） |
| 图标 | 物品/技能图标 32×32，小图标 16×16 |
| 主色板 | 全项目一套主色板，≤64 色，按色阶组织（每组 4–6 阶，暗部偏冷，亮部偏暖）。所有成品像素必须落在主色板里；首领/特效可在主色板内选子集，不另加色 |
| 透明 | 只允许 alpha 0 或 255。唯一例外：脚下阴影用主色板指定的阴影色，整块 50% |
| 描边 | 1 px 外描边，用相邻色阶的最暗色（选择性描边），不用纯黑；内部结构线同样手点 |
| 光源 | 统一左上 45°；每个物体最多 1 处高光点 |
| 禁止 | 抗锯齿边、渐变、模糊、半像素（mixel）、同一画面里两种像素尺寸、成品里还留着 AI 生成图的噪点 |
| 抖动 | 只在大面积（地表、天空、首领大块面）用 2×2 有序抖动，角色身上不用 |
| 动作 | 只画右朝向，左朝向镜像（和现在一致）。帧数：待机 4，移动 6，普攻 6，技能 6，投射 6，受击 2，死亡 6。每个动作的总时长和命中帧要和现有动作数据对齐（读 `apps/web/src/wardrobe-renderer.ts` 加载的 motion json 里的 `duration`/`fps`/`impactTime`），命中帧画在 `impactTime` 对应那一帧 |
| 锚点 | 每张表在 manifest 里给出脚底锚点和挂点（胸口/手/武器尖/枪口），挂点名沿用 `hero-sockets.json`、`native-actor-sockets.json` 的叫法，特效靠它们挂接 |

## 二、生产流程（每张图都走）

1. **出草图**：可以用你的图像生成出概念，但只当参考，不能直接当成品。
2. **对齐网格**：生成图先用本机已有工具 `G:/webgame/aw-third-party/pixel-tools/proper-pixel-art`（MIT，已获同意下载）找到真实格子并缩回原生像素尺寸。用法见该目录 README；venv 在 `G:/webgame/aw-third-party/pixel-tools/.venv`。
3. **套色板**：量化到主色板，不能出现色板外的颜色。
4. **清理**：逐格修轮廓、描边、高光，去掉孤点和 AI 噪点，保证剪影一眼能认。
5. **出表**：按动作排成精灵表（每行一个动作，每格同尺寸），附 json（帧尺寸、每动作帧数和 fps、锚点、挂点）。
6. **校验**：用 PX0 里写的校验脚本（见下），全部通过才算完成。

## 三、文件与接入

- 成品放 `apps/web/public/art-pixel/`，子路径和原素材一一对应（例：原 `art/hub-port/build-forge-1.png` → `art-pixel/hub-port/build-forge-1.png`）。根目录放 `art-pixel/manifest.json`：原资源键 → 像素资源（文件、帧尺寸、动作表、锚点、挂点、显示倍率 2）。
- **图片不进 Git**，和现有素材规则一样，只提交 json、代码和文档。
- 接入（前端）：
  - 像素模式开着、manifest 里有对应项时，加载像素版。显示时整数 ×2 放大，最近邻，`roundPixels`。
  - 角色在像素模式下改用逐帧精灵表播放，不走骨骼或部件拼装。
  - 世界相机在像素模式下画到 640×360 低分辨率渲染目标，再整数放大到舞台，保证全屏同一套像素格。
  - 文字与 HUD 继续走不放大的文字相机，现有的 `pixel-mode.ts` 已经实现，复用即可。
- **过渡期**：manifest 里没有的资源，继续用第 2 轮的自动像素化兜底，即现有 `pixel-art.ts`、`pixel-texture.ts`。PX9 覆盖到 100% 后删除这套兜底。
- 关闭开关：恢复原画风，不残留任何像素资源或渲染目标（现有关闭逻辑沿用）。

## 五、默认裁决（遇到就照做，不回来问）

- 原画风细节在像素尺寸下放不下时，保剪影和识别特征（发型、武器、主色），细节直接删。
- 某个资源原尺寸很怪、不好按 ÷2 定画布：取最接近的 8 的倍数，在 manifest 里写清显示倍率。
- 帧数不够表现动作：可以加帧，但总时长和命中帧不变。
- 换装外观靠换色区分不开：把它列为"叠层"补画，不阻塞本批。
- 自动地形分类出错的格子：在地形映射 json 里手工改，不改原地表图。
- 中文像素字体：**不下载**。需要下载新素材必须用户逐次同意。把候选（名称、协议、来源）写进进度文件的"待用户"清单，其余照常推进。
- 校验脚本报错又一时修不掉：这张图不进 manifest，继续用兜底，记进进度文件。

## 六、约束

- 不改原素材，不改玩法数值、碰撞和动作时长。
- 不跑无头浏览器、Playwright 或任何浏览器自动化。重任务一次只跑一个（tsc、vitest 加 `--maxWorkers=1 --no-file-parallelism`）。
- 只按明确路径提交本任务的文件，不碰其他会话未提交的改动。不提交图片、截图、原始明细、构建产物。
- 云测试服口令只在 `G:\webgame\aw-deploy\staging-credentials.txt`，不得写进报告、日志、提交或链接。不清库，不改正式角色数据。
- 每批完成都要通过：校验脚本、tsc、相关单测（`pixel-mode`、`pixel-art`、`wardrobe-renderer`、`hero-appearance` 及本批新增）。
