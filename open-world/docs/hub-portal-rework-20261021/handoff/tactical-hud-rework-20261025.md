## 3. 敌人意图（后端规则 + 前端显示）

### 3.1 后端现状

已经实现，本批不改语义：

- 回合开始、英雄行动之前，`revealEnemyIntents` 为每个存活敌人生成一条意图，写进状态，然后冻结。英雄行动不会改写已经揭示的意图。
- 敌人行动时，`executeEnemyIntent` 只执行已揭示的那条意图。如果目标已经不在攻击格里、施法者死了或被控制，这条意图记为 `fizzled`，写入 `reason`，不会临时换成别的行动。
- 致死保护：本回合所有意图的伤害加起来，如果不小于英雄的「生命 + 护盾」，会把排在后面的意图降级成只移动，并发出 `intent-downgraded` 事件。降级在揭示时就已经完成，所以英雄看到的就是降级后的意图。
- `damage` 是按当前英雄防御和抗性算出的期望伤害，暴击按期望值计入，不读随机数。`tier` 是威胁等级。`hidden=true` 的意图只公开「有行动」，不公开类型和数值。

### 3.2 本批补的后端内容

- **B1** 在意图视图里给出 `threatCells`：这条意图执行时会命中的格子，冲锋类包括冲锋终点的相邻格。前端用它画敌方威胁区，也用它判断移动是否踩进去。
  - 已经有 `cells` 时直接复用；只有在缺少冲锋终点的情况下才补算。
  - 只能新增字段，不能改 `cells` 的含义。
- **B2** 每条意图带上 `order`，也就是执行顺序。顶部头像条和头顶标签都按这个顺序标号。

### 3.3 前端显示规则

| 情况 | 头顶标签 | 颜色 |
|---|---|---|
| 攻击英雄 | 「砍你 14」，动词来自 `INTENT_LABEL` | `--color-danger` |
| 冲锋、移动后攻击 | 「冲向你 14」 | `--color-danger` |
| 只移动、降级 | 「靠近」 | `--color-text-secondary` 底 |
| 施法、增益、召唤 | 「强化同伴」「召唤」，来自 `EFFECT_LABEL` | `--color-warning` |
| `hidden` | 「?」，悬停时写「意图未知」 | 中性 |
| `tier` 为致命或重击 | 标签加粗，加 `--shadow-danger`，或使用现有的最强危险 token | — |
| 已失效（执行阶段） | 标签划线，飘出「落空」加原因 | — |

- 悬停在敌人身上时，用浅红色显示这条意图的 `threatCells`，并在英雄头顶显示「将受 N」。
- 降级事件在日志里写成「某某 收手了」，不要露出内部英文。

## 4. 伤害预览（后端规则）

### 4.1 现状

- `previewTacticalEncounter`：
  - 在预览副本上依次执行动作，再自动结束回合，让敌人意图也跑一遍。
  - 只返回合计值：`kills`（个数）、`damage`（总和）、`expectedDamageTaken`、`remainingHp`，以及 `events` 和 `projection`。
- 前端 `sandbox-wire.ts` 用 projection 的前后差值推算每个单位的伤害。这样拼出来不可靠：护盾吸收、多段伤害、敌人互相伤害都会算混。
- 只有沙盒路由 `GET /api/tactical/sandbox/:id/preview`。正式战斗还没有 `server` 来源。

### 4.2 规则（本批落地）

- **只在服务端算，只读。** 预览：
  - 不推进随机数游标。
  - 不消耗预算。
  - 不改冷却。
  - 不写库。
  - 不推进超时窗口（沿用现有注释里的要求）。
- **暴击按期望值计入。** 所有伤害都用期望值。返回值里带 `expected:true`，前端固定加一句「按暴击期望估算」。不能用这次的随机结果去「剧透」实际会不会暴击。
- **B3 按单位给出前后值。** 在 `previewTacticalEncounter` 的返回值里新增 `units`：

```ts
units: Array<{
  unitId: string;
  hpBefore: number; hpAfter: number;
  shieldBefore: number; shieldAfter: number;
  damageFromHero: number;   // 英雄这次动作造成的，含溅射、持续伤害的首跳
  damageFromEnemies: number;// 敌人意图在本回合造成的
  killed: boolean;          // 本回合结束时 hp===0，且之前 >0
  killedBy?: 'hero' | 'enemy-intent';
}>
```

  - 合计字段保留，并从 `units` 汇总出来，保证两边数字一致。
  - 只统计本回合；下回合的持续伤害不算。
- **B4 拆成两段。** 新增 `phase:{afterHero, afterIntents}`，各自给出英雄生命和护盾。
  - 前端在目标上显示「−N · 剩 M」，用 `afterHero`。
  - 「将受 N」用的是 `afterIntents` 减去 `afterHero`。
- **B5 覆盖移动和技能两种预览。** move 预览也会跑完敌人意图。这里有个现成的效果：站到失效格上，意图会显示为落空，预览里的「将受」就是 0。
- **B6 拒绝码。** 预览非法时返回 `{ok:false, code, message}`。`code` 至少包括以下几种：
  - `cooldown`
  - `insufficient_mana`
  - `main_action_used`
  - `out_of_range`
  - `no_line_of_sight`
  - `blocked_path`
  - `not_your_turn`

  前端用 `code` 映射成按钮下的中文原因，不显示英文原文。现有的「中文前缀 + 英文原文」只作为没有对应 code 时的兜底。
- 线协议和前端契约同步更新：
  - `SandboxPreviewWire` 加 `units` 和 `phase`。
  - `TacticalForecast` 加 `units`，旧的 `damage[]` 和 `kills[]` 从 `units` 派生。
  - `sandbox-wire.ts` 改为直接读取，不再算差值。

### 4.3 撤销移动

- 默认裁决：同一回合内、主动作出手之前，可以撤销一次移动，英雄回到回合开始时的位置，移动预算恢复。
- 出手之后，或者移动中触发了陷阱或反应伤害，就不能撤销。按钮变灰，写「已触发地形，不能撤销」或「已出手」。
- 后端加一个 `{type:'undo-move'}` 动作，实现方式是还原回合开始时保存的英雄位置和预算。随机数游标不会因移动而推进，所以不需要回滚。
- 如果实现中发现移动会推进随机数（比如路上有触发机关），只给那一类格子禁用撤销，并记进进度文件。
