> 版本：2026-10-05 初稿。用途：把星潮海从“小岛 + 远航切图”改成“大岛无缝开放世界”，交给实现方（GPT/开发）按里程碑落地。
> 本文写清：现状、目标形态、功能改动（具体到文件与数据结构）、美术资源清单、分阶段计划、验收标准、决策记录。
> 已定事项见第 7 节「决策记录」。
> 配套文档：[内容方案](open-world-content-plan.md)（主线/支线/功能开启/怪物难度）、[割草爽感方案](open-world-grind-feel.md)（爽感曲线与关联系统）、[数值心流](open-world-numeric-flow.md)（开荒/爽刷阶段阶梯、墙与钥匙、运气）、[任务系统改造](open-world-quest-system.md)（引导任务 + 支线，取消严格主线）、[流派丰富度](open-world-build-variety.md)（特效原子、二级属性、套装、威能、潮印）。

## 0. 必须遵守的既有约束（来自 `AGENTS.md`，改造不得违反）

1. **服务端权威**：钱包、装备、进度、奖励、击杀确认只由服务端修改；客户端战斗核心只消费已解析参数。
2. **清场不原地重刷**：不得在玩家所在处自动刷出新怪；刷新必须由“离开 + 条件满足”触发（本方案改为“营地级、视野外刷新”，见 §3.3，已确认，见 §7 第 3 条）。
3. **怪物 = 模板 + 指定等级 + 档位修正 + 副本难度**，唯一源 `packages/content/monsters.json`；地图只指定模板、等级、档位、位置；禁止按玩家等级暗中缩放。
4. **配置表驱动**：任务、步骤、路线、章节、NPC、对白、道具唯一来源 `config/excel/*.xlsx` → `pnpm config:export` → `config/json`，`pnpm config:check` 校验；代码里不得新增硬编码文案/奖励/站位。
5. **副本规则**统一由 `packages/content/dungeons.json` 声明；不得按副本 ID 隐藏兜底数值。
6. **美术风格**：奶白浅金 UI（`../项目.md`）；NPC/场景统一方案 2（`../.design/npc-scene-unification-20261003/camp-unified-v2.png`）；技能/道具图标“手绘符记”；特效优先复用 `Q版日式手游SPINE特效300套`。
7. **野外满包**：停止并阻止全自动，不自动分解、不自动回城。
8. **版本**：改协议/规则/库表时分别提升 `protocol_version` / `ruleset_version` / `db_schema_version`；每批改动后用真实浏览器登录验证进入营地（见 `../docs/04-open-world/local-dev-service.md`）。
9. **不清档**：已有账号、角色、奖励回执、流水全部保留；已开放功能不回收。
10. **机器负载**：探针、vitest、数据库测试、浏览器验收逐个运行，不并行。

## 2. 目标形态

### 2.1 推荐方案：大岛无缝 + 岛间远航（默认）

**尺寸怎么定**：人物 6 格/秒。按“直线穿岛约 1.5 分钟、沿路实际走完一座岛 4–6 分钟、一个分区 1 分钟左右走穿”反推：

| 尺寸 | 直线穿过 | 对角穿过 | 面积（相对现在） | 评价 |
|---|---|---|---|---|
| 192×192 | 32 秒 | 45 秒 | ×9 | 太小，1 分钟逛完 |
| 384×384 | 64 秒 | 1.5 分钟 | ×36 | 偏小，6 区时每区约 150 格见方 |
| **512×512** | **85 秒** | **2 分钟** | **×64** | **推荐**：6–8 区，每区约 170–200 格见方 |
| 768×768 | 2.1 分钟 | 3 分钟 | ×144 | 需要坐骑/疾跑，内容填不满 |

- 每座岛从 64×64 扩到 **512×512 格（16×16 个 32 格区块）**，岛内**无缝**行走，不切图。
- 岛的轮廓不做成正方形：可走陆地约占 55–65%，其余是海、悬崖、湖、山体，用来做天然分区边界和视野遮挡。
- 跑图配套：传送点（§3.7）+ **疾跑**（脱战 3 秒后移速 +40%，进战取消；属于新机制，需新增执行能力与测试）。坐骑下一批。
- 岛与岛之间仍通过港口/远航切换（保留“星潮海群岛”设定和主线章节结构，改动风险最小）。
- 每座岛分 **6–8 个分区（Zone）**，每区有自己的等级带、主题、地标、营地、事件、传送点。
- 首领场保留为独立小图（剧情首领战需要演出与独立结算）。

> 备选方案 B：全部岛拼成一张超大无缝世界（约 1536×1024 格）。工作量和风险约为方案 A 的 2–3 倍（存档、授权、渲染、寻路全部要做流式分区），且与“群岛远航”设定冲突。**不采用**（见第 7 节决策 2）。

### 2.2 内容规模目标（6 座岛合计）

| 内容 | 现在 | 目标 | 说明 |
|---|---|---|---|
| 可走面积 | 6×64² | 6×512²（×64，可走约 60%） | 分区 40–48 个 |
| 野外怪物 | 每岛 24–30 | 每岛 600–900（营地 150–220 个×3–5 只） | 只加载玩家附近 2 圈区块、只激活 40 格内（§3.4） |
| 怪物模板 | 15 普通 + 6 精英 | 每岛 +2 普通、+1 精英，+2 稀有精英 → 共 27 普通、12 精英、12 稀有 | 可先用现有模板换色/缩放 |
| 传送点 | 0 | 每岛 8–12（每区 1–2） | 靠近交互解锁 |
| 世界事件 | 0（只有任务守护） | 每岛 6–8 个事件点，3–4 种类型循环 | 复用 `starsea/defense.ts` 守护机制 |
| 野外地下城入口 | 0 | 每岛 3 个（共 18 个新地城） | 走现有副本系统 |
| 宝箱/秘密点 | 0 | 每岛 25–40 | 一次性，服务端记账 |
| 支线/悬赏 | 每章 4–6 | 每章 15–24（每分区 2–3） | 全部在 `config/excel/任务.xlsx` |

### 2.3 时长目标

总时长仍为 30 小时 1→50 级（`balance-30h-design.md`）。地图变大以后：
- 主线路线长度控制在“主线总时长 18 小时”内，主线路过的分区约占岛面积 50%；
- 其余分区服务于支线、悬赏、事件、地城、刷装（属性规划表中的“养成追赶”时间）。

## 3. 功能改动（具体怎么做）

### 3.1 地图数据格式扩展

文件：`packages/content/starsea/index.ts`（`StarseaMapSource` 类型与校验），`packages/content/starsea/collision.ts`，地图 JSON。

新增字段（全部可选，旧地图不写也能加载）：

```jsonc
{
  "width": 512, "height": 512,
  "chunkCells": 32,                       // 渲染/模拟/存档的统一分块尺寸
  "zones": [{ "id": "wind-z1", "name": "落风坡", "rect": {"x":0,"y":320,"w":192,"h":192},
              "levelBand": [1,3], "theme": "wind-meadow", "ground": "ss-scene-ground-wind",
              "music": null, "ambient": "ss-scene-ambient-star" }],
  "camps": [{ "id": "wind-c01", "zone": "wind-z1", "x": 30, "y": 150, "radius": 4,
              "pack": [{"template":"ss-mon-wind-hound","rank":"normal","count":3},
                       {"template":"ss-mon-dock-scavenger","rank":"normal","count":1}],
              "elite": null, "respawnSeconds": 90 }],
  "patrols": [{ "id": "wind-p01", "zone": "wind-z2", "path": [[..],[..]], "template": "ss-elite-hook-leader", "rank": "elite" }],
  "rares": [{ "id": "wind-r01", "zone": "wind-z3", "spots": [[x,y],[x,y],[x,y]], "template": "...", "cooldownMinutes": 20 }],
  "waypoints": [{ "id": "wind-w1", "zone": "wind-z1", "x": 12, "y": 170, "resource": "ss-scene-waypoint" }],
  "dungeonEntrances": [{ "id": "wind-d1", "zone": "wind-z4", "x": 160, "y": 40, "dungeon": "ss-dg-wind-cave", "resource": "ss-scene-dungeon-cave" }],
  "events": [{ "id": "wind-e1", "zone": "wind-z2", "kind": "defend", "x": 90, "y": 120, "definition": "ev-wind-supply" }],
  "chests": [{ "id": "wind-x1", "zone": "wind-z3", "x": 70, "y": 60, "loot": "chest-t1" }]
}
```

规则：
- 怪物等级由 `zone.levelBand` 与营地在区内的位置决定（替代 `islandPlacements` 的随机路线进度）；精英 +1 级；仍走 `resolveMonsterSpawn`。
- **校验**（内容构建时报错，不允许运行时兜底）：营地/传送点/入口不在碰撞体、安全区内；营地之间最小间距 8 格；每个分区至少 1 个传送点；所有坐标可从登陆点寻路到达（复用 `findPath`）。
- 旧 `islandPlacements()` 保留给未迁移的地图；迁移完成后删除。

**数据来源**：分区、营地、传送点、入口、事件、宝箱的“设计数据”放新工作簿 `config/excel/世界.xlsx`（页签：分区 / 营地 / 巡逻 / 稀有 / 传送点 / 入口 / 事件 / 宝箱），按 AGENTS 配置表规则 `pnpm config:export` 导出，地图 JSON 只保留几何（地面、道路、碰撞、装饰）。表头写批注。

### 3.2 地图编辑流程

现有地图是手写 JSON + 生成脚本（`assets/starsea/scenes/generation.json`、`export.mjs`）。512×512 手写不可行，需要：
1. **灰盒生成脚本** `tools/world-graybox.mjs`：输入分区矩形与道路骨架，输出地面分区、道路、碰撞、悬崖边界、装饰散布（按分区主题的物件池与密度）。
2. **预览页**：复用 `assets/starsea/scenes/preview` + `serve.mjs`，叠加显示营地、传送点、入口、事件、等级带热力。
3. 可选：支持从 Tiled 导入（仓库已有 `packages/content/tiled.ts` 与旧 `*.tiled.json`），供手工精修。

### 3.3 刷怪与刷新（营地制）

**统一替换**现有两层规则（整图一轮 + 单怪 75 秒补刷 `starsea-respawn.ts`），新地图只用营地制：

- **营地（camp）是刷新单位**。每个营地有自己的轮次 `cycle`。
- 刷新条件：营地**全部**击杀 **且** 最后一只死亡后 ≥ 90 秒 **且** 玩家距营地中心 > **36 格**。三条同时满足，服务端才生成下一轮。
  - 为什么是 36 而不是 24：服务端不知道客户端视野，只能用距离代替。按投影 `屏幕x=(x−y)×32, 屏幕y=(x+y)×18`，1920×1080 画面的四角离角色约 30 格，再加营地半径 4 格，36 格才能保证刷新时营地真的在画面外。参数写进 `encounter-balance.json`，画面缩放或分辨率变了再调。
  - 站在营地里永不刷新；断线重连、续期、规则版本更新都不重置营地轮次与已击杀实例（AGENTS 恢复规则）。
- 旧规则迁移：旧 64 格地图下线后删除 `starsea-respawn.ts` 与 `starseaRespawn` 配置；已有 `~rN` 击杀回执保留只读。
- 稀有精英：每岛 2 个，多个候选点随机一个；击杀后**按角色**冷却 20 分钟。
- 巡逻精英：沿路径移动，同营地规则刷新。

**全自动的活动范围**：
- 开启全自动时记录当前**分区**；在本分区内找最近的“有活怪”营地，清完后自动走向下一个，不跨分区。
- 自动走开本身就满足“离开 36 格”，分区里营地轮转起来会自然刷新；若本分区所有营地都在冷却，停下并提示“本区营地刷新中”，由玩家决定等待或换区（不自动跨区）。
- 满包规则不变：停止并阻止全自动，整理后由玩家主动重开。

服务端改动（`apps/api/src/app.ts` `/api/permit`、`apps/api/src/battle-result.ts`、`database.ts`）：
- `ow_permits` 从“一行 = 整图 spawns”改为“一行 = 一个 (character, region, camp) 的一个 cycle”，或在 permit 数据里按营地分组保存 `{camp, cycle, spawns}`。推荐新表：
  `ow_camp_cycles(character, region, camp, cycle, spawns jsonb, created, cleared_at)`，主键 `(character, region, camp, cycle)`。
- spawn ID 规则：`{camp}:{cycle}:{index}`，击杀校验仍走 `ow_kills`。
- 新接口：`POST /api/field/camps`（参数：lease、region、玩家位置）→ 返回玩家周围 2 个区块内营地的当前 cycle 与存活实例；客户端进入新区块时调用。刷新判定在服务端做，客户端只请求。
- 奖励、时间校验（反作弊抽检）改为按营地 cycle 计；阈值沿用“只抽检、宁可漏判”原则。
- 迁移：旧 permit 行保留只读；角色首次进入新版岛屿时创建营地 cycle。提升 `db_schema_version`、`ruleset_version`、`protocol_version`。

### 3.4 模拟性能：只模拟附近（AOI）

文件：`packages/simulation/index.ts`。

- 引入**空间网格**（格子 8×8），敌人按位置入格；所有“对每个敌人”的循环（伤害、范围技能、AI、投射物命中）改为查询附近格。
- **激活集**：只有距玩家 ≤ 40 格的敌人执行 AI 与移动；其他敌人休眠（不移动、不回血、不消耗 tick 预算），回到范围内再唤醒。
- 区块外营地实例不加入 `World`（由 §3.3 的接口按区块加载/卸载）。卸载只在营地无交战时进行，交战中的怪保留直到脱战或死亡。
- 性能目标：同时加载 200 只怪、激活 40 只时，30 Hz 单 tick ≤ 2 ms（中档笔记本 Chrome）。新增基准 `tools/world-aoi-bench.ts`。
- 断线恢复、续期、规则版本更新必须保留营地实例状态与已击杀记录（遵守 AGENTS 副本/野外恢复规则）。

### 3.5 渲染与资源加载

文件：`apps/web/src/starsea-world-renderer.ts`、`scene.ts`、`iso.ts`。

- 地面 chunk 已有：改为**按相机视野 ±1 区块加载/释放**，记录纹理内存。
- 装饰物、建筑、营地物件按区块创建/销毁（现在一次性全建）。
- 分区地面过渡：相邻分区地面用渐变遮罩混合（需要美术提供过渡贴图或使用程序遮罩）。
- 进入新分区：显示分区横幅（名称 + 等级带），复用现有地区横幅组件。
- 首次进入岛屿显示加载进度；切区块不得卡顿（预加载下一区块）。

### 3.6 小地图 / 大地图 / 迷雾

文件：小地图相关（`docs/minimap.md` 已定 B 方案「圆形近域雷达」）。

- 雷达保持现状（跟随角色）。
- 全图（点击展开）：显示已探索区域、分区名称、传送点、地城入口、当前事件、任务目标方向；未探索区域覆盖迷雾。
- 迷雾数据：每岛按 8×8 格记录已探索位图，服务端保存（`ow_characters.state.exploration[region]`，base64 位图），客户端每 10 秒或进入新格时上报，服务端只做“只增不减”合并。
- 图例与图标风格遵守 `docs/minimap.md` 与手绘符记规范。

### 3.7 传送点（快速旅行）与疾跑

- 传送点需**走到附近交互**才解锁（服务端记录 `state.waypoints`）。
- 全图上点击已解锁传送点 → `POST /api/travel/waypoint`：同岛已解锁点之间**免费**；战斗中、副本中禁止；**满包允许传送**（用于回前哨/营地整理）。服务端校验后返回新位置，客户端走现有定位流程。
- 跨岛仍走远航（保留现有远航门规则）。
- 疾跑：脱战 3 秒后移速 +40%，受击或进战立即取消；新机制，需在 simulation 增加执行能力并补测试。坐骑下一批。
- 老角色进入新版岛屿时，自动解锁其已到达过的登陆点与首领门附近传送点（不补造其他历史）。

### 3.8 野外地下城入口与新地城

- 入口是场景物件 + 交互气泡（复用 `interact-bubble.ts`），点击后打开该地城的副本目录条目（不在野外直接开战）。

- 旧区域试炼/高难/噩梦/团队：保留（不删除），后续可换成星潮海地城地图；数值按属性规划表「副本推算」页重新标定。

### 3.9 世界事件、稀有精英、宝箱

- 事件类型（第一版只做已有执行能力的）：
  1. **守护**：复用 `packages/content/starsea/defense.ts`（任务里已用）。
  2. **歼灭波次**：限时击杀 N 波（复用任务波次生成）。
  3. **护送**：NPC 沿路径移动，需要新执行逻辑（新机制需新增执行能力与测试，按 AGENTS 规则列为第二批）。

### 3.13 寻路与移动（2026-10-06 已修第一步）

**问题**：等距投影 `屏幕x=(x−y)×32, 屏幕y=(x+y)×18`，屏幕上的“水平/竖直”其实是网格**对角线**。旧 `findPath` 是只走上下左右 4 方向的广度搜索，于是往屏幕右边走会变成“右下、右上”交替的阶梯，或先一路右下再一路右上的 V 字——表现为人物“上下走”。

**已改（`packages/simulation/navigation.ts`）**：
- 8 方向 A*（八方向距离启发；斜走不切墙角：两侧正交格都可走才允许斜走）。
- 路径拉直：从当前点一直连到最远的直线可达路点（按同一碰撞半径逐 0.25 格采样），只保留拐点。空地上任意方向都是一条直线。
- 测试：`tests/simulation.test.ts` 新增“空地对角直走只有 1 个路点”“拉直后每段都不穿障碍”。导航相关 33 项通过；全量测试中另有 4 项失败，已用旧寻路对照确认是改动前就存在的失败（战斗轨迹录制 2 项、威能旋风 1 项、天赋文案 1 项）。

**大地图还需要做（实现方）**：
1. **碰撞网格**：`walkable()` 现在每次都扫描全部障碍物；512 地图障碍物会到数千个，A* 会慢到不可用。地图加载时按碰撞半径（0.35/0.55/怪物体型）预先生成位图，`walkable` 改为查表，动态障碍（技能召唤物）另叠一层。
2. **分层寻路**：先在“区块图”（32 格一块，记录区块边界的连通口）上找区块序列，再在相邻区块内做 A*；或者长距离直接沿道路网（道路折线即导航图）。目标：512 地图任意两点 ≤ 5 ms。
3. **怪物寻路限距**：怪物只在拴绳半径内寻路（营地半径 + 12 格），超出就回营地，不跨图追人。
4. **键盘方向**：键盘 WASD/方向键已经按屏幕方向换算到网格（`control()` 归一化）；验收时确认 8 个屏幕方向都是直线。
5. **自动战斗走位**（规则见 §3.3「全自动的活动范围」）：自动模式找怪改为“当前营地/分区内最近的怪”，不跨分区乱跑。

### 3.14 主线与主线人物

> 2026-10-06 用户裁定取消严格主线：下文“主干路”“剧情硬门槛”“按主线进度开放”以 [任务系统改造](open-world-quest-system.md) 为准（方案 A：每岛故事拆为并行线索、任务由发现触发、目标认世界事实；岛屿按等级/首领开放；剧情门改为世界机关；人物按所在线索站位）。

> 逐章任务表、人物站位表、剧情门见 [开放世界内容方案](open-world-content-plan.md)。

**现状**（`config/json/npcs.json`、`tasks.json`）：
- 星潮海 7 个主线人物（澄、米洛、铜铃、青芒、雪弥、弥迦、烬羽）的驻地全部在港口 `ss-map-port`，各自挂一个服务（强化、采集制造、召唤石、威能、挑战……），按主线逐个开放。
- 主线 6 章 × 6 个任务、63 个步骤：交谈 8、调查交互 21、战斗 15、选路线 6、路线战斗 6、首领 6、守护 1。
- 岛上步骤只写“地图 + 地标”（landing / clue / objective / route-a / route-b / device-1…），每座岛只有 4–5 个地标。交谈几乎全在港口；岛上人物只有米洛（第一章落点）和烬羽（龙眠岛）。
- 剧情战斗走服务端剧情副本实例（`story-*`），客户端不能自报完成。

**开放世界里的做法**：

1. **主线是一条穿过分区的“主干路”**
   - 每章主线从“岛上 4–5 个地标”扩到“穿过本岛 4–5 个分区”，每个分区 1–2 个主线步骤，主线约占岛面积的一半，其余分区留给支线、事件、地城。
   - 地标改成“分区 + 地标”两级：`zone: wind-z2, landmark: objective`，坐标在 `世界.xlsx`「地标」页；任务表只引用地标 ID，不写坐标。现有地标 ID 全部保留并迁到对应分区（旧存档的进行中步骤不失效）。
   - 每章新增 2–3 个“串场”主线任务（护送米洛去下一个分区、在前哨与人物会合、调查沿途线索），让主线把玩家带进新分区；文案、奖励全部写进 `config/excel/任务.xlsx`，不写进代码。
   - 主线怪物等级 = 所在分区等级带（不随玩家等级缩放）；等级不够时引导去本区支线/营地（始终有刷级路线）。

2. **主线人物“随剧情走”，不是永远站在港口**
   - `NPC.xlsx` 新增「站位」页：`npc, 地图, 分区, 地标, 出现条件（某任务接取后/完成后）, 消失条件, 朝向, 待机动作, 闲聊组`。服务端按角色主线进度解析“此刻这个人物在哪”，客户端只按结果摆人，同一时刻**一个人物只出现在一个地方**（不分身）。
   - 例：米洛第一章在风栖岛落点 → 第二章跟着去雾铃岛前哨 → 回港后回到港口；铜铃第三章出现在炉心岛工坊遗址；雪弥第四章在霜镜岛观测站。
   - 人物离开港口时，港口驻地显示“外出：在××岛××”，地图上可点击定位。
   - **服务不跟人走**（默认）：强化、召唤石等服务挂在港口的设施（工作台、观测仪）上，人物外出时设施照常可用。这样不会因为剧情把玩家的强化入口带走。

3. **每岛一个“前哨营地”（安全区）**
   - 每岛 1–2 个前哨：传送点 + 补给（修理、出售、仓库），由通用前哨 NPC（非主线人物）负责；主线人物在剧情进行到这里时会站在前哨里。
   - 死亡仍按 AGENTS 规则返回归途营地，前哨不替代主城。

4. **世界随主线变化（个人相位）**
   - 野外是每个角色各自一份（授权按角色），所以可以按角色进度切换世界状态：分区可以带 `when` 条件，例如“第一章首领前，船坞区是侵军营地；击败后换成友方前哨，营地怪移除”。
   - 少量**剧情硬门槛**保持叙事顺序：雾墙、封印门、断桥，主线推进到对应步骤才打开；其余靠等级带软门槛，不做空气墙。
   - 主线战斗/救援/守护地点周边的普通营地，在该步骤进行中对这个角色暂停刷新，避免野怪混进剧情战。剧情战斗仍走现有 `story-*` 实例，规则不变。

5. **首领**：首领场继续独立地图；入口变成分区里的“首领门”物件，明确点击进入（AGENTS：首领新挑战必须由明确进入开始）。

6. **新增区域人物（支线）**：每个分区 1–2 个区域人物（村民、商人、遇难船员、侵军逃兵），发布支线和悬赏，约 40–60 人。外观按 NPC 统一方案 2 用现有骨骼与服装零件换装组合，不逐个新画。

7. **引导**：按已确认规则，只有方向箭头 + 一行任务文字；目标在别的分区时箭头指向最近已解锁传送点或分区出口；主线人物在全图上用专属图标标出当前位置。

8. **旧存档**：进行中的主线步骤按“旧地标 ID → 新分区地标”映射继续；已完成的章节不补造新串场任务的历史，新串场任务对老角色直接视为已完成（不发奖）；人物站位按当前进度直接解析。

**验收**：6 章主线在新地图上能从头走到尾，每章至少穿过 4 个分区；人物在剧情各阶段只出现在一个地方，站位与进度一致；人物外出时港口服务可用；剧情门在对应步骤前打不开、之后永久打开；老角色进行中的步骤不失效；真实数据库测试覆盖“剧情进度 → 人物站位/分区相位”的服务端解析与断线恢复。

## 5. 分阶段落地计划

2026-10-06 执行顺序补充：用户要求美术先落地。M0 已完成、M1 已实施部分保留；先制作并验收 §4 的 P0/P1 正式资源包，再继续剩余系统与六岛内容集成。风栖岛套件先形成统一样板，再扩展其余主题。下方 M0–M5 编号继续表示功能和内容里程碑，不把美术资源交付冒充对应玩法完成。当前事实见 [实施进度](open-world-implementation-progress.md#当前执行优先级美术先落地)。

> 每个里程碑都要：自动化测试通过 → 内容校验 → 生产构建 → 真实浏览器登录进入营地与新岛屿（AGENTS 版本同步规则）→ 记录证据。按用户要求：**内容全部做完后由用户统一试玩**，中途不要求用户逐章走查。

### M0 技术原型（灰盒，1 座岛）
- 512×512 灰盒风栖岛（`tools/world-graybox.mjs` 生成），6 个分区、150 个营地、8 个传送点。
- 碰撞网格 + 分层寻路（§3.13）达到性能指标。
- `World` 空间网格 + 激活集；`tools/world-aoi-bench.ts` 达到 §3.4 指标。
- 渲染按视野加载/释放区块与装饰。
- **验收**：自动模式在新岛连续刷 10 分钟无掉帧（≥ 50 FPS），内存平稳；旧岛与旧存档正常。

### M1 系统
- 营地制刷新（服务端表、接口、反作弊抽检、迁移）。
- 传送点解锁与传送；全图 + 迷雾；分区横幅。
- 任务表新增分区字段与引导箭头指向传送点。
- **验收**：真实数据库测试覆盖“清营地→离开→刷新”“在营地内不刷新”“断线恢复保留实例”“传送防重”；老角色登录位置迁移正确。

### M2 第一座岛内容（风栖岛）
- 正式地面/物件/营地物件/地标/传送点/入口美术（P0）。
- 3 个野外地城 + 2 种事件 + 宝箱 + 稀有精英。
- 数值按属性规划表标定，`field-efficiency-probe` 复测交战占比 ≥ 50%。

### M3 其余 5 座岛
- 逐岛复制 M2 流程（P1 美术）。主线任务改走新分区（`config/excel` 修改，不改代码）。

### M4 地城与旧副本迁移
- 18 个新地城（每岛 3 个）定义与地图；旧试炼/高难/噩梦/团队数值按「副本推算」重标。

### M5 丰富度（P2）
- 护送事件（新执行能力 + 测试）、稀有精英全量、环境音、分区图标。

## 6. 验收标准汇总

2026-10-08 实施字段：正式末地城可声明`hardmode`（阶段、准入等级、怪物等级和难度），目录/创建由服务端按角色解析，开战后冻结。副本政策可声明逐房间`stageEnemyScale`，长度须覆盖全部房间，首领与入口压力可以独立定标；不会按玩家战斗属性临时缩放。世界营地、巡逻、事件、稀有的新实例按本岛正常等级区间到裂星潮区间比例映射分区等级，已生成实例保持原等级和世界层级。

终局再挑战通过`hardmode.worldTierScalingFrom`声明何时启用终局层级；达到该层级的新实例冻结相对难度和对应层级钥匙池，真实通关开放下一层。活动冻结等级、层级难度、词缀范围、生成半径和收益基础；怪潮从已声明范围内侧生成，自动活动使用同一范围约束。守护目标生命按普通/当前遭遇等级的已登记生命曲线比例升阶，在服务端生成时冻结；剧情波次`defense`下发已解析生命/半径/守护时长，客户端只消费，旧波次仍用原参数。

1. 6 座岛均为 512×512 无缝；每岛 ≥ 6 分区、≥ 150 营地、≥ 8 传送点、3 地城入口、≥ 6 事件点。
1b. 寻路：屏幕上的左右/上下移动走直线，不出现阶梯、V 字或无故折返；任意两点寻路在 512 地图上 ≤ 5 ms。
2. 野外交战时间占比 ≥ 50%，普通怪体感 TTK、首领体感 TTK 在属性规划表目标 ±20% 内（`field-efficiency-probe` 报告，写明版本、种子、样本、限制）。
3. 30 小时 1→50 级节奏偏差 ≤ 10%（`pnpm balance`）。
4. 性能：§3.4 基准达标；进岛加载 ≤ 5 秒；切区块无可感卡顿。
5. 服务端：营地刷新、传送、宝箱、事件、稀有精英全部防重，断线恢复不丢实例、不重复发奖。
6. 老存档：全部账号可登录，位置合法，回执与流水条数不变。
7. `pnpm config:check`、内容校验、类型检查、生产构建、真实浏览器登录全部通过。
