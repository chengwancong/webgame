# 任务列表与领奖档案

2026-10-02，用户批准多任务列表方案落地。游戏HUD入口改为“任务”，打开后左侧常驻任务列表，右侧固定详情；类型使用金色主线、紫色副本、青绿支线及不同图形。当前任务和任务档案分别保存筛选、选择、列表位置及正文滚动。1280×720窗口为1144×608；较小视口使用所属区域滚动或上下排列，正文不整体缩放。

## 正式内容与分类

2026-10-03 更新：用户授权「先做主线，再完善整个副本及 NPC、怪物、技能、功能解锁」。已经增加「最后一条归途」六章正式任务，具有服务端确认的调查、路线战斗、救援、守护与首领进度，营地报告后形成领奖档案并衔接下一章。原两项目标和已保存的历史档案保留。当前行为以 [主线与剧情关卡](story-campaign.md) 为准；下文两项任务与无前后关系的描述记录 2026-10-02 版本，不能覆盖新主线。

正式内容仍为初识苍风、穿过结界两项原有任务，每项奖励50金币、5灵石、0经验。设计稿的12条任务和8条历史记录未发布。配置入口为 `packages/content/tasks.ts`，三个初始类型是可扩展的平级目录，类型标识、名称、排序、启用状态、颜色与图形均有明确字段。

每任务只有一个主类型。穿过结界属于主线，守门人试炼是地点和标签；副本分类不会重复显示它。任务链字段保留，但这两项现有目标没有已定义的前后领取关系，按独立目标展示；不把示意图的任务链变成新的准入条件。Boss准入消费现有 `resolveBossAccess`，首次击败Boss即开放迷雾林地，不等待任务领奖。

## 服务端数据和事务

`GET /api/tasks` 返回角色标识、角色版本、规则版本、类型、当前任务、只读档案。当前进度和奖励由API解析，界面不重新判断累计击杀或读取私有奖励表。任务详情不使用界面示例数据，也不将档案复制到当前列表。

`POST /api/task/claim` 保留原命令结构和回执指纹，复用角色锁、控制权、revision与command_id检查。奖励、已领取标志、完整档案快照、回执和流水同事务提交；任一写入失败全部回滚。原command_id重放返回原回执，新command_id重复领奖被拒绝。

持久状态位于角色JSON的 `taskJournal`：`completed`记录服务器确认目标首次达成的时间，`archive`保存领奖时目标、达成数、剧情摘要、主类型、地点、任务链、奖励与两种时间的快照。当前定义、名称、奖励或分类变更不改写已保存档案。只将发生未达成→达成转换的新写事件记时；已有达成事实但无事件时间时保持空值。

当前任务为一次性目标，同一taskId只能领取一次。重复任务需要另行定义实例或周期标识；本次不把重复领取当作任务档案功能。

## 旧存档迁移

数据库10迁移只补充任务记录，不修改金币、灵石、装备、击杀、Boss、区域、战斗build或已有回执。已有已领取任务进入档案。若连续revision的真实回执能证明单一任务从未领取变为已领取，则保存该回执的实际delta及流水时间；不从当前奖励表推算过去金额。无证据的金额与时间为空，界面显示“未记录”。旧剧情、目标细节、任务链和达成时间也不补造。

历史类型按已知任务ID映射到当前平级目录；未知旧任务使用历史未分类。停用或改名类型不会隐藏对应历史记录。迁移有版本标记，重复启动保持幂等。

## 交互与恢复

领奖前不提前把任务放入档案。客户端使用已有IndexedDB outbox及回执恢复：不确定的操作保留待核对状态；服务器已确认的档案可显示，客户端不自行制造成功状态。恢复连接后继续留在任务页，查询原回执，不创建第二次发奖命令。

列表、标题图标、说明、目标、任务链、地点、奖励、记录和底部操作均有固定区域。选中、悬浮、长文本、待确认、失败与归档不改变它们的占位。任务窗口采用局部DOM更新，输入焦点和滚动位置不因重绘丢失。空筛选保留列表区域；当前任务全部完成时提供直接查看档案入口。
