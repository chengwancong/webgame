# 混合方案落地：泰拉瑞亚骨架 × 暗黑4/流放之路伤害深度 × 星潮海主线

日期：2026-10-04。用户决定：A 混合；由 Claude 负责设计与落地；开发环境存档可全清；目标是好玩。
数值依据：[balance-30h-design.md](balance-30h-design.md)、[build-depth-design.md](build-depth-design.md)。剧情依据：[starsea/requirements.json](starsea/requirements.json)。

## 1. 一句话

新角色在**拾星港**醒来，沿星潮海六岛主线（36 个任务）推进。每击败一个岛的首领：
- 一位 NPC **入住**港口，开放一个系统（泰拉瑞亚式）；
- 下一阶段装备开放（T1→T8）；
- 第六章后世界进入**裂星潮**（困难模式），六岛怪物整体升阶，开放太古装备和后期乘区。

伤害走“加算池 [+] × 独立乘区 [×] × 暴击 × 易伤”的结构，数字从几十涨到几百万。

## 2. 关键架构决定

| # | 决定 | 原因 |
|---|---|---|
| H1 | 主线任务在**野外**进行（客户端模拟 + 服务端授权/结算），不另开副本实例 | 同一张岛图先剧情、后刷图，像泰拉瑞亚一样是一个连续世界；复用 permit/report 权威链路 |
| H2 | 任务波次怪由服务端追加到当前岛的 permit（ID 前缀 `q:`），击杀经 `/combat/report` 结算，并推进任务进度 | 击杀仍由服务端校验，任务进度只由服务端写 |
| H3 | 调查、交互、对话步骤走 `POST /api/quest`；服务端校验当前步骤与前置击杀 | 剧情顺序权威 |
| H4 | 首领场 `ss-map-boss-N` 走野外 permit（boss 区域，每次进入新 attempt）；首通推进任务，之后可重复挑战刷装备 | 泰拉瑞亚式“首领可重打” |
| H5 | 岛上的常驻刷怪由内容生成器按岛等级段确定性生成（成群，避开安全区和障碍）；permit 生成时按角色世界状态（是否裂星潮）决定怪物等级 | 地图源 JSON 只有美术站位；困难模式只需换等级 |
| H6 | 新角色只走星潮海。旧地图、旧主线和旧副本代码暂留，但不出现在新角色的路线里 | 存档可清；不一次性删除大量已测代码 |
| H7 | `storyFeatureUnlocked` 对有 `starsea` 状态的角色改读星潮海解锁表 | 强化、采集制造、武器盘、召唤石、法典、梦魇只用一个开关 |

## 4. 任务运行时（服务端）

角色状态 `starsea`：`{version, chapter, task, step, progress, choices, done[], npcs[], features[], hardmode, crystals[]}`。

任务类型拆成步骤：

| 类型 | 步骤 |
|---|---|
| battle / defend | `wave(required, at landmark)` |
| choice-battle | `choose(a/b)` → `wave(3, at route landmark)` |
| rescue | `wave(required)` → `interact(landmark)` |
| investigate | `interact(landmark)` |
| multi-investigate / multi-interact | `interact` × N（clue-1..3 / device-1..3） |
| multi-defend | `wave` × N（device-1..N） |
| dialogue / report / post-boss-report | `talk(speaker, at port)` |
| boss | `boss(map)`：击败首领场首领 |

- 角色接近任务地标，客户端发 `quest start`，服务端把波次追加进 permit，并返回给客户端加入世界。
- 任务完成时：
  - 发放经验和金币（剧情占主线期约 30% 经验）；
  - 回港报告时发放章节宝箱（必出本阶段稀有及以上）；
  - NPC 入住；
  - 解锁功能；
  - 开放下一岛。

## 6. 已落地的运行规则（2026-10-04）

### 出生与旧内容隔离
- `createApp` 的 `campaign` 选项默认 `'starsea'`：新角色出生在拾星港，拥有 `starsea` 状态，装备经 `applyItemPower` 按物品等级定数值。
- 旧测试显式传 `campaign:'legacy'`，角色保持旧路线（`town`/`meadow`），不带 `starsea` 状态。这个选项只给测试用，正式服务不传。

### 野外节奏（Region 标志，由 `starseaRegion` 生成）
| 标志 | 取值 | 作用 |
|---|---|---|
| `rest` | 港口（hub） | 每帧回复生命，不自动施法。旧 `town` 规则保留 |
| `calmRegen` | 岛屿 0.03 | 脱战 4 秒（`outOfCombatTicks=120`，以最后一次掉血计）后，每秒回复 3% 最大生命 |
| `aggroRadius` | 岛屿 8 | 怪在 8 格内或受伤才进入交战，并带上同群（ID 同前缀且 6 格内）。不再整图 20 格一起围上来 |

`hurtAt` 是 World 私有字段，并列入 `heroFields`，所以检查点和断线恢复会保留它。

### 岛上刷怪
- 群锚点避开剧情地标（`landing`/`gate` 除外）10 格以内的区域。
- 群间距至少 7 格，每岛最多 30 个锚点。
- 教学岛（第一章）野外没有精英。任务波次里，第一章在首领之前也不出精英；其他章仍从第 4 个任务开始出。

### 经验
- 星潮海击杀经验为 `30 × 1.12^(L-1) × 档位倍率 × 越级惩罚`，是 30 小时模型的 3 倍。目的是让“岛上刷两三轮”就能补够首领的推荐等级。
- 主线任务经验不变，到首领前大约 3100。

### 首领
- 目标：同级“普通”构筑（装备落后 2 级）在半自动下约 50 秒击杀首领，站桩约 35 秒倒下。所以需要走位，或者再练两级。
- 工具：`npx tsx tools/starsea-boss-tune.ts [--write]` 测量双方秒伤，反推模板的 `base.hp` 和 `base.attack`。多跑几次会收敛。
- 修复：首领施法结算原来按 `owner.art` 查技能表。星潮海首领的 art 是自己的皮肤，查不到技能表，导致第 4–6 首领的技能从不生效。现在统一用 `bossKey(owner)`，即 `bossProfile ?? bossKey ?? art`。修复后重新调参，六个首领全部达到上述目标。
- HUD：首领步骤显示“推荐等级 Lv(首领等级-2)（当前 LvX）”。等级不足时标黄，并提示先在岛上野外历练。

### 模型工具
| 工具 | 用途 |
|---|---|
| `tools/starsea-power-model.ts` | 各等级期望角色的命中与怪物生命比 |
| `tools/starsea-fight-model.ts` | 新角色对一组怪的胜负 |
| `tools/starsea-island-walk.ts` | 期望角色从登陆点走到岛门 |
| `tools/starsea-boss-tune.ts` | 首领调参 |
| `tools/probe-quest.mjs` | 真浏览器主线探针。等级低于推荐时，回本章岛开全自动历练；服务重载后点击“恢复连接” |

### 巡猎（全自动）
- 岛屿带 `roam`：附近没有目标、也没有待拾取掉落时，挂机中心移到最近的怪群，全自动可以自己清完整座岛。

## 7. 构筑深度与泰拉瑞亚系统（2026-10-04）

### 技能标签与乘区
- 技能标签由 `packages/content/skill-tags.ts` 推导，分三类：
  - 形态：近战 / 远程 / 法术。
  - 元素：物理 / 火焰 / 冰霜 / 闪电 / 奥术 / 暗影 / 毒素。
  - 方式：单体 / 范围 / 投射物 / 持续 / 位移 / 传导。
- 乘区可以带 `tags`。`foldZones(zones, skillTags)` 只折算命中标签的区和通用区。角色面板的通用 [+]/[×] 只算不带标签的区。
- 标签词缀（13 种，如“火焰伤害”“范围伤害”）进入加算池，T2 为 8–15%，T3 为 16–30%。词缀描述写作“火焰伤害 [+]15%”。
- 套装：每个装备系的 4 件和 6 件效果各带一个按标签的 [×]，随美术阶段 T1/T2/T3 提升（`equipment-runtime.json` 的 `setZones`）。
- 构筑威能（16 个 `aspect-build-*`）：每个只给一个标签 [×]，例如余烬之心让持续技能 [×]1.25、焚心烈焰让火焰技能 [×]1.2。
  - 法典每级再 +10%。
  - 穿戴中的传奇装备自带威能直接生效，萃取和刻印用来把威能转移到别的装备。
  - 掉落的传奇有 2/3 概率是构筑威能。

### 分章掉落
- 每座岛偏重两个装备系，掉落权重 ×3（`starseaLootFocus` 加上 `equipment-drop-rules.json` 的 `familyBoost`）。航图会显示“多掉 X、Y 系”。
  - 风栖：剑、暗器。
  - 雾铃：法杖、魔杖。
  - 赤炉：锤、斧。
  - 霜镜：魔杖、暗器。
  - 沉星：法杖、剑。
  - 龙眠：斧、锤。

### 生命星晶与星核
- 每岛 2 处生命星晶，每处 +5% 最大生命。裂星潮后每岛另有 1 处星核，每处伤害 [×]1.1。
- 位置由 `relicSpots` 按地图确定性挑选，避开安全区、碰撞和地标，藏在角落。六岛全部可达（寻路模拟验证）。
- 收取方式：靠近后按交互，客户端发 `POST /api/quest {op:'relic'}`，服务端写入 `starsea.crystals`。航图显示每岛“星晶 x/y”。

### 星潮夜
- 同一座岛累计击杀 40 只野怪（任务波次和首领不算）后，岛中央登陆 5 只入侵怪，其中 3 只精英。
- 入侵怪必掉稀有及以上，全部击退后额外发金币。入侵进行中的击杀不计入下一次的进度。
- 入侵怪会追加进当前野外授权；授权重建时由 `starseaPendingWave` 补回。HUD 显示“星潮 x/40”和入侵进度。

### 大数字与伤害面板
- `formatBig` 统一缩写为 万 / 亿，保留 3 位有效数字。飘字和人物面板都在用。
- 人物面板新增“伤害乘区”：逐条列出 [+]/[×] 的来源和生效标签，以及每个技能的单次伤害。

### 副本接入星潮海
- 星潮海角色开的副本记 `world_line:'starsea'`。
- 旧区 1–9 级映射到 9–37 级：首领等级段，与六岛首领对齐。
- 旧模板按星潮海曲线换算生命和攻击，仍然是“模板＋等级＋档位＋难度”，不看玩家等级。
- 副本经验和金币仍走旧表，偏低，后续可以改成按怪物等级发放。

### 已知待办
- 副本奖励没有按星潮海经济重算。
- 赤炉岛：用期望装备模拟，L17 对 3 只 L20 的怪 12.5 秒取胜。之前“倒在路上”是因为首领技能表的 bug 和探针用的装备偏弱。
- 雾铃岛：任务点、星晶全部可达。之前的超时来自探针在战斗中途被打断。

2026-10-05 客户端入口统一隐藏：`apps/web/src/story-gates.ts` 只调用 `packages/rules/story-campaign.ts` 的 `storyFeatureUnlocked` / `storyProgressionFeature`，不另写解锁条件；服务端拦截保持不变。未解锁时隐藏：养成分组与模块（武器盘、武器成长、威能法典与收集奖励、召唤石、采集与制造、挑战赛季及其高难/梦魇/团队页签；分组只剩一个模块时改用模块名）、副本目录里带 `feature` 的类型与条目、远行地图“副本挑战”、首领传送门（提示原因，不打开面板）、背包材料里去往锁定模块的按钮。老角色（`legacyAccess`）和快照未就绪时不隐藏。测试：`tests/story-gates-ui.test.ts`。


## 2026-10-05 战斗手感：护盾、打击反馈与飘字

- 权威 `CombatEvent` 新增可选 `crit?:true`、`shieldPhase?:'applied'|'absorbed'`、`shieldRemaining?:number`。暴击沿用原判定和 RNG 调用顺序；护盾字段在施放/扣除后的事实事件发出。`World` checkpoint 与副本快照的事件对象通用序列化，无事件字段白名单；旧事件缺字段继续兼容。反作弊规则未改。
- Token 源 `packages/ui-tokens/tokens.json` 新增 `Font.Size.CombatHit/CombatCrit/CombatMinor/CombatTaken/CombatLabel`，以及 `Color.Combat.Crit/Heal/Shield/Miss/Element.{Fire,Cold,Lightning,Arcane,Shadow,Poison}/NumberStroke/HealthTrail`；仍由 `tools/build-ui-tokens.mjs` 生成。物理输出继续引用 `Color.World.Text`。
- `world-numbers.ts` 管分类、样式、运动、确定性散布、四槽堆叠、DOT 合并和 28 个上限；主角提示补充可见行距，避免护盾获得和吸收在不同运动曲线下重叠。
- `hit-feedback.ts` 管渲染闪光、挤压、击退、动画冻结、血条残影、重伤暗角和分档相机震动；只读取模拟数据，不写角色位置或战斗时钟。图集、换装与原生骨骼均接入显示时钟。
- `combat-audio.ts` 使用确定性合成与 8 个完整声部上限，提供命中、暴击、受伤、击杀、护盾及闪避音效；危险提示优先，其次破盾与击杀。
- `shield-feedback.ts` 记录纯表现状态：生成、常驻、吸收、破碎、自然到期。活动 `combat-vfx.ts` 绘制前后半盾、高光/涟漪、代码碎片和到期光点，复用 `VfxPool`；旧 `skill-effects.ts` 未扩展。圣盾原纹理按 holy 奶白浅金染色，冰盾保留冰色。头顶血条和现有 HUD 共用 `shieldBarSegments` 规则。
- 同一地区、单调 tick 的权威快照替换会保留表现状态；换地区或回退时清理。减少动态效果关闭位移、弹跳、顿帧和震屏，保留颜色与淡出。
- 独立开发验收页 `combat-feel-qa.html` / `src/qa/combat-feel.ts` 使用模拟器产生事件，不接入玩家入口、账号或奖励。复验命令 `node tools/verify-combat-feel.mjs`；硬件压力复验加 `--hardware-performance`。证据及两项既有自动化失败见 [战斗手感验收](reviews/combat-feel-20261005/result.md)。
