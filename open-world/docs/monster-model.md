# 怪物模板、等级、档位与副本修正

2026-10-03，客户端 0.8.5／协议 12／规则 ow-16。用户确认四层结构；高难、梦魇、团本各自指定怪物等级，迁移时保留原首领实际强度。

## 唯一数据与解析链路

- `packages/content/monsters.json`：模板身份、外观、行为、参考等级、生命／攻击／护甲基值、等级曲线、普通／精英／首领系数、AI 参数、技能绑定和召唤物模板。
- 地图的怪物点只配置 `monster`、`level`、`rank` 和位置；加载时由 `rules/monster-stats.ts` 解析实际属性。地图不再保存另一套生命、攻击或行为数据。
- `dungeons.json`：每个正式副本明确配置 `policy.monsterLevel`，角色准入等级仍为独立字段。旧记录缺少该字段时保留当时的地图实例值。
- `rules/dungeon-build.ts`：使用创建时冻结的模板、指定等级、档位和难度参数，统一计算入场与后续阶段的敌人。主线波次用同一解析器升为精英，不再借用另一个物种的精英生命／攻击。

公式：

`属性 = 模板基值 × 曲线(指定等级) / 曲线(模板参考等级) × 档位系数 × 副本／层数／词缀／阶段修正`

模板参考等级用于标定基值，与玩家等级无关。曲线节点之间线性插值；只有最终生成实例时取整。未知模板、档位、技能、曲线或超出配置范围的等级直接报错，不使用地区三档统一覆盖或隐藏备用数值。此轮没有追加等级差伤害惩罚。

## 当前标定

等级曲线以旧六区普通怪预算的 1／2／4／5／7／9 级锚点为基础，显式扩展 20／30／40／50／100 级节点。扩展节点是本作迁移标定，不能称为复刻其他游戏的整套等级成长。普通／精英／首领的生命系数为 1／2／10，攻击系数为 1／1.5／2；每个首领模板按原属性标定独立基值。

同为雪域 5 级普通怪，冰霜狼 180 生命／16 攻击、雪地游侠 153／18、冰元素 171／15。重甲物种具有模板护甲；护甲与玩家共享命中减伤公式，穿透降低有效怪物护甲。原先守卫固定减伤 5 只保留在旧记录兼容路径。

普通龙王指定 9 级，保持 6500／36；高难龙王指定 50 级，保持 32500／101。难度修正按等级成长后的数值校准，部分系数小于 1，表示迁移校准。比较最终生命与攻击，不能直接拿不同等级的倍率大小判断难度。层数、词缀和阶段修正在此基础上继续应用一次。

首领技能倍率、阶段阈值、前摇和范围保留现有配置。模板绑定技能与首领行为键，外观字段只选择资源。召唤物获得独立模板身份和普通档位；现有固定召唤预算与幼龙父体比例保留，避免复制召唤者的首领技能和身份。

## 历史状态与验收

旧地区统一覆盖表和两套怪物草案移入 `docs/history/`，不进入运行包。旧许可、已运行副本、存档怪物保留原属性、生命、冷却、技能阶段与已击杀状态；恢复读取冻结的模板与规则，不用新表重建。新怪物的解析属性及来源在许可与战斗快照中保存，客户端通过合同校验保留字段。

机器证据位于工程上一级 `docs/reviews/open-world/monster-model-20261003/`：迁移前实例、逐副本校准、全部解析模板与 60 组首领边界预算核对、30 条实际技能路线及失败样本。预算核对覆盖最低／最高层数与首／末阶段；不代表真人难度或自动策略结果完全一致。

真实 PostgreSQL、HTTP 与 WebSocket 用 60 级角色进入指定 25 级怪物的副本，并在创建后修改当前模板对象，验证开战仍读取创建时快照；现有断线、救援、团灭、多人、阶段推进与奖励防重继续回归。

复验：`pnpm exec tsx tools/balance-monsters.ts`、`pnpm exec tsx tools/balance-campaign.ts --out=../docs/reviews/open-world/monster-model-20261003/campaign.json`、`node tools/verify-dungeon-suite.mjs`。
