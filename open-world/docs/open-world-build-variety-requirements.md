## A. 现状盘点

### A.1 计算链路（谁算、在哪执行）

**服务端解析**（`packages/rules/index.ts` `resolveBuild`，唯一所有者）

| 顺序 | 步骤 | 函数 / 文件 |
|---|---|---|
| 1 | 等级基础属性 + 已穿装备主属性 + 强化 | `levelStats`、`gearContribution` |
| 2 | 副属性：12 种通用属性直接相加；13 种标签增伤生成 `affix-<标签>` 加算区 | `simulation/set-calculator.ts` `applyAffixBonuses`（switch 分支） |
| 3 | 套装：属性相加；4/6 件生成按标签的独立乘区 | `applySetBonuses` |
| 4 | 养成修正：天赋、巅峰盘、威能、觉醒、合剂、收藏 → 百分比属性；`tagDamage` → 独立乘区；`executeBonus`、`effectChain` | `rules/deep-progression.ts` `resolveProgressionStats` |
| 5 | 角色乘区：等级精通（加算）、星潮之力 ×6 岛、裂星潮、星核 | `rules/damage-zones.ts` `characterDamageZones` |
| 6 | 生命星晶 | `resolveStats` |
| 7 | 流派连携：主手固有 + 已穿流派威能 | `rules/weapon-combos.ts` `resolveWeaponCombos` |
| 8 | 每个技能：按技能标签折算适用乘区 → `skill.damage` 定值；等级成长；状态预算 | `resolveSkill` |
| 9 | 每个技能：武器盘、召唤石、技能修正（伤害 / 半径 / 冷却 / 消耗 / 拉拽 / 投射物数） | `resolveProgressionSkill` |

**客户端执行**（`packages/simulation/index.ts` `World`，服务端抽查也跑同一份）

`damage()` 中玩家打怪的顺序：

1. 致盲判定 miss；
2. 斩杀加成：技能自带，或 `stats.executeBonus`（阈值固定 20%）；
3. 暴击：只有直接伤害能暴击；
4. 感电 × 连携 `amplify`；
5. 穿透与破甲后过护甲；
6. 扣血；
7. 生命偷取：只对直接伤害；
8. 旧装备开关 `burn` / `chain` / `ward`；
9. 击杀连携；
10. 命中连携。

`hurt()` 中怪打玩家的顺序：

1. 免疫；
2. 致盲；
3. 闪避：只对直接伤害；
4. 护甲；
5. 护盾吸收（带反击状态时按吸收量反击）；
6. 守护天使复活；
7. 扣血。

**关键事实**：所有加成都在服务端折成技能的定值伤害，客户端在命中时只能再判断“目标身上的状态”这一类条件。

| 锤 | 护甲 +1 | 生命 +3% | 护甲 +2 | 范围 | 物理 |

| 法杖 | 能量 +10 | 回复 +1 | 冷却 +3% | 法术 | 持续 |

| 魔杖 | 能量 +10 | 回复 +2 | 冷却 +3% | 闪电 / 奥术 / 传导 | 法术 |

**旧套装 6 套**：狂战士、守护者、元素使、暗影、圣光、迅捷，2/3 件，纯属性。`content/gear-sets.ts`。

### A.6 流派连携（25 条，唯一有触发机制的系统）

Schema：`contracts/weapon-combos.ts`。执行器：`simulation/index.ts` `comboHit` / `comboKill` / `comboCast` / `comboAct`。

| 触发 | 动作 | 条件字段 | 条目 |
|---|---|---|---|
| `nth` 每第 N 次命中 | `nova` | — | 剑气（剑固有） |
| `kill` | `nova` | — | 余震（锤斧固有）、过载（魔杖，目标感电） |
| `nth` + 投射物 | `shards` | `skillKinds` | 裂矢（弓固有） |
| `hit` + 火焰 | `status burn` | `damageTypes` | 引燃（法杖固有） |
| `hit` + 冰霜 + 目标燃烧 / 迟缓 | `nova` | `targetStatus` | 碎冰（法杖固有） |
| `hit` | `status shock` | — | 感电（魔杖固有） |
| `kill` 50% | `shards` | `chance` | 回旋刃（暗器固有） |
| `crit` | `status bleed` / `shards` | — | 血刃、刃舞 |
| `cast` 25–30% | `echo` | `skillKinds` | 残影、连珠、时回 |
| `passive` | `amplify` | 目标状态 | 嗜血、碎骨、弱点、冷热交替、压制、毒理 |
| `hit` | `status armor_down` / `poison` | `skillKinds` | 破甲、淬毒 |
| `hit` 25% | `shards` | — | 分光 |
| `kill` | `refund` / `spread` | — | 战意、野火 |
| `hit` + 闪电，0.5 秒冷却 | `nova` | `damageTypes` | 唤雷 |

- 限制：每帧最多 24 个动作；击杀连锁最多 2 层；连携伤害不再触发命中类连携；回响不再回响；`cooldown`（帧）与 `chance`。
- 局限：
  - 规则必须绑定主手 `weapons`；
  - 技能过滤用 `skill.kind`，不是技能标签；
  - 条件只有伤害类型、技能形态、目标状态三种；
  - 只有 6 种触发、7 种动作。
- 测试：`tests/weapon-combos.test.ts`。
- 表现：`apps/web/src/vfx-profiles.ts` 的 `combo/<规则 id>`。

### A.7 状态（19 种）

来源：`contracts/skill-mechanics.ts`。

| 状态 | 谁会施加 | 执行效果 |
|---|---|---|
| burn 燃烧 / poison 中毒 / bleed 流血 | 技能：毒箭、淬毒针（中毒）、死莲（流血）；连携：引燃、淬毒、血刃；旧装备：burn。**没有任何技能施加燃烧**：燎原只是火焰伤害的持续地面，不挂燃烧状态 | 持续伤害，总预算按间隔均分；**不能暴击、不吸血** |
| shock 感电 | 只有魔杖固有连携；**没有任何技能施加**，雷链、闪电箭也不挂 | 受到玩家伤害 ×(1+强度) |
| slow / stun / silence / petrify / fear / root / blind / time_stop | 控制技能 | 控制；首领持续时间 ×0.35，免疫恐惧、时停 |
| armor_down 破甲 | 战吼、破甲连携 | 护甲 ×(1−强度) |
| attack_up / speed_up / counter / immunity / guardian / regen | 自身技能 | 增益、反击、免疫、复活、回复 |

- **叠层**：实例 ID = 来源 + 目标 + 技能 + 状态种类。同来源同技能只刷新时间；不同技能各自独立计时。读取强度时取最大值。`statusPolicy.maxStacks = 1`。
- 没有冻结、易伤。

- `schedule`：多段，带间隔、是否跟随施法者、移动是否打断；

## C. 通用逻辑拆分

**原则：内容全是数据。**

- 新增一个属性、原子、套装、威能、潮印，只改内容源。
- 只有新增一种触发、条件、动作、状态、技能机制字段时才写代码，而且每种只有一个执行器、一份 schema、一组测试（AGENTS.md）。

```
内容（JSON）
  └─ L8 构筑零件收集：副属性 / 主属性 / 铭纹 / 套装 / 威能 / 潮印 → BuildParts
        └─ 服务端 resolveBuild
              ├─ 静态属性（L1）与类型池、独立乘区（L2 静态部分）→ 折进 skill.damage
              ├─ 条件属性列表（L2 动态部分）→ Stats.conditional
              ├─ 技能补丁（L7）→ resolvedSkills
              └─ 效果规则（L4）→ Stats.rules
  └─ 客户端 World
        ├─ 事件总线（L4 触发） → 条件求值（L3） → 限制 → 动作执行器（L4/L5/L6）
        └─ 战斗事件（带规则 ID）→ 表现与统计（L11）
```

### L1 属性登记表

- **解决**：同一个属性现在要在 6 处各写一遍，加 24 种必然漏。这 6 处是：
  - `affixStatSchema`；
  - `ratioAffixStats`；
  - `set-calculator.ts` 的 switch；
  - `equipment-runtime.ts` 的 `setStats` 和 `labels`；
  - `modifierSchema`；
  - `resolveProgressionStats` 的键表。
- **做**：新建 `packages/content/stats.json` + `contracts/stats.ts`，一行一个属性：

  | 字段 | 含义 |
  |---|---|
  | `id`、`name` | |
  | `unit` | `ratio`、`flat`、`seconds` |
  | `pool` | `base`、`type`、`cond`、`vuln`、`defense`、`resource`、`status`、`skill` |
  | `tag` | 类型池用 |
  | `cond` | 条件池用，引用 L3 |
  | `cap` | |
  | `stageScaled` | 是否随物品阶段放大，修 A.11-4 |
  | `slots` | 可出现部位 |
  | `display` | 显示格式 |

- **替换**：
  - 上面 6 处全部改成读登记表；
  - `applyAffixBonuses` 的 switch 改成按 `pool` 分派的一个函数；
  - 套装、威能、潮印的属性加成走同一个函数。
- **测试**：
  - 每个属性：生成 → 解析 → 显示，往返一致；
  - 旧装备解析结果与改前逐字段相等（存档回归样例）。

### L2 伤害分池（静态 / 动态）

- **静态部分（服务端）**：`DamageZone` 加 `pool: 'type' | 'mult'`；`foldZones` 返回 `(1+Σtype) × Πmult`，仍折进 `skill.damage`。行为与现在一致，只是多了池的概念。
- **动态部分（客户端）**：条件池、易伤池只能在命中时知道。服务端把它们解析成数值列表，放进 `Stats.conditional: {id, pool:'cond'|'stat', stat?, value, when: Condition}[]`。客户端 `damage()` 在暴击之后加一步：
  - `× (1 + Σ 命中条件的 cond 值)`；
  - `× (1 + (感电 + 易伤) × (1 + 易伤效果))`。

  现有感电乘数并进易伤池。
- `pool:'stat'` 用于条件属性，例如“对精英吸血 ×2”“静止时暴击率 +15%”：同一机制，在用到该属性的地方查一次。
- **测试**：同构筑、同种子，条件全不满足时，伤害与改前完全一致。

### L3 条件求值

- **做**：一个纯函数 `matches(cond, ctx)`，放在 `packages/simulation/conditions.ts`。条件池、效果规则、`amplify` 都只调它。
- `ctx` 包含三部分：
  - 来源技能：标签、武器、伤害类型、是否最长冷却；
  - 目标：状态及层数、档位、生命比例、距离、周围敌人数；
  - 自身：生命比例、护盾、移动 / 静止时长、能量比例、增益。
- **首批条件种类**：

  | 条件 | 说明 |
  |---|---|
  | `skill` | 标签 / 武器 / 伤害类型 |
  | `target_status` | 可带最少层数 |
  | `target_rank` | 普通 / 精英 / 首领 |
  | `target_hp` | |
  | `self_hp` | |
  | `distance` | |
  | `crowd` | 返回数量，供“每个 +x%”使用 |
  | `self_state` | 护盾、移动、静止 N 秒、能量 ≥ x、带某增益 |
  | `combat_time` | 开战 N 秒内 |

- 所有条件可以组合 `all` / `any` / `not`。
- R3 实施扩展（交接 §5.1）：`cast_hits` 比较本次施放已实际命中的不同目标数，用于震波的“命中至少4敌”；与周围敌人数 `crowd` 分开，记录随战斗检查点保存。
- **测试**：每种条件一张真值表样例，客户端与服务端共用（AGENTS.md“共享样例校验”）。

### L4 效果规则引擎（连携泛化）

- **规则形状**：`EffectRule = {id, source, tier, trigger, filter, when[], chance, icd, stacks?, action, scale[]}`，由 `comboRuleSchema` 扩展。
  - `weapons` 改为可选过滤，空表示任意主手；
  - `skillKinds` 保留，新增 `tags`。
- **触发总线**：每种触发只在 `World` 里埋一个点。

  | 触发 | 埋点 |
  |---|---|
  | `hit` `crit` `kill` `nth` | `damage()`（现有） |
  | `kill_elite` | `damage()` 击杀分支 |
  | `cast` `dash` | `cast()` |
  | `status_apply` | `applyStatus()` |
  | `hurt` `dodge` `block` `shield_break` `shield_gain` `low_hp` `lethal` | `hurt()` 与护盾写入点 |
  | `interval` `combat_start` `moved` `mana_empty` `mana_spent` | `step()` 与能量扣除点 |
  | `zone_end` | 区域结束 |

  `nth` 加 `count: 'hit' | 'crit' | 'cast' | 'kill'`。
- **动作注册表**：`action.type → 执行器`，一个类型一个函数。

  | 动作 | 新 / 改 | 说明 |
  |---|---|---|
  | `nova` `shards` `status` `spread` `echo` `refund` `amplify` | 改 | 伤害基数加 `ref: 'hit' \| 'shield' \| 'armor' \| 'maxHp' \| 'attack'`；`nova` 加 `at: 'target' \| 'self'`；`spread` 允许 `hit` 触发；`echo` 加 `skill: 'same' \| 'slot1'`、`retarget` 条件 |
  | `buff` | 新 | 交给 L6 |
  | `shield` / `heal` / `mana` | 新 | 交给 L6 |
  | `cooldown` | 新 | 减 N 秒 / 重置当前 / 重置全部 / 重置随机 1 个 |
  | `field` | 新 | 生成地面区域，复用现有 `zones` 执行 |
  | `detonate` | 新 | 立即结算目标身上指定持续伤害剩余的 x%，可选移除 |
  | `extend` | 新 | 延长自身增益或目标状态 N 秒，有上限 |
  | `reduce` | 新 | 受到伤害 ×(1−x)，用于防御类被动 |
  | `arc` | 新 | 传导 N 跳，复用旧 `chain` 开关的找目标逻辑 |

- **限制（沿用并补全）**：
  - 每帧 24 个动作；击杀连锁 2 层；衍生伤害不触发命中类；回响不回响；
  - 非 `passive` 规则必须有 `chance` 或 `icd`；
  - 同一原子 ID 多来源取最高档。
- **迁移**：25 条连携改成 25 条规则数据，行为不变；`tests/weapon-combos.test.ts` 全部保留。
- **测试**：
  - 每种触发一个埋点测试；
  - 每种动作一个执行器测试；
  - 一次压力测试：全原子同时生效，10 分钟内每帧动作数 ≤ 24。

### L5 状态扩展

- **叠层**：状态定义加 `maxStacks`、`stackMode: 'refresh' | 'independent'`。`strength()` 按叠层模式求值：独立计时时求和，刷新时取最大，上限由定义给出。现有状态默认 `maxStacks=1`，行为不变。
- **新状态**：
  - `freeze`：不能行动，受到非冰霜伤害解除；首领改为迟缓。
  - `vulnerable`：进 L2 易伤池。
- **阈值转换**：状态定义加 `onStacks: {at, convert:'freeze'|…, consume}`，例如“冰缓叠 3 次冻结”。
- **持续伤害权限**：`damagePermissions.periodic.crit` 改为可由规则开启（`dotCrit` 属性，暴击率减半），默认关闭。
- **测试**：叠层上限、独立计时、阈值转换、首领规则；改前的 19 种状态回归。

### L6 自身临时状态

- **做**：玩家身上一个统一的 `selfBuffs` 列表，每项包含：

  | 字段 | 含义 |
  |---|---|
  | `id`、`source` | |
  | `ends` | 结束时刻 |
  | `stacks` | 层数，有上限 |
  | `mods` | 属性或条件池增量 |
  | `consume` | `nextCast` / `nextMelee` / `nextHit`，用完即消耗 |
  | `flags` | 必定暴击、本次免消耗等 |

- **计数器**：移动距离、静止时长、窗口内击杀数、累计消耗能量。由 `step()` 统一维护，供 L3 条件和 L4 `moved` / `mana_spent` 触发使用。
- **护盾与恢复**：护盾、治疗、回灵都走现有 `hero.shield`、`restoreResources`；护盾写入点发 `shield_gain`，护盾归零发 `shield_break`。
- **复用**：`lethal` 触发 + 现有 `guardian` 复活逻辑实现“不屈”类效果，不另写。
- **测试**：每种 `consume` 与每个计数器一个样例；断线恢复时 `selfBuffs` 随战斗快照保存（`heroFields` 加入）。

- 2026-10-06 L6 自然延伸：`buff.currentCast` 仅在明确声明时把临时 `projectiles` 增量施加于当次成功施放并立即消费；其他 nextCast 语义不变。增弹为非负整数，参数与旧弹体通道统一支持至15枚，组合7弹有总预算/实际发射测试。L5可叠层与转化计数按角色、状态类型、技能/规则来源隔离，避免技能原生迟缓抢占寒蚀的三次计数。

### L7 技能补丁与新机制字段

- **参数补丁（不写新执行器）**：`SkillPatch = {skills | tags, ops: [{path, op:'set'|'add'|'mul'|'append', value}]}`。
  - `path` 白名单：`radius`、`range`、`pull`、`projectiles`、`projectileSpread`、`cooldown`、`cost`、`mechanics.schedule`、`mechanics.projectile.penetrations`、`mechanics.statuses`、`mechanics.damageType`（改伤害类型后重新推导标签）、`mechanics.zone.*`、`mechanics.execute`。
  - 服务端在 `resolveProgressionSkill` 里应用，客户端执行的仍是普通技能。
  - 2026-10-06 按交接 §5.1 补充既有字段 `weapons` 的参数补丁：明确威能可改变该技能的武器许可，原始绑定保持；SkillAccess 和技能装备校验读取补丁后许可。用于风暴回旋允许锤/斧施放旋风斩，完成主文震地旋风的真实 4+2 装配。白名单、共享武器 schema、战斗执行器与定向测试必须共同覆盖。
- **新机制字段（各需执行器）**：只加以下 6 个，每个都对所有技能通用。

  | 字段 | 行为 | 用到它的内容 |
  |---|---|---|
  | `projectile.returns` | 到达终点后返回，返回途中可再次命中 | 回旋箭、潮印 |
  | `projectile.orbit` | 绕施法者旋转 N 秒 | 环刃、潮印·星环 |
  | `zone.followCaster` | 地面区域跟随施法者 | 随行箭雨 |
  | `dash.pathHit` | 位移路径上的敌人受到伤害与状态 | 裂空、火径原子 |
  | `schedule.advance` | 多段技能每段向前推进 N 格 | 地裂 |
  | `chain.count` | 传导目标数（现写死 3） | 回弹雷链、传导类原子 |

- `skill.charges`（位移多次充能）作为第 7 个字段，只在 E6 做。
- **测试**：补丁按白名单校验，非法路径报错；每个新字段做释放、命中、表现三项验收（AGENTS.md 技能落地规则）。

### L8 构筑零件收集

- **做**：`collectBuildParts(s, run?) → {stats[], conditional[], zones[], rules[], patches[], overrides[]}`，所有来源走同一个入口：
  - 副属性、主属性、铭纹、套装、威能、天赋、潮印；
  - 旧来源：旧套装、旧威能、旧效果开关，作为“旧版”零件。
- **档位缩放**：零件引用原子时带 `tier`；按原子声明的 `scale` 字段乘档位系数，只在这里做一次。
- **去重**：同一原子 ID 取最高档。威能“同族取最高法典等级”的规则也搬到这里。
- **改写**：`overrides = [{target: 原子 ID | 套装 ID | '*', set / mul: {...}}]`，用于潮印“套装共鸣”“连携无限”这类改别的零件参数的效果。
- **套装计数**：按套装身份（谱系 × 系列）计数，造型阶段只决定数值（按最低阶段）；“全套共鸣”通过改写计数实现。
- **测试**：
  - 同一角色改前 / 改后 `resolveBuild` 一致，旧套装除外（套装身份规则切换按 `ruleset_version`）；
  - 去重与档位样例。

### L9 局内修正（潮印）

- **做**：
  - 副本实例状态加 `augments: {offered[], chosen[], rerollsLeft}`；
  - 选项由实例种子生成；
  - 选择是带 `command_id` 的副本命令；
  - 选择后服务端用 L8 把潮印并入冻结构筑，带 `build` 版本号下发；
  - 客户端在下一次同步时替换参数，保留生命、冷却、状态（AGENTS.md 副本恢复规则）。
- **配置**：开关、次数、档位表写在 `dungeons.json` 的默认 / 模板 / 逐副本覆盖里。
- 局内修正只存在实例里，不进存档。
- **测试**：
  - 断线重连保留已选和待选；
  - 重复命令幂等；
  - 选择后的构筑与服务端解析一致。

### L10 防作弊上界

- `minimumClearMs` 给 `World` 一个 `upperBound` 模式：
  - 所有 `chance` 视为 1；
  - 所有条件视为满足（仍受 `icd` 和每帧预算约束）；
  - 暴击率 100%。
- 新增触发、动作上线时，必须同时让上界模式覆盖；没覆盖的规则在抽查里**跳过该次检查**，不判违规（宁漏不错）。
- **测试**：带满特效的构筑合法清场 100 次，误判 0 次。

### L11 表现与统计

- 规则触发事件统一为 `effect_triggered {ruleId, source, action, amount}`；表现按 `vfxKey` 登记表取。缺登记的规则在内容校验时报错，不允许运行时无表现。
- 先从现成特效库检索复用。
- 战斗统计按 `ruleId` 累计次数与伤害，供“伤害构成”面板与平衡模拟使用。

### L12 内容校验

`pnpm content:check`（或并入现有校验）检查：

1. 每个属性、条件、触发、动作、状态、机制字段都有登记和执行器；内容里出现未登记类型即失败。
2. 每个原子的触发与动作组合合法，沿用并扩展现有 `need` 表。
3. 每个规则都有 `vfxKey` 登记。
4. 威能、潮印引用的技能 ID、套装 ID、原子 ID 都存在。
5. 补丁路径在白名单内。
