# 宠物建模需求（PA1，2026-10-17）

状态：美术先行。宠物玩法定位（连携技、共鸣位、数值预算）和商业化方向（外观付费还是数值付费）**都还没定**。这一批只做两件事：
- 与玩法无关、无论走哪个方向都要用的模型资源；
- 按现有怪物管线出可运行的帧图集。

不做跟随 AI、连携规则、数值、界面和付费。

## 1. 设计目的
- 宠物跟在主角身边，是「第 5 个技能来源」（连携技）和「共鸣位」被动的载体。它不是主力输出，画面上不能抢主角。
- 每座岛有一只本地宠物，用来接上「远航 + 发现」的主循环。
- 每只宠物都要能「长大」：成长形态的变化要看得见。
- 外观变体要能直接换皮。之后无论外观是付费还是靠玩法获得，资源都不用重做。

## 2. 素材来源（已盘点）
**主来源**是工程外层的 `G:/webgame/abyss-walker-migration/spine源文件_召唤与合成Q版spine动画源文件欧美风格小怪物素材819套/`。这个库项目里还没用过。

库的结构：
- 目录名是 `guai<系列><编号><阶段>`。系列有 A/B/C/D/S，共 50 个家族；每个家族有 a–e 五阶，体型逐阶变大、配色也变。
- 另有 `ds`/`es` 变体和 `_1`/`_2` 版本目录。
- 每个目录里有：`.json` 骨骼、`.atlas` + 零件图（**是零件图集，不是成品预览**）、`.spine` 工程文件、`pic/` 原始零件。

## 3. 数量
第一批 6 只，每座岛 1 只：

| 岛 | 主题（地图描述） | 色面方向 | 初选家族 |
|---|---|---|---|
| 风栖岛 | 草坡、船台、风向布 | 米褐、青蓝、奶白 | D1 或 C8 |
| 雾铃岛 | 林冠、溪谷、邮站 | 苔绿、雾白 | D3 |
| 赤炉岛 | 工坊、管线、炉火 | 铜灰、橙红 | 候选池里挑火/机械系 |
| 霜镜岛 | 冻舰、观测站、冰岩 | 白蓝、银蓝 | A15 |
| 龙眠岛 | 米金龙骨、旧航网 | 米金、青蓝 | A7 |
| 沉星岛 | 界隙、难民区 | 灰紫、星点 | S12 |

每只宠物要交付：
- **3 个成长形态**：幼年、成年、觉醒，默认取该家族的 a / c / e 三阶。
- **2 个外观变体**：默认用 b / d 两阶的配色，换皮后保持幼年的体型。是否付费不在本批决定。
- 总计 6 × 3 = 18 个形态，加 12 个变体。

**先做 1 只样板**（风栖），全套过自检后再铺开另外 5 只，中途不用等人确认（§7）。

## 4. 规格
**显示高度**：实机主角约 100px（头顶血条在 −104），NPC 100、普通怪 80。

| 形态 | 显示高度 |
|---|---|
| 幼年 | **44px** |
| 成年 | **56px** |
| 觉醒 | **68px** |

- 任何动作的最大边界不超过主角高度的 75%。
- 脚底固定，用实际像素边界缩放，不按透明画布高度。

**导出格式**：按现有怪物管线 `assets/starsea/monsters/export.mjs` 的格式，导出 atlas 帧图集。
- 30 fps，单格 256，`actor.png` + `actor.json` + `sockets.json`；
- 记录 `displayHeight`、`anchor`、`nativeFacing`、`referenceHeight`、`displayBounds`；
- 每个动作写 `provenance: complete original native animation`。

**画风对齐**：项目.md 与 `docs/world-art-unification.md` 的「圆润头身、简化五官、柔和深色描边、手绘色面」。
- 库名写的是「欧美风格」，凡是写实、恐怖、持武器的人形、带血肉的家族，一律排除。
- 岛屿配色用 Spine 原生的槽位颜色（slot color / 双色 tint），不重画贴图。
- 只有可拆的小挂件（项圈、徽记）可以用 imagegen 新画，方式同 `ss-mon-dusk-blade` 的 dusk-clasp：透明底、无外发光，记录原始路径和 sha256。

**来源登记**：每个形态都要写清原始绝对路径、sha256、Spine 版本、所用阶段、调色参数和挂件来源。

## 5. 动作清单

| 运行时动作 | 来源 | 必需 | 说明 |
|---|---|---|---|
| `idle` | `std` | ✅ | 循环 |
| `idle2` | `std2` | ✅ | 城镇和宠物页里的休闲动作，循环或单次按原动作 |
| `move` | `walk` | ✅ | 跟随主角用。要验证播放速度放到 1.6 倍时脚底仍稳定，记下合适的倍率范围 |
| `attack` | `atk` | ✅ | 原样导出，留给普通协攻 |
| `knock` | `jifei` | ✅ | 原样导出，留给演出；宠物是否会受击未定 |
| `skill` | `skill` | 有就导 | 只在部分变体里有，没有就在清单里写「无」 |

不做：
- **连携技动作不做**。连携的姿态和节奏由 Claude 亲手做，本批只保证骨骼完整、动作原样导出、骨骼和槽位名单写进 manifest。
- **出场、收回、抚摸**：库里没有这些动作。**禁止用两张静态姿态拼、或平移单图冒充动作**，在清单里记成「程序演出，待做」。

## 6. 挂点（sockets.json，每个动作逐帧）
- `ground`：脚底，用于深度排序和阴影。
- `body`：身体中心和受击点。
- `head`：头顶，挂名字和表情气泡。
- `emit`：嘴、手或发射点，连携技的特效从这里出。没有明显嘴部的家族取正面中心偏上，并写明。
- `accessory`：挂件点，项圈或背部，换外观挂件用。记录绑定的骨骼名。
- 左右镜像后挂点位置正确。三个形态的挂点比例要一致，换形态时特效不跳位。

## 7. 执行方式（强制）
- 一次做完全部：
  1. 拼装渲染候选池；
  2. 定 6 只；
  3. 做样板；
  4. 铺开剩下 5 只；
  5. 自检；
  6. 写报告。
- 每完成一步就更新进度文件 `assets/starsea/pets/progress.md`，中断后从进度文件续做。
- 遇到能按 §8 裁定的情况，按裁定继续，并记进 `assets/starsea/pets/decisions.md`。不要停下来问。
- 只有两种结束状态：**全部完成**；或**其余全部做完后**，被 §9 的硬阻塞卡住。

## 8. 默认裁定
| 情况 | 裁定 |
|---|---|
| 3.5 版家族看起来更合适 | 本批不用。写进 decisions.md 的「下批候选」 |
| 初选家族拼装后发现不合画风或不合主题 | 从 17 个候选家族里换一个，记原因 |
| 两岛想用同一家族 | 不允许，每岛家族不同 |
| a / c / e 三阶的外形差异太小 | 改用 a / d / e 或 b / d / e，只要三阶体型逐级变大、成长看得出来 |
| b / d 的配色和本岛色面冲突 | 外观变体照原配色导出（它们本来就是另一种皮），只有正式形态按岛调色 |
| 某阶缺 `std2` 或 `jifei` | 清单里写「无」，不补、不拿别的动作顶替 |
| 原动作有大位移（攻击时冲出去） | 原样导出，在 sockets 里记位移量，不裁切动作 |
| 原动作带特效零件（光、火） | 保留在动作里，但在清单里标「含内置特效」，方便之后决定要不要拆开 |

## 9. 硬阻塞（只有这些可以停）
- 3.6 运行时加载候选家族时，渲染结果和原图零件明显对不上（缺件、错位），而且换家族也解决不了；
- 候选池里能用的家族不到 6 个；
- 需要改 `packages/asset-manifest`、`apps/web/src`、`contracts` 版本或数据库才能继续。

## 10. 文件权限与禁止
- 只写 `assets/starsea/pets/` 和 `apps/web/public/art/starsea/pets/`。局部 manifest 是 `assets/starsea/pets/manifest.json`，字段契约同 `docs/starsea/requirements.json` 的 `manifestContract`，`type` 填 `pet`。
- 导出脚本、预览页、证据都放在组目录里。
- 不改公共 manifest、游戏源码、规则、数值、版本号，不重启服务，不碰 8612 和 8790。
- **不跑无头浏览器**。
  - 现有 `monsters/export.mjs` 用的是无头 + swiftshader，非常吃 CPU。导出要改用可视 Chrome（`headless:false`，硬件 GL），一次只导一只，串行执行。
  - 预览检查也用可视浏览器。
- 原始渲染明细、大图只留在本地 `assets/starsea/pets/evidence/`，进度和报告只写结论（≤200KB）。
- 禁止：只交文档、删减数量、占位图、用静态图冒充动作、跳过自检。

## 11. 自检与交付
- **候选池拼装渲染总表**：17 个家族 × 五阶，用 `idle` 第 0 帧拼装出完整形象（不是零件图），附在报告里，说明每只为什么选或不选。
- **每个形态的自检**：
  - 全部帧都在格子内；
  - 跟随移动时脚底不滑；
  - 镜像正确；
  - 三形态逐级变大，且不超过 §4 的上限；
  - 5 个挂点每个动作都有；
  - 来源和 sha256 齐全。
- **并排预览页**：组目录下的可视预览页，主角（读现有主角运行资源）和 6 只宠物的三形态站在一起。可以切换 `idle` / `idle2` / `move` / `attack` / `knock`，也可以切换外观变体。截图存 evidence。
- **报告 `assets/starsea/pets/report.md`**：最终 6 只的家族和阶段对应表、动作齐全表、未覆盖项（出场、收回、抚摸、连携动作）、已知限制。
