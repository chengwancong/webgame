# 全界面统一规范审计（2026-10-25）

规范：[`docs/ui-uniform-spec-20261025.md`](../../ui-uniform-spec-20261025.md)。
方法：
- 本地 1280×720，在 agent 内置浏览器（非无头 GUI）里执行。
- 测量脚本 `tools/ui-uniform-probe.js` 跑了三块：
  - 静态验收页：U0/U4–U6 共 56 个样例、hub-review 主城面板 16 态、方向 A 结算 3 态。
  - 真实游戏：新测试角色 `uiaudit1025` 走 登录 → 建角 → 开场 → 港口 → 9 个菜单入口及其页签 → 人物 → 背包装备与候选 → 仓库 → 首个剧情节点的战斗 HUD。
  - 对重点界面截图目检（截图只留本地）。
- 另跑 `node tools/audit-ui-system.mjs`：剩余直接颜色 25 处、裸字号 5 处。

## 总体结论

- 公共件接入面已经很广：一屏一个主按钮、面板不越出舞台、正文 ≥13px、Esc 关闭等测量项，**绝大多数界面通过**。
- 问题集中在三类：
  1. 主城（HUB）这批新面板和老窗口的**标题样式**是两套。
  2. 若干**文案和数据呈现**违反"同一信息只写一次 / 零值隐藏 / 不露内部 ID"。
  3. 零散的**小字号**和**禁用无原因**。

## 问题清单与改法

| 编号 | 级别 | 规范 | 现象 | 改法 |
|---|---|---|---|---|
| UF-01 | 高 | UX-08 | 副本里剧情行显示内部 ID：「ss-npc-milo：巡猎兽被航钥的光引来了…」 | `story-controller.ts` 的 `frame.speaker` 过 `starseaSpeaker()`；全仓搜同类，凡是渲染 speaker 的地方统一走这个函数 |
| UF-02 | 高 | UI-04 | 航图、今日、委托板、港口建设、宠物用 `iconHtml` 小图标标题；老窗口用 `emblemHtml` 缎带徽记标题。两套并存 | HUB 面板统一改用 `emblemHtml`，图标与右下菜单同源（`hudMenuIcon`）；没有菜单图标的用现有 seal 图标 |
| UF-03 | 中 | UI-02 | 宠物角色胶囊 10px；战棋指令状态、名牌 10–11px；工坊品质标签 11.7px（`.65em`）；结算 `.7em` | 全部改为 `--font-size-micro`（12px）及以上；em 相对字号改成 Token |
