2026-09-29。这份记录只写已经核对过的事实，不写完成百分比，也不把静态检查说成目视通过。

## 这次实际改了什么

- 面板标题在页面内容确定之后生成，并用转义函数写入。登录、创建、接管这三页仍用各自的标题，不走这套空标题路径。
- 小地图外框改为 `width: max-content`，画布 140×140，圆形裁切。四种视口下测量到画布矩形落在外框内，页面没有横向溢出。
- Esc 先关分解确认，再关面板。关闭后面板让出焦点的时机改到 HUD 更新之后，并用 `data-action`、`data-id`、`aria-label` 找回入口，不再保存会失效的 DOM 节点。
- 行囊改为三列：左侧角色立绘和四个部位，中间 24 格，右侧大图、名称、部位、属性变化、特效得失、操作条件和主次按钮。分解仍是次按钮。装备没有品质字段，界面写明「品质未分级」，没有编造稀有度。服务端预览请求在这次浏览器里返回 200。
- 构筑保留勾选框 `name="skill"`，并分成顺序、技能库、详情和保存区。保存区有草稿、保存中、已一致、失败四段文案。
- 自动设置把「拾取筛选」和「低生命停止」标成缺项。
- 按钮、面板、槽位、进度条改由样式绘制，不再用旧的平涂按钮图。主按钮实测为杏金底 `rgb(255, 182, 92)`、深色字 `rgb(26, 18, 8)`。
- 技能图标、角色立绘、装备图标和系统入口图标从 `assets/ui-source/v2` 发布到 `/art/ui-v2/`。游戏和展示页都从 `packages/asset-manifest/ui.v2.json` 取路径。
- `tools/build_ui_v2.py` 先校验再写入临时目录，失败时不替换上一版。`--self-test` 覆盖缺图、尺寸不符、坏图，三次都非零退出且清单哈希不变。正式 `build` 会先跑这个脚本。展示页已进入 Vite 入口。
- 展示页有黑、白、灰、深蓝、场景色五块底，复选框带名称、`role="checkbox"` 和 `aria-checked`，格子响应方向键。场景色用的是游戏清屏色，不是一张实机战场截图。

浏览器自动化仍使用原来的按钮名：背包、构筑、自动设置、出发远行、前往结界、进入试炼、回城、设置、退出账号、登录远行、创建账号、进入营地、保存构筑、恢复连接，以及装备名按钮、技能勾选框和待领取页签。

## 没有做到的目视结论

当前模型不能读取 PNG，换一个子任务后仍然不能看图。因此不能声称已经用视觉对照过四张标准图，也不能声称画面已经达到标准图。上面的浏览器结果是标题、外框、溢出、按钮色、请求状态和页面错误，不是目视验收。

已知和标准图的实现差距：

- 8 个技能图标裁自构筑标准图，另外 4 个（冰环、破阵、裂地、星矛）和角色立绘来自生成图。立绘已去掉棋盘格背景和右下角水印分量，但没有再目视确认边缘。
- 六件装备图标是按色板新画的，不是从行囊标准图挖出来的。
- 面板和按钮是样式，不是标准图里的控件原图。
