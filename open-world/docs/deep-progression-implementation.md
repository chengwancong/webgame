# 深度养成系统：实现与研发说明

2026-10-01。本机版本：客户端 `0.5.0`，协议 `6`，规则 `ow-7`，数据库 `8`。设计依据为 [深度养成系统设计](deep-progression-system.md)；本文记录实际运行行为。美术与排版遵循根目录 `项目.md`。

营地 HUD 的「养成」入口集中提供武器盘、威能法典、三系天赋、巅峰雕文、召唤石、突破觉醒、声望专业、挑战赛季。原有背包、技能和远行保持现有结构。详情显示服务端报价、持有量、材料来源、未满足条件与属性预览；正式动作仍会重新校验。

## 已运行的成长循环

| 模块 | 实际行为与来源 |
| --- | --- |
| 武器盘 | 主手和八把副武器；主手提供本体属性，副武器只提供技能乘区；同一实例不可占多个位置。普通加算、方阵乘算和上限由配置控制。 |
| 武器成长 | Lv1–150、★0–5；到达当前等级上限后，以同种未装备、未锁定武器及材料突破。旧装备强化继续保留。 |
| 威能 | 120 项法典内容；传奇装备有自身 `aspectId`，只能萃取该威能。法典永久保存并可反复付费刻印，同类通用威能取最高等级。龙骨首领提供神话威能来源。 |
| 三系天赋 | 每系 30 节点，主、副专精及前置层投入校验。战士斩杀、法师连锁、游侠分裂具有实际战斗执行。等级与声望奖励提供天赋点，允许付费重置。 |
| 巅峰雕文 | 50 级开启独立巅峰经验，成长阈值为 `600 + 巅峰等级 × 100`，不依赖角色继续升级。四盘共 48 节点，雕文 Lv1–21，插槽按距离提升邻近节点。全盘之后可继续积累等级与点数。 |
| 召唤石 | 六域首领解锁六种召唤石，以碎片唤醒、升级和突破。主加护与半效友方加护生效，同一石不能占两槽。 |
| 角色和技能觉醒 | 角色五星突破逐步开放 50→100 级上限，觉醒 Lv1–10，各层三选一。满级技能可以选择强攻、疾速或扩散分支。 |
| 声望专业 | 六域声望五阶，战斗及上交材料推动进度。采集、制造各选一门，等级 1–300；战斗补充最多 30 次采集行动，八个配方提供装备、合剂和成长材料。收集目标按所选专业计算，保持可达。 |
| 高难与噩梦 | 六个高难首领，每日共享三次；噩梦 1–100 层，每日五次，必须逐层通关，词缀实际修改生命、攻击、冷却或回复。高难固定提供方阵装备；背包满时转换为额外方阵碎片。 |
| 团队副本 | 真实玩家创建、加入、准备、离队；20 人、2 坦克/4 治疗/14 输出，队长启动。八或十二阶段，检查每位队员的构筑版本与周次数，并逐人记录奖励、回执和流水。 |
| 赛季与收集 | 当前赛季 2026-10-01 至 2027-01-01，常规击杀与挑战推进免费进度。奖励只领取一次；噩梦排行榜按赛季取每位玩家最佳成绩。法典、首领和专业收集奖励可领取。 |

普通野外掉落仍限原来的六种装备定义。方阵、神话定义用于服务端属性解析和专属获取，不会因扩充装备表而混入草原普通掉落池。

暴击、暴伤、吸血、冷却缩减、闪避、守卫穿透与低血斩杀由战斗核心实际执行。专属旋风的拖拽经过墙体及单位碰撞处理；多箭为独立扇形投射物，沿整段路径判定。服务端先解析持久构筑，战斗核心仅消费结果，不再次计算武器盘与成长。

启动和内容检查会解析配置 schema，检查重复 ID、引用、递增曲线、材料、区域、配方产物、技能和巅峰依赖。配置修改后本机托管服务会自动重载；正式更新须修改相应规则版本，并重签战斗授权。

## 状态、存档与接口

持久成长保存于角色 `progression`，挑战周期与最近结果保存于 `challengeProgress`。页面草稿独立于角色镜像。迁移 8 为增量迁移：保留账号、金币灵石、装备实例、已领取奖励、技能投资和历史回执；补充成长初值及旧传奇装备的自身威能。

| 接口 | 行为 |
| --- | --- |
| `GET /api/progression` | 模块目录、状态、材料持有/来源和逐项服务端操作报价。 |
| `POST /api/progression/preview` | `{revision, action}`；不需要控制租约，不写数据库。 |
| `POST /api/progression/action` | `{command_id, revision, lease_id, action}`；重新核验并提交。 |
| `GET /api/challenges` | 开放条件、剩余次数、赛季、队伍和排行榜。 |
| `POST /api/challenges/run` | 通用写操作字段和 `challenge_id/tier`；由服务端实际战斗计算胜负。 |
| `POST /api/challenges/season-claim` | 通用写操作字段和 `reward_id`，原子领取免费奖励。 |
| `POST /api/raids/{create,join,ready,leave,start}` | 真实队伍生命周期及全员结算。 |

每个写操作自首版接入 `command_id` 幂等、revision 和控制租约。同 ID 同内容返回原回执，不再次扣费；同 ID 不同内容拒绝。失败时事务完整回滚。普通战斗授权保存私有养成奖励快照，未揭示的掉落候选与随机状态不进入客户端。

装备、武器盘和萃取共用实例保护。构筑变化更新 build；玩家旧战斗报告无法使用新构筑结算。未知响应使用严格契约拒绝；响应丢失保留 outbox，恢复先查原回执。已确认成长但战斗授权更新失败时，界面明确显示已保存、待同步。

团本当前采用「共享前线」自动战斗：汇总实际玩家解析后的攻击技能、坦克生命/防御与治疗技能，复用真实 World 核心执行连续阶段。它是协作自动战斗模型，尚未提供 20 个独立角色的实时移动、语音或手动战术指令。当前提供免费赛季奖励；付费通行证、交易市场和坐骑展示未在本次接入外部平台或新增专用功能。

## 验收和调参

```powershell
node tools/verify-deep-progression.mjs
node --import tsx tools/balance-deep-progression.ts
node tools/accept-deep-progression.mjs
node --import tsx tools/verify-progression-service.mjs
```

工程入口提供隔离的真实 PostgreSQL，不用 mock 代替事务验证，结束后停止并清理测试库。证据目录为 `../docs/reviews/open-world/deep-progression-20261001/`，包含工程检查、浏览器操作、实际截图、本机服务核对和数值模拟。

首轮完整回归 18 个测试文件、140 个测试通过，覆盖已有装备、技能、战斗碰撞、登录、奖励与新增成长。随后真实通关路径发现升级后授权滚动周期的客户端游标不同步，已统一授权切换并增加 4 个回归测试；再增加分裂不影响回复/护盾及图鉴长线去重测试，最终为 19 文件、146 测试全部通过。新增测试覆盖幂等并发、竞态版本、错误回滚、迁移、真实材料奖励、周期次数、失败零奖励、噩梦跳层限制，以及 20 个独立账号的团本结算。

`apps/web/src/combat-permit.ts` 在升级、持久构筑操作和心跳续期时统一采用服务端授权的敌人周期、战斗时钟、报告序号、起点与 build，保留玩家生命、能量、剩余冷却和步行意图。避免已经击败首领后仍以旧周期报告而无法回城；不放宽服务端顺序或构筑校验。

浏览器验收在 1280×720、1024×576、1600×900、1920×1080 和 375px 窄屏连续选择长短条目，实测图标、边框、内边距、滚动偏移和焦点；并验证真实成长命令、忙碌防重复、刷新恢复、报价失败重试、响应丢失以及并发版本拒绝后的恢复。

仓库综合 QA 入口 `node tools/qa.mjs` 额外执行真实三域战斗、首领解锁与击败、退出重登、100 会话容量、Windows PostgreSQL 备份恢复、桌面启动及渲染压力。它使用固定 8611 端口；本机托管服务开启时按停止服务→执行 QA→恢复服务运行。备份检查使用一致的导出数据库快照，核对 12 张表完整行数与 SHA256，包含成长存档、挑战、队伍、历史回执、奖励及流水。实际结论以 `../docs/reviews/open-world/qa-result.json` 为准。

完整综合 QA 全绿的证据另存 `qa-full-before-discovery.json`：145 测试、真实前三首领、回执恢复、完整存档重登、100 会话/1000 报告/零失败、12 表备份恢复、真实 Electron 启动，原生 Chrome 渲染 P95 为 17.88ms（目标 20ms）。随后唯一业务变化为图鉴记录按固定怪物模板去重，防止刷怪周期无限增加角色与回执体积；旧周期 ID 在正常读取/写入时归并，金币、材料、击杀和首领进度不重置。该变更由最新 `engineering-result.json` 的 146 个完整回归，以及 `discovery-service-result.json` 的真实常驻服务验证覆盖；综合渲染数值属于去重前冻结源码的实测，不冒充不同源码的全流程重跑。

数值报告使用相同 Lv50、技能等级和主装备的四套受控构筑；成熟盘武器 Lv150/五星，使用种子 11/41/97。36 场真实自动战斗均有限结束；混合方阵盘旋风伤害 12806、普通盘 706，约 18.14 倍。方阵攻击/技能倍率保持配置的 32/27 上限。该小样本验证公式与相对强度，不证明设计稿中的 10/30/50 小时资源获取节奏，也不证明长时玩家留存或全面职业平衡。后续调参应同时观察材料日收入、突破重复武器需求、失败率、战斗时长与不同构筑的优势。
