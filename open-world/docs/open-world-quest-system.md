# 开放世界任务系统改造（引导 + 支线，取消严格主线）

> 2026-10-06 用户裁定：开放世界中**只有引导任务和支线任务，没有严格的主线任务**；随后选定方案 **A**：剧情含义与已确认对白不动，每座岛的任务链拆成“登岛 → 并行线索 → 汇合 → 首领”，取消跨岛强制顺序，目标尽量认世界事实，补写少量过渡对白。
>
> 本文覆盖 [内容方案](open-world-content-plan.md) A「主线」的结构（§0–§5）、§6.2 接取条件、§7 功能开启点，以及 [改造方案](open-world-expansion-plan.md) §3.14 中“主干路”“剧情硬门槛”的说法。任务的剧情含义、章节标题、首领、已写对白、步骤内容保留，只改**组织方式、接取方式和完成判定**。冲突处以本文为准。
>
> 适用范围：星潮海开放世界。旧「最后一条归途」（`campaign=homeward`）不在开放世界里，本次不改。

## 0. 原则

1. **进度不靠任务。** 岛屿、首领、地城、功能、港口服务、裂星潮，每一项都有不做任务也能达到的路径。只刷怪也能玩完全程。
2. **任务从世界里发现。** 走到某处、看到某物、碰到某人才出现任务；地图上只有“？”和传闻，不提前列清单。
3. **岛内无顺序，岛间无锁。** 每座岛的故事分成几条并行线索，顺序随意；岛与岛之间不强制先后，衔接靠对白随“玩家已经知道什么”变化。
4. **目标认世界事实。** 首领打没打、门开没开、营地清没清、线索看没看过，这些是世界里的事，接没接任务都算。只有少数关键演出（守护、选路线、救援）保留任务专属战斗。
5. **引导只做两件事：教系统、指方向。** 不负责推剧情。

`pnpm config:check` 自动检查第 1 条（§6.3）。

## 2. 任务分类

`任务.xlsx`「任务类型」页：

| type | 名称 | 内容 | 重复 |
|---|---|---|---|
| `guide` | 引导 | 新手引导；每座岛的登岛指路；地城指路；分区探索指路 | 一次性 |
| `side` | 支线 | **岛屿故事**（原 51 个主线任务拆成的线索与汇合，带 `岛屿故事` 标签）；区域支线（内容方案 §6.4） | 一次性 |
| `bounty` | 悬赏 | 前哨悬赏板（内容方案 §6.3） | 可重复 |

- 悬赏单独一类，是因为它可重复、没有剧情；如果希望任务页只有两类，可以把它并入支线，只改类型表，不影响实现。
- 原 `dungeon`（地城引路）、计划中的 `explore`（探索）并入 `guide`，用标签 `地城` / `探索` 区分。
- `main` 行保留，仅用于显示已领过奖的旧档案条目（历史快照不改类型）。新内容不得填 `main`。
- 每个任务只有一个主类型（AGENTS.md 任务页规则）。

## 3. 岛屿故事的结构

```
登岛（引导，到达自动接取，指出三条传闻）
   ├─ 线索 A ─┐
   ├─ 线索 B ─┼─ 汇合（满足汇合条件后出现）→ 首领 → 回港
   └─ 线索 C ─┘
门：世界机关，任何时候都能打开，与任务无关
```

- **登岛任务**：到达本岛登陆点自动接取；对白里提到三条传闻，完成后在全图对应分区打上“？”传闻标记。不做登岛任务也可以直接撞见线索。
- **线索**：1–3 个任务的小链，位于 1–2 个分区。线索之间没有顺序。每条线索的第一个任务由**发现**触发（§5.2）。
- **关键线索**：讲本章核心揭示或引出后续人物的线索，汇合条件里必须包含它（每章最多 1 条）。其他线索可以跳过。
- **汇合任务**：条件满足后出现，讲到首领前的剧情。首领步骤认世界事实：已经打过首领就直接完成。
- **回港任务**：港口对白，完成后执行本章的“引导路径”开放项（§7）。
- **门**：内容方案里的六道剧情门（船坞闸门、雾墙、炉心隔热门、冰封舱门、界桥封锁、航网屏障）改为**世界机关**，在 `世界.xlsx` 新页签「门」配置：调查机关 → 击退守门敌人 → 永久打开。记在 `st.gates`，任何时候都能开，不需要任务。故事里原来“打开门”的步骤改成认世界事实（门已开就直接完成；没开就在这一步现场开）。
- **跳过整座岛的故事**：门照样能开，首领照样能打；回港任务不做，本章功能走等级兜底（§7）。

### 4.1 跨岛衔接

- 岛与岛之间**没有任务前置**。第 n 章登岛任务只要求第 n 座岛已开放。
- 后面岛屿的任务里出现前面岛屿的人物（青芒、铜铃、烬羽等）时，任务条件加“该人物已认识”：完成了该人物的登场线索，或已通过等级兜底入驻港口（§7）。兜底等级都低于后面岛屿的开放等级，所以实际上不会卡住任何人。`config:check` 校验每个“已认识”条件都有兜底。
- 对白用 §6.4 的条件变体处理“玩家知不知道某件事”，不靠锁任务。

## 5. 规则

### 5.1 进度规则

| # | 规则 |
|---|---|
| R1 | 岛屿、首领、地城入口、功能、港口服务、裂星潮都有不含任务条件的开放路径（§7） |
| R2 | 第 n 座岛远航条件：等级 ≥ 该岛等级带下限 − 2（第 2–6 岛：L6 / L13 / L19 / L25 / L30），或已击败第 n−1 座岛首领。航图显示“等级 X 可远航” |
| R3 | 首领场：所在岛已开放就能进入。打不打得过由 [数值心流](open-world-numeric-flow.md) 的墙与钥匙决定 |
| R4 | 任务刷出的敌人等级取步骤所在分区的等级带，不读任务进度；裂星潮后取升阶后的等级带 |
| R5 | 多任务并行（上限 20，配置在「说明」页全局参数），只追踪一个 |
| R6 | 同一时间只有一组任务专属战斗波次：本区域未打完时开另一个任务的战斗 → 拒绝；旧波次在别的区域 → 新战斗开始时旧波次作废（已击杀不复活），旧任务停在原步骤，回去可重新开始（`attempt+1`） |

### 5.2 发现与接取（`accept_mode`）

| 值 | 触发 | 用于 |
|---|---|---|
| `none` | 条件满足立即自动接取 | 新手引导 |
| `arrive` | 进入指定分区/地标范围 | 登岛任务、部分线索、探索 |
| `discover`（新增） | 调查世界里的线索物件 | 线索（货箱、浮标、输能管、冻舰……） |
| `talk` | 与人物对话（包括野外偶遇的人物） | 线索、区域支线 |
| `board`（新增） | 悬赏板选取 | 悬赏 |

- **线索物件常驻世界**：线索物件（原来只在任务进行中出现的调查点）在所在分区被探索到后一直可见，显示为可调查的“？”。调查它会接取对应线索，并把这一步记为已完成（同时写进 `st.seen`）。
- **传闻**：登岛任务、港口人物对话、悬赏板可以给出传闻，在全图对应分区打“？”标记，只指地点不给任务。传闻在 `任务.xlsx` 新页签「传闻」配置。
- 发现时弹出一行提示（例如“发现线索：封印货箱”），不打断操作；需要对白的在接取时播放（沿用接取对白组）。

### 5.3 目标认世界事实

步骤满足以下事实时直接完成：在接取时检查一次，之后每推进到新的一步再检查一次。

| 步骤 | 世界事实 | 来源 |
|---|---|---|
| `boss` | 已击败该首领 | `st.bosses` |
| `gate`（新增） | 该门已打开；没开就在这一步现场开（调查 + 守门战） | `st.gates`、`世界.xlsx`「门」 |
| `clear_camp`（新增） | 该营地被这个角色清空过至少一次 | `ow_camp_cycles` 的服务端记录 |
| `interact` 且 `world_fact=是` | 该线索物件已被调查过 | `st.seen` |
| `reach_waypoint`（新增） | 传送点已解锁 | 传送点记录 |
| `discover_zone`（新增） | 分区已发现 | 探索位图 |

保留任务专属战斗的步骤：`defend`、`choose`、`route_battle`、`rescue`，以及剧情需要的少数 `battle`。原来在营地旁“打一波专属怪”的 `battle` 步骤，凡是旁边有对应营地的，改为 `clear_camp`（逐条见 §4 说明列；其余由实现方按“步骤位置 ±12 格内有同主题营地”筛选后列清单给用户试玩确认）。

### 5.4 放弃与追踪

- 支线、悬赏可以放弃，放弃后进度清零、波次作废。引导不能放弃，但可以不追踪。
- 追踪：任务页点“追踪”切换；接取新任务时不抢追踪；只有新手引导和“当前没有追踪任何任务”时自动追踪。
- HUD 只显示一行文字 + 方向箭头，无地面路径线。当前场景目标优先，其次玩家主动追踪的任务，再其次阶段目标。

### 6.4 `config:check` 新增校验

1. 每个 `feature:*`、`island:*`、`npc:*`、`hardmode` 至少有一个 `group` **不含** `kind=task` 和 `kind=threads`（原则 1）。
2. 每个 `npc_met` 条件引用的人物都有等级兜底入驻，且兜底等级 ≤ 引用任务所在岛的开放等级。
3. 每座岛：线索 2–3 条；关键线索 ≤ 1 条且出现在汇合条件的每一组里；汇合条件不要求全部线索（第一章除外，标注 `allow_all=是`）。

5. 跨岛不得有 `task` 条件（`npc_met` 除外）。

7. `discover/arrive` 必须有 `discover_landmark`；`bounty` 必须有 `pool` 和冷却；`main` 不得出现在新行。
8. 同一人物在同一时刻只能命中一条站位（§8）。

## 9. 运行时状态（`StarseaState` v2）

```ts
type QuestRun = { step: number; attempt: number; acceptedAt: number; choice?: 'a' | 'b' };
type BountySlot = { slot: string; zone: string; task: string; instance: string; progress: number; cooldownUntil?: number };

type StarseaState = {
  version: 2;
  quests: Record<string, QuestRun>;   // 进行中；可接/锁定按条件实时计算，不存
  done: string[];                     // 已完成一次性任务（沿用）
  tracked: string | null;
  wave: { task: string; step: number; region: string; spawns: Spawn[]; killed: string[]; startedAt?: number; minClearMs?: number } | null;
  gates: string[];                    // 已开的门
  seen: string[];                     // 已调查的线索物件
  rumors: string[];                   // 已获得的传闻
  bounties: BountySlot[];
  // 沿用不变
  npcs: string[]; features: string[]; islands: string[]; bosses: string[]; hardmode: boolean; crystals: string[];
  tide?: Record<string, number>; night?: …; nights?: number; completion?: …;
  legacy?: { chapter: number; task: number; step: number };  // 迁移留底，保留一个规则版本
};
```

删除：`chapter`、`task`、`step`、`attempt`、`accepted`、`openingComplete`、`choices`。

### 9.1 接口 `POST /api/quest`

| op | 参数 | 说明 |
|---|---|---|
| `discover` | `target`（线索物件/门） | 调查世界物件：写 `seen`，接取对应线索，推进认此事实的步骤 |
| `gate` | `gate` | 开门流程：调查 → 刷守门敌人（复用波次）→ 全灭后写 `gates` |
| `accept` | `task` | `talk` / `board` 接取；`arrive` / `none` 由服务端在进入区域、条件变化时自动接取 |
| `talk` / `interact` / `start` / `defense-finish` | `task`、`target`、`choice?` | 原逻辑，作用于指定任务的当前步骤 |
| `abandon` / `track` | `task` | §5.4 |
| `relic` | 不变 | |

全部写操作带 `command_id` 幂等和角色 revision 校验；发奖与任务完成在同一事务。

### 9.2 击杀结算

- 任务波次怪：ID 含任务 ID（`q:<task>:<step>:<attempt>:<i>`），推进对应任务。
- 守门敌人：ID 前缀 `gate:<id>:<attempt>:<i>`，全灭后开门。
- 首领：写 `bosses`；推进所有当前步骤为该首领的进行中任务；`evaluateUnlocks`。
- 营地清空：营地轮次结算时，推进所有当前步骤为 `clear_camp` 且是该营地的任务。
- 悬赏：只计服务端确认的击杀（内容方案 §6.3）。

### 9.3 视图 `starseaView`

返回进行中任务列表、当前岛可见的“？”（线索物件、传闻、门）、`tracked` 或“附近值得去”、航图（含“等级 X 可远航”）。其余沿用。

### 9.4 经验

`starseaBalance.taskXp` 改为按任务 ID（或直接用 `reward_xp`）；各任务数值不变。被删除的两个任务（ss-c01-n03、ss-c05-n03）的经验平分到同章汇合任务。其余被改成门或汇合开场的任务保留 ID 和奖励。

## 10. 旧存档迁移（v1 → v2）

在角色加载时执行，幂等：

1. 旧游标 `(chapter, task)` 之前的任务（含内容方案新增的串场任务）全部并入 `done`。新串场任务不发奖、不写档案。
2. 游标指向的任务：已接取（按旧 `acceptedList` 规则或 `accept_mode≠talk`）→ `quests[id] = {step, attempt, choice}`；未接取 → 不写，它会作为可接任务出现。
3. 游标指向 ss-c01-n03 或 ss-c05-n03（已删除）→ 对应门直接写入 `gates`，同章汇合任务按条件出现。
4. 已越过的门、已调查过的线索 → 写入 `gates`、`seen`。
5. `wave` 原样保留；`choices[chapterId]` → 写到该章 `choose` 任务的 `choice`，任务已完成则丢弃。
6. `npcs`、`features`、`islands`、`bosses`、`hardmode`、`crystals`、星潮夜原样保留，只增不减；随后跑一次 `evaluateUnlocks`（按现状解析，不补造历史、不发任务奖励）。
7. `tracked` = 旧游标任务；旧字段存入 `legacy`。
8. 任务档案（`taskJournal.completed / archive`）一律不改。

用真实数据库验证：迁移前后账号、角色、回执、流水逐行一致；跑两遍结果相同；进行中的波次、守护、路线选择迁移后能继续并正常完成。

## 12. 验收

1. **不做任务也能通关**：新角色不接任何任务，只靠营地、地城、悬赏、开门：开放全部六岛、全部功能、全部港口服务，击败六座岛首领并进入裂星潮。用自动化驾驶器跑一遍，记录每项开放时的等级。
2. **乱序**：每章三条线索按 6 种顺序各跑一遍，汇合在满足条件时出现、对白变体正确；先打首领/先开门/先清营地/先调查线索物件，对应步骤接取后直接完成；跳过第 n−1 章直接做第 n 章，承接句出现，其他一切可用。
3. **发现**：每个线索第一个任务都能通过“看到物件/走到地点/遇到人物”接取，不需要先接登岛任务；线索物件在分区发现后常驻可见。
4. **并行**：同时进行 ≥ 5 个任务；追踪切换；跨区域开新战斗时旧波次作废、已击杀不复活、可重新开始；同区域冲突被拒绝。
5. **刷级路线**：`pnpm balance` 跑“全做任务”与“完全不做任务”两种日程，后者到达每座岛开放等级的时间不超过前者 1.15 倍；超过时调高悬赏奖励或兜底等级，不能把任务改回必做。
6. **怪物等级**：任务怪只取分区等级带，同一任务在不同进度的角色上等级相同。
7. **配置校验**：故意删掉某功能的兜底组、或让两条线索互为前置、或加一条跨岛任务前置，`config:check` 都报错。
8. **迁移**：§10 全部条目，真实数据库，含断线恢复、重复提交、奖励防重。
9. **界面**：任务页类型目录（引导/支线/悬赏 + 历史）；岛屿故事按岛分组并显示“线索 2/3”；HUD 只有一行文字 + 箭头；无追踪时显示“附近”；全图“？”标记；按 [项目.md「状态切换与布局稳定」](../../项目.md#状态切换与布局稳定) 连续切换条目检查。
