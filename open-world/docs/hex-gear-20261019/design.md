# HEX 海克斯符文散件——设计文档（HEX-D01）

> 设计版本：D01-draft-1（2026-10-19）
> 负责人：Claude
> 状态：初稿；U-01～U-07 已由用户于 2026-10-19 决定（见 7.1）

## 一、玩法定位

### 1.1 现有装备体系回顾

| 层次 | 来源 | 特性 |
|---|---|---|
| 套装散件 | 324 件，6 武器谱系 × 3 系列 × 3 造型阶段 | 数值属性 + 词缀 + 套装效果，养成主干 |
| 威能（Aspect） | `aspects.json`，绑定武器类型 | 技能改造，多规则束，改变特定技能行为 |
| 铭纹（Inscription） | `effect-atoms.json`，按部位分配 | 元素原子效果，单触发简单机制 |
| 副本强化（Augment） | `augments.json`，副本内临时 | 副本限定的临时属性/机制增强 |

### 1.2 HEX 散件的定位

**核心理念**：参考 LOL 海克斯大乱斗（ARAM Augments）的「单件即构筑」思路——每件 HEX 散件携带一条独立的**战斗行为机制**，不修改特定技能（区别于威能），不限元素（区别于铭纹），而是改变**通用战斗行为**（命中、击杀、受伤、移动、施法等触发的连锁反应）。

**体验目标**：
- 玩家通过 HEX 散件的**组合搭配**，在不改变技能配置的前提下，显著改变战斗风格
- 每件 HEX 散件的机制足够独特，能单独影响构筑决策
- 鼓励「我来试试这个组合」的构筑探索，而非单纯数值堆叠

**与现有体系的关系**：
- 套装 → 基础属性骨架
- 威能 → 技能专精方向
- 铭纹 → 元素联动
- **HEX → 战斗行为风格**（本次新增）

## 二、系统规格

### 2.1 槽位方案（待用户决定）

> 已作废（2026-10-21）：HEX 不占槽位，而是装备词缀，见 `d13-affix-rework.md`。

**方案 A：复用现有部位**
- HEX 散件分配到已有 6 部位（weapon/armor/helmet/boots/accessory/ring）
- 与套装散件共享槽位，穿 HEX 就不能穿同部位套装件
- 优点：无需新增槽位，存档兼容
- 缺点：与套装养成互斥，可能让玩家纠结

**方案 B：新增独立 HEX 槽（推荐）**
- 新增 1–3 个 HEX 专用槽位（如 `hex1`、`hex2`、`hex3`）
- 与套装/威能/铭纹完全独立，互不冲突
- 优点：不破坏现有养成，专注构筑选择
- 缺点：需后端新增槽位 schema、快照与迁移（B01 已确认无通用实现，需 B02 新增）
- 槽位数决定了构筑深度：1 个太单薄，3 个组合丰富但需更多内容，**建议首批 2 个**

**方案 C：饰品子槽**
- 在项链或戒指下挂 HEX 子槽
- 不新增顶层部位，但需子槽逻辑

→ **推荐方案 B（2 个独立槽位）**，理由：独立养成线不冲突，2 槽即可产生有趣组合，后续可扩展。

### 2.2 品质与稀有度

| 品质 | 颜色 | 效果强度 | 获取 |
|---|---|---|---|
| 普通（common） | 灰 | 基础版机制 | 野外掉落、商店 |
| 魔法（magic） | 蓝 | 数值增强 | 精英掉落、任务奖励 |
| 稀有（rare） | 金 | 数值增强 + 附加条件效果 | 首领掉落、副本宝箱 |
| 传说（legendary） | 橙 | 完整版机制 + 独特附加 | 高难副本、特殊挑战 |

> 2026-10-19 修订：品质直接复用游戏现有 `GearQuality`（common/magic/rare/legendary）与 `--color-rarity-*` 色值，不另设 epic/紫色。

同一个 HEX 机制（如「连锁闪电」）在不同品质下的数值不同（连锁次数、衰减比、伤害比），但核心触发逻辑相同。品质升级路线待定（是否支持升品、洗练）。

### 2.3 互斥与组合规则

- **同名互斥**：同一 HEX 机制不能同时装备两件（即使品质不同）
- **类别互斥（待定）**：某些机制间可能冲突（如两个「命中时 AoE」可能叠加过强），需样板验证后逐对标注
- **正向组合**：设计时有意制造跨类别联动（如「命中附加灼烧」+「引爆灼烧」）
- 互斥信息写入 HEX 数据条目，客户端穿戴时校验，服务端授权时二次校验

### 2.4 效果执行

HEX 散件的机制**必须映射到现有 `EffectRule` 体系**：
- 每件 HEX 散件在数据中声明 1 条或多条 `EffectRule`（同威能的 `parts.rules` 结构）
- 触发、动作、条件、ICD、概率均使用已有 schema
- 构筑解析通过 `rules/build-parts.ts` 汇总，与威能和铭纹共用管线
- 战斗执行由 `packages/simulation` 消费，事件通过 `CombatEvent` 反馈客户端
- **不新增效果类型或触发器**（首批），只组合现有语义

数据源建议：新增 `packages/content/hex-runes.json`，结构类似 `aspects.json` 的 `parts.rules` 字段。`build-parts.ts` 需增加从 HEX 槽位读取规则的入口（B02 实现）。

## 三、首批 HEX 散件候选（12 件）

以下设计参考 LOL 海克斯大乱斗的增强效果，每条标注【原作参考】和【本作改编】。所有数值为初始提案，最终由 TTK 推导和用户确认决定。

### 3.1 攻击增强类

#### HEX-01 连锁闪电（Chain Lightning）
- **原作参考**：ARAM「Chain Lightning」——普攻弹射到附近敌人
- **本作改编**：命中时有概率释放连锁闪电
- **触发**：`hit`，概率 30%，ICD 60 ticks（2秒）
- **动作**：`arc`，伤害比 40% hit，弹射 3 次，范围 4，衰减 0.7，雷电伤害
- **条件**：无额外条件
- **组合提示**：与「风暴聚能」组合增加弹射次数感知

#### HEX-02 余震裂地（Aftershock Slam）
- **原作参考**：ARAM「Infernal Soul」——攻击附带 AoE
- **本作改编**：每第 5 次命中在目标点产生小范围爆破
- **触发**：`nth`，every 5（命中计数），概率 100%
- **动作**：`nova`，伤害比 60% hit，半径 2.5，物理伤害，at target
- **条件**：无
- **组合提示**：群怪环境下稳定 AoE 补充

#### HEX-03 猎手印记（Predator's Mark）
- **原作参考**：ARAM「Vulnerability」——标记敌人使其受到额外伤害
- **本作改编**：命中时对目标施加「猎手印记」状态，标记期间受到的伤害增加
- **触发**：`hit`，概率 20%，ICD 150 ticks（5秒）
- **动作**：`status`，状态 `vulnerable`，持续 90 ticks（3秒），强度 15%
- **条件**：无
- **组合提示**：全队增伤，对精英/首领价值高

#### HEX-04 暴风收割（Storm Reaper）
- **原作参考**：ARAM「Phenomenal Evil」——攻击永久叠加属性
- **本作改编**：击杀敌人时获得短暂攻击增幅 buff（本场战斗内叠加）
- **触发**：`kill`，概率 100%，ICD 0
- **动作**：`buff`，攻击增幅 damageMult +3%，持续 300 ticks（10秒），最多 5 层
- **条件**：无
- **组合提示**：清怪越快增幅越高，鼓励连续击杀

### 3.2 防御/生存类

#### HEX-05 荆棘之心（Thorned Heart）
- **原作参考**：ARAM「Shield Bash」——护盾期间攻击增伤
- **本作改编**：持有护盾时，命中敌人额外造成反伤
- **触发**：`hit`，概率 100%，ICD 30 ticks（1秒）
- **动作**：`nova`，伤害比 20% shield，半径 0（仅命中目标），ref shield，at target
- **条件**：`self_state: shield`（持有护盾时）
- **组合提示**：与护盾类技能/铭纹联动

#### HEX-06 生命涌泉（Overflow Spring）
- **原作参考**：ARAM 治疗过量转护盾机制
- **本作改编**：治疗溢出部分转化为护盾
- **触发**：`passive`
- **动作**：`buff`，持续 999，maxStacks 1，flags: { surviveAtOne: false }
- **实现说明**：此效果需利用 `heal` action 的 `overflowShield` 字段。如果 HEX 不能直接修改其他治疗来源的行为，改为——受到治疗时获得短暂护盾（消费已有 `heal`+`shield` 组合）
- **替代方案**：`hurt` 触发（受伤后），自动回复 5% maxHp 并给予等量护盾
- **触发**：`hurt`，概率 100%，ICD 300 ticks（10秒）
- **动作**：`heal` 5% maxHp + 后续规则 `shield` 5% maxHp 2秒
- **条件**：`self_hp lt 0.5`（低于50%血量时）
- **组合提示**：生存兜底机制

#### HEX-07 寒霜护甲（Frostbite Armor）
- **原作参考**：ARAM「Glacial Augment」——攻击减速敌人
- **本作改编**：受到近战攻击时，对攻击者施加冰冻减速
- **触发**：`hurt`，概率 40%，ICD 90 ticks（3秒）
- **动作**：`status`，状态 `slow`（原稿 chill 非现行枚举，2026-10-19 更正），持续 60 ticks（2秒），强度 30%
- **条件**：无（近战/远程均触发，或后续限定 `distance lt 3`）
- **组合提示**：近战怪包围时自动减速

### 3.3 机动/控制类

#### HEX-08 幻影步（Phantom Step）
- **原作参考**：ARAM「Blinding Speed」——使用技能后获得移速
- **本作改编**：施法后获得短暂移速增幅
- **触发**：`cast`，概率 100%，ICD 120 ticks（4秒）
- **动作**：`buff`，speedPercent +30%，持续 60 ticks（2秒），maxStacks 1
- **条件**：无
- **组合提示**：提高走位灵活性，半自动模式下走 A 节奏更流畅

#### HEX-09 虚空裂隙（Void Rift）
- **原作参考**：ARAM「Orbital Laser」——周期性召唤伤害区域
- **本作改编**：每 10 秒在自身周围产生一个短暂伤害区域
- **触发**：`interval`，every 300 ticks（10秒），概率 100%
- **动作**：`field`，at self，半径 3，持续 90 ticks（3秒），interval 30（每秒），伤害比 25% attack，暗影伤害
- **条件**：无（战斗中自动触发）
- **组合提示**：站桩/群怪场景稳定 DPS 补充

#### HEX-10 引爆印记（Detonation Sigil）
- **原作参考**：组合灵感——消耗异常状态造成爆发伤害
- **本作改编**：命中携带 2 种以上异常状态的敌人时，引爆所有异常造成额外伤害
- **触发**：`hit`，概率 100%，ICD 180 ticks（6秒）
- **动作**：`detonate`，statuses 全异常（burn/poison/bleed/slow/shock/vulnerable/armor_down），伤害比 50%，remove false（不消耗状态），radius 0
- **条件**：目标至少有 2 种异常——用 `target_status` + `any` 组合条件
- **实现说明**：需组合多个 `target_status` 条件判断堆叠数量，可能需简化为"命中中毒或灼烧的敌人"
- **组合提示**：与铭纹元素原子深度联动的核心 HEX

### 3.4 资源/效率类

#### HEX-11 灵力虹吸（Mana Siphon）
- **原作参考**：ARAM「Teardrop」类灵力恢复
- **本作改编**：击杀敌人时恢复灵力
- **触发**：`kill`，概率 100%，ICD 0
- **动作**：`mana`，ratio 0.08 maxMana
- **条件**：无
- **组合提示**：持续作战不用回城补给

#### HEX-12 冷却共鸣（Resonance Echo）
- **原作参考**：技能循环加速机制
- **本作改编**：暴击时缩短一个随机技能的冷却时间
- **触发**：`crit`，概率 100%，ICD 150 ticks（5秒）
- **动作**：`cooldown`，mode random，ticks 30（1秒）
- **条件**：无
- **组合提示**：暴击构筑的技能循环加速器

## 四、样板候选

**推荐样板**：HEX-01「连锁闪电」
- **理由**：
  1. 完全复用已有 `arc` action，无需新增执行语义
  2. `hit` 触发 + ICD + 概率是最常见、最稳定的效果模式
  3. 视觉反馈明显（闪电弹射），玩家立刻感知 HEX 的效果
  4. 数值可通过弹射次数、衰减、伤害比精确控制
  5. 与现有雷电类铭纹（atom-thunder）有天然联动点

**样板验证内容**：
- 数据定义 → `hex-runes.json` 样板条目
- `build-parts.ts` 读取 HEX 槽位 → 汇入已解析构筑
- 战斗模拟触发 → `CombatEvent: effect_triggered` 事件
- 客户端弹射特效播放
- 穿戴/卸下/换装流程
- 存档兼容（旧存档无 HEX 字段，可选缺省）

**备选样板**：HEX-04「暴风收割」（`kill` + `buff`，同样完全复用已有语义）

## 八、已确定 vs 建议 vs 待定

### 已确定（来自现有项目规则）
- 效果执行必须使用 `EffectRule` 体系，不用未知效果字符串
- 客户端消费服务端权威状态，不复制公式
- 新增内容只改内容源，新机制需新增执行能力与测试
- 装备实例工厂、私有掉落与服务端解析复用已有实现
- HEX 散件是散件，不是套装（无套装效果）

### 建议（需用户确认后成为确定）
- 2 个独立 HEX 槽位（方案 B）
