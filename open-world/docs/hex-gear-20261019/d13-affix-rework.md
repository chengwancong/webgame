# HEX-D13 海克斯改为装备词缀（推翻 U-01 双槽）

> 2026-10-21 用户纠正：海克斯本意是「装备上的符文效果」，不是额外装备栏。本文是 HEX **获取与承载方式**的唯一规则源。design.md §2.1 / U-01、d11/d12 中凡涉及 hex1/hex2 槽、开槽任务、选奖、回响碎片的内容，一律以本文为准。机制本身（d03/d05/d06/d07/d10 的效果、互斥组、全局钳制、文案 d08、图标 d09）继续有效。

## 1. 用户决定（2026-10-21）

| 编号 | 决定 |

| U-01′ | HEX 是普通装备上的一条特殊词缀，不再有独立槽位 |

## 2. Claude 默认裁决（不阻塞，用户事后复核）

### 2.1 数据形态
- 装备新增可选字段 `hex?: {rune: string; tier: GearQuality}`。`rune` 是 hex-runes.json 的 id，`tier` 是这条 HEX 的品质（独立于装备本身品质，但 **tier ≤ 装备品质**）。
- 带 HEX 的装备仍是完整的普通装备：主属性、普通词缀、套装、威能、铭纹、强化、洗练都照旧。**强化和洗练不改 HEX**，分解按普通装备结算，HEX 不额外返还。
- `core` 旧核心与 stage-key 保底钥匙装备（origin.kind='stage-key'）不出 HEX；只在 `origin.kind='random'` 的装备上随机。

### 2.2 何时出现
- 门槛不变：接取 HEX-Q01 后（进行中或已完成），在 `ss-map-mist` 经济区掉落的装备才会掷 HEX。首发目录仍为 hex-loot.json 的 8 种。
- 来源仍是 elite / event / dungeonChest / dungeonBoss / rare，普通小怪不出。**只有魔法及以上品质的装备**才有资格掷 HEX。
- 概率换算一次：保证每个来源的 **HEX 期望获取量与现行 hex-loot.json 相同**。做法是 `p_词缀 = min(1, p_现行 ÷ 该来源每次掉出合格装备的期望件数)`，件数从冻结掉落表算出。Codex 算出后写回 hex-loot.json（version 升 2），并在交接里附上算式。
- HEX 品质沿用现行规则：默认 common；dungeonBoss/rare 按 dungeonMagic/rareMagic 概率出 magic（需角色 ≥ magicLevel）。最后再钳到不超过装备品质。
- 符文池过滤：`tier.requiredLevel ≤ 装备 requiredLevel + levelAhead`，并满足 `hexPrerequisiteMet`。前置判定时，「已装备 HEX」改为读身上 6 件装备的 `hex`。
- 打法偏向（biases）原样保留。

### 2.3 引导保底（替代开槽与选奖）
- HEX-Q01 进行中：下一件合格来源掉出的魔法及以上装备**必带** common HEX（只保一次，存 `hex.pity`）。
- HEX-Q03（军需平台首杀）：该次首杀掉落中品质最高的一件装备**必带** magic HEX。
- 三个引导任务的 `reward_hex_slot`、`reward_hex_choice`、`reward_hex_shards` 全部删除，改为同章节引导任务模板的普通奖励（经验/金币/材料，按 ss-c02 引导档）。
- 任务文案（Claude 定，Codex 写进表）：
  - Q01 goal：清退 z2 侵军 → 拾取一件带六角印的装备 → 回青芒交付。
  - Q02 goal：穿上带六角印的装备 → 在雾铃击败首领 → 回铜铃。
  - Q03 goal 不变。对白里「槽 / 嵌入 / 碎片」的说法由 Claude 在 HEX-F03 一并改。

### 2.4 叠加与互斥
- **同机制不叠加**：同一 `exclusiveGroup` 的多件装备，只生效品质最高的一条（同品质取部位顺序靠前的），其余显示为「同类未生效」。可以正常穿戴，不报错。
- d10 §5.1 的互斥组照用：`lethal-save` 同组只生效一条；`invuln` 共享冷却；`cooldown-reset` 第二件减半。
- 共鸣（替代原“两槽同打法 ×1.1”）：生效中的首发 HEX 里同一打法 **≥3 条**时，这些条目的 scale 数值 ×1.1。只有一档。

### 2.5 强度重定档（TTK，推导一次）
- 原口径（d05）：单条 common 10% / magic 14% / rare 20% / legendary 25%，按两槽设计，满配约 +50%。
- 现在最多 6 条，单条目标改为 **common 5% / magic 7% / rare 10% / legendary 12%**。6 条 common 约 +30%，6 条 magic 约 +42%，高品质满配由 d10 §5.2 的「HEX 伤害乘区 +60%」硬钳制兜底。
- 落地：所有 HEX tier 规则里列在 `scale` 路径上的伤害、护盾、回复数值统一 ×0.5。触发条件、ICD、控制时长、半径不变，保持“机制手感”。d10 §5.2 全局钳制全部保留。
- 验证一次：d10 §5.3 的高危对子 + 「6 件同打法 magic」整套各跑一次确定性战斗，结果满足 §5.2 即定档，不做扫参。

### 2.6 旧数据
- 开发期清档（用户已批）：先备份，再删除所有 `slot` 为 hex1/hex2 的装备实例（行囊、仓库、地面奖励），清掉 equipment.hex1/hex2 和 `hex.shards/offers`。`hex-echo-shard` 材料余额清零，不做补偿。
- 已完成 HEX-Q01～Q03 的角色：不补发保底，也不重置任务。

## 3. 接口变更（Codex，contracts 唯一修改人）

## 6. Claude 默认裁决（2026-10-21，回应 Codex B08 两问）

1. **共鸣阈值**：首发每打法仅 2 种机制，≥3 条不可达。改为 `resonanceMin` 配置项，首发 = **2**：生效中同打法且**机制不同**的条目 ≥2 条，这些条目 scale ×1.1，只有一档；同机制重复穿不算（本就同组未生效）。任一打法上线第 3 种机制后，把该值改 3，不改算法。
2. **验收用例改写**：D13-5 = 穿 2 件同打法不同机制 → ×1.1 生效，拿掉一件立即失效；再穿第 3 件同机制重复 → 不触发共鸣也不叠加。D13-7 = “6 件 magic 整套”取 6 种不同机制（8 种里任选，含 d10 §5.3 高危对子），满足 §5.2 全部钳制；不再要求 6 件同打法。
3. **引导任务奖励（无物品，仅经验/金币，沿用 ss-c02 同类任务数值行）**：HEX-Q01 = ss-c02-t01 档（xp 2232 / gold 120）；HEX-Q02 = ss-c02-t03 档（xp 3341 / gold 160）；HEX-Q03 = ss-c02-t05 档（xp 6121 / gold 400）。type 仍为 guide；删除所有 reward_hex_* 字段。

## 7. 三条引导任务按词缀改写（Claude 文案裁决，2026-10-21；取代 d12 §2 的对白/步骤/奖励/验收，ID 与接取条件不变）

通用：奖励见 §6.3，只发经验/金币；对白不出现“槽/嵌入/碎片/选奖”，不出现原作名。装备上的词缀统一叫“六角印”。

### HEX-Q01「旧信上的六角印」（青芒，z2）
- 步骤：① 清退 z2 侵军（`kill:z2_invader` ×12）→ ② 拾取一件带六角印的装备（`obtain:hex_gear` ×1，由 Q01 保底掉落保证）→ ③ 回青芒交付。
- 对白（接取）：「这批旧信封口都盖着六角印，我不敢乱送。你替我把侵军清一清，说不定打着打着，装备上就长出一枚。」
- 对白（完成）：「就是它。印不用镶，不用换——长在装备上，你穿着它打，它就替你干活。」

### HEX-Q02「印记的主人」（铜铃，港口；接取 Q01 完成）
- 步骤：① 穿上一件带六角印的装备（`equip:hex_gear` ×1）→ ② 在雾铃击败首领（`kill:mist_boss` ×1）→ ③ 回铜铃。
- 对白（接取）：「印随装备走，换了装备印也跟着换。打法对得上才有用，穿着去会会雾铃的首领，再回来跟我讲手感。」
- 对白（完成）：「看出来没？同一路数的印穿两枚，劲儿会拧到一起。别急着堆，先找搭档。」

### HEX-Q03「寄往下一站」（青芒，军需平台首杀后；首杀掉落保底 magic 印，见 §2.2）
- 对白按当前生效六角印的打法取一句（缺则通用）：先铺后炸/贴身绞杀/节奏接力 三句沿用 d12，通用句沿用。
- 完成后追加：「再往后，印会长出第三道纹——那是稀有的活儿。」（rare 门槛预告，不发奖）。

### 验收（取代 d12 §2 验收 2、3）
2'. 三条任务无槽/选奖字段；Q01 步骤②由保底掉落完成，重复交付不重复发奖。
3'. Q02 步骤①认“穿着带六角印的装备”，脱下后再穿可重新计数一次（不重复发奖）。

## 8. 资格比较裁决（Claude 默认裁决，2026-10-21，回应 Codex 审计）
- 词缀资格比较改为 `(gear.ilvl ?? requiredLevel) + levelAhead`，符文自身门槛（common 10 / magic 15 / rare 按配置）保留；不抬装备 requiredLevel。
- 角色等级低于符文门槛时，词缀保留但 `active=false`（reason=level，前端灰显并写「需 N 级」），升级后自动生效；不阻止穿戴。

## 9. D13-7 判据裁决（Claude 默认裁决，2026-10-21，回应 Codex「基线 5 分钟不死」）

1. **D13-7 以钳制为准，不以生存提升比为准。** 基线不死时“生存提升比”无意义，作废该指标；不得为过关调怪血或角色数值。
2. **通过条件（三条全满足）**：
   - ① 确定性注入：6 种不同机制 magic 整套 + d10 §5.3 高危对子，用固定 seed 构造最坏叠加（同帧多触发回复/减伤/冷却返还/无敌），断言 §5.2 全部钳制值（回复、减伤、冷却缩减、无敌时长上限）未被突破，且 lethal-save 同组只生效一条、invuln 共享冷却、cooldown-reset 第二件减半（以 d10 §5.1 为准）。
   - ② 同场景 5 分钟精英+首领压力，对比有/无 HEX：精英与首领击杀时间 ≥ 基线的 70%（即 HEX 整套提速不超过约 30%）；承受伤害 ≥ 基线的 60%；两者均不要求“基线会死”。
   - ③ 任一条出现触发次数为 0 的机制（慢触发未覆盖）时，用定向场景单独触发一次并断言行为，不计入②的时间对比。
3. 慢触发机制的定向场景由 Codex 补；若②超出阈值，登记为数值缺陷回派 Codex 调该机制档位（按 TTK 推导一次、验证一次），不改基线怪物。
