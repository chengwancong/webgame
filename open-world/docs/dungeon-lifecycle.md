# 副本流程与生命周期

客户端 0.8.1／协议 10／规则 ow-13／数据库 11。普通关卡、首领试炼、高难、梦魇以及实时／自动团队挑战统一走副本目录、准备、正式开战、目标推进、结局和返回营地。旧账号、角色、任务档案、回执和流水采用增量迁移保留。

## 玩家操作

营地的「副本」直接打开目录。目录显示服务端解析的准入、人数、次数、时限、断线、救援和消耗。普通关卡完成配置的清怪、精英目标即可进入首领阶段，支路无须全清。职责只是现有团本席位要求，本轮没有新增职业。

成员加载并准备后，由队长正式开战；单人界面自动完成这两个命令。初次加载不计时、不扣次。准备时修改的构筑在开战时重新核对，补位者在检查点加载并准备后正式加入、扣费并冻结构筑。重连原席位不重复收费。

运行中的副本由服务端持续推进。背包、任务、技能、后台、个人或全员断线都不暂停。实时掉线者留在场内，停止新输入，可受伤、治疗和救援；保留期到期释放席位。自动模拟退出或断线结束本人参与，其他成员继续；覆盖面板不算退出。

队友列表可选择治疗／护盾目标，靠近倒地队友按交互键或点击救援。移动、实际受伤、距离超出或救援者断线会中断读条。单人阵亡或所有实际参战成员倒地失败；没有检查点复活。队长离线后转交最早加入的在线成员。

个人退出保留此前收益，不拿后续奖励，不能再加入同场。仍参战的倒地成员、有效保留席位成员可以获得通关奖励。服务端逐事件自动入包，满包暂时超额保留。成功、失败、退出均返回营地；网络重试复用原命令编号，不能把成功改成失败。

## 配置与冻结

唯一副本内容源为 `packages/content/dungeons.json`。`defaults` 声明所有公共默认值，`profiles` 引用现有次数池、人数、职责、层级与剧情准入，`definitions` 配置内容并逐项覆盖。缺项只继承声明值；未知字段、地图、模板、不可执行目标、循环前置和冲突组合直接报错。UI 消费服务端结果，不重新推导玩法参数。

| 参数 | 公共初值 |
|---|---|
| 战斗时限／实时保留 | 各 1800 秒，保留不延长时限 |
| 加载超时 | 120 秒 |
| 救援 | 5 秒、2 格、30% 生命，无道具费用 |
| 次数扣除 | 正式开战，可覆盖为成功扣次 |
| 构筑 | 整场锁定；永久经验照常入账，场内属性保留快照 |
| 返回位置／满包处理 | 营地／临时超额保留 |
| 完整战斗明细 | 结束后 7 天；结果、奖励回执长期保留 |

实例创建时复制定义、地图、怪物、私有掉落／成长奖励配置与挑战词缀；开战及补位冻结实际角色构筑。内容调整只影响新实例的已冻结参数。实时使用开战后的墙钟安排战斗帧，续接补算未运行帧；自动模拟用逻辑战斗帧计时。截止前执行的有效最终击杀优先于同帧死亡，达到时限后不再执行后续战斗帧。

## 服务端与恢复

`DungeonService` 以 PostgreSQL 运行所有者锁维护一个实例执行器。`World` 持有独立角色、共享敌人、真实队友治疗／护盾和身体碰撞；自动模式使用同一执行器的自动操作，正式新路径不调用旧的整队合成角色结算。

事务同时保存完整战斗 checkpoint、成员、冻结构筑、输入、战斗事件、目标进度、奖励和终局。位置、生命、冷却、技能前摇、投射物、区域、首领阶段、随机状态和已死亡敌人均保留。换阶段保存前一阶段，携带角色生命、能量和冷却。已提交的奖励与结局通过实例／角色／事件唯一键去重。

运行状态包括准备、加载、运行、成功、失败、放弃、关闭；掉线属于成员状态，没有暂停状态。终局释放运行对象并关闭通道。恢复失败或连续运行故障达到声明阈值后关闭实例；同一事务退还本次入场资源和已扣次数，保留已获得奖励。退款失败回滚并等待数据库恢复，不提交半份结果。

官方 `@fastify/websocket` 集成在升级前校验登录、来源和实例编号；握手校验当前角色控制权，后续输入再次校验控制权、输入格式、顺序与参与状态。Vite 开发代理支持 WebSocket。客户端击杀报告不能给副本发奖，旧首领授权入口停止创建新场；野外清场规则保留。

| 接口 | 用途 |
|---|---|
| `GET /api/dungeons/catalog` | 解析后的目录、准入和次数 |
| `GET /api/dungeons/lobbies` | 可加入队伍 |
| `GET /api/dungeons/active` | 当前参与或待返回结果 |
| `POST /api/dungeons/command` | 创建、加入、准备、开战、续接、退出、返回、推进 |
| `GET /api/dungeons/:id/result` | 所属成员读取真实结果 |
| `WS /api/dungeons/:id/live` | 认证、操作输入、状态与已提交回执 |

## 验收与边界

真实 PostgreSQL、HTTP、WebSocket 检查覆盖 20 个独立账号、共享敌人、队长转交、救援中断、团灭、补位、配置覆盖、加载免费、两种扣次、保留过期、原场重连、系统退款、同帧终局与自动退出。浏览器检查覆盖直接进入、实际击杀与入包、蓝金结果、返回响应丢失后的幂等重试、背包与浏览器冻结不停战，以及 1280×720 和另外三个视口的文本／几何稳定性。

少见的团灭竞争、损坏 checkpoint 与安全补位使用明确的服务端持久化测试夹具；不是客户端报死，也不是自然养成结果。数值对比使用现有装备、职责和技能的固定种子小样本；独立角色团队相对旧聚合模型的战斗时长发生变化，本轮没有据此偷偷加倍怪物属性或重调奖励。小样本不代表玩家胜率，详见数值报告。

证据位于 `../../docs/reviews/open-world/dungeon-lifecycle/`，包含数据库、完整回归、浏览器截图、数值对比；发布证据另外记录真实双入口与原存档核对。复验命令：`node tools/verify-dungeon-instance-db.mjs`、`node tools/verify-dungeon-suite.mjs`、`node tools/verify-dungeon-browser.mjs`、`pnpm exec tsx tools/dungeon-balance.ts`。

最终验收：49 个测试文件、332 项全部通过；副本数据库 16 项、单人浏览器与 20 人双浏览器验收通过。完整发布前后源指纹一致。8611／8612 的 0.8.1／协议 10／ow-13／数据库 11 已通过真实登录与会话恢复；原账号、角色、回执与流水保留，常驻服务保持运行。
