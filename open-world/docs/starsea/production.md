# 六代理制作调度与资源台账

设计版本starsea-20261003-d1；主代理负责文档与独立验收，全部制作/返修归六代理。

## 先决条件与调度

本目录世界观、36任务、13地图、美术总表、ID需求与六任务书齐备后才启动制作。最多3子代理同时运行，首轮npc_art、monster_art、boss_art，第二轮monster_vfx、scene_art、props_integration。保持总计六制作代理，不建立用户侧新聊天、不自行扩增子代理。

第一轮先交付首章/统一样板再扩展本组后章资源，保证原生骨架、姿态、足点与挂点可供第二轮消费。代理提交样板后可继续本组余量；第二轮启动前主代理检查第一轮已交付事实。所有返修使用原代理追加任务，不新建第七名制作代理。

## 文件与接口归属

- 源与局部工具：assets/starsea/<group>/。
- 发布资源：apps/web/public/art/starsea/<group>/。
- 局部清单：assets/starsea/<group>/manifest.json，按requirements.json.manifestContract。
- npc/monsters/bosses/vfx/scenes/props为六固定组。
- props_integration唯一维护公共索引、构建入口、Vite QA入口、聚合资源注册、公共加载代码和资源版本。其他组不能同时改旧全局builder输出或共享manifest。
- 主代理维护docs/starsea正文、JSON需求与台账、review证据；不制作或修改资源主体。
- 原始素材、正式主线、玩家资产与旧档案不得清理。无关工作树改动保留。

## 里程碑

| 批次 | 覆盖 | 完成门槛 |
| --- | --- | --- |
| B0 | 一NPC、一普通怪、一首领主体、一技能、一段主港场景 | 来源、动态和风格经主代理核对；不是仅概念图 |
| B1 | 主港与第一章全部资源 | NPC、怪物、首领、技能、场景、物件在统一预览连续可用 |
| B2 | 第二、第三章 | 邮路/森林、工坊/矿道、对应角色技能与设备齐全 |
| B3 | 第四、第五章 | 冻舰、观测、前哨、难民/证词、角色与技能齐全 |
| B4 | 第六章与尾声 | 龙眠、维洛共用主体、三节点、界桥与复航表现齐全 |

所有需求按每组横向覆盖六章再按批次纵向组合，独立素材/变体/状态/实例数量分别统计。源文件制作、动态、登记、集成、验收分别记状态。脚本“成功”或代理口头完成不直接使台账accepted。

## 返修

主代理记录issueId、assetId、证据、重现条件、期望与所有者。所有者改自己目录，集成代理重新发布受影响的部分，主代理复测。未通过保留具体原因与缺失状态；最终报告只把全部必需门槛通过的资源记为接受。

## 数据与服务

资源先独立包/生产验收页，不默认切换正式剧情。涉及公共版本/构建的修改由集成代理遵守AGENTS.md：实际health/content兼容、真实登录/营地、发布构建停止服务→构建→恢复、原存档与回执保留。验收页不写钱包/任务进度；故事机制未接入明确显示待接入。
