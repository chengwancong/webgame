# 《深渊行者》大世界自动战斗游戏开发设计文档

版本 0.3；日期 2026-09-28；用户确认的实施依据。本文定义目标，不表示全部功能已经实现。实现与验证状态另见 `docs/04-open-world/implementation-status.md`。

新版客户端、服务端、数据结构和协议重新设计。现有代码只作参考，素材按需复用。独立运行入口、独立数据库，从空数据开始，不迁移旧账号、角色、装备或进度；不删除旧工程、数据库、存档和 cloudrealm。

## 一、游戏定义、玩法与交互

### 1.1 产品定位

浏览器优先、单人在线成长的二维斜视角探索割草游戏。玩家移动探索、清剿敌群、挑战首领、获得装备和调整技能构筑，自由选择手动、半自动和全自动。

大世界包括主路、支路、地标、危险区、安全据点、捷径；相邻地块连续加载；怪物、交互和入口有空间位置；探索改变后续路线。第一版为主城、三个野外区域和三个独立首领区域。不做多人共享地图、组队、交易、竞技排名、公会或开放玩家经济。现有侧面角色保持左右朝向，通过脚底定位、纵向排序与斜视地形组合，不伪造八方向动作。

### 1.2 体验目标

|尺度|行为|反馈|
|---|---|---|
|数秒|移动、聚怪、攻击、躲避、施法|命中、敌群变化、危险提示|
|数分钟|选路线、遭遇、事件、装备|地图推进、战利品、构筑、据点|
|数十分钟|首领、区域、成长方向|新机制、效果与探索目标|

自动减少重复操作，保留区域、构筑、深入程度、危险接管与首领选择。必须看到实际寻路、接敌、技能与拾取，不用静止角色加后台数值代替游戏。

### 1.3 内容预算

|项目|首个切片|第一版|
|---|---|---|
|世界|主城、两野外、一首领|主城、三野外、三首领|
|技能|六个|十二个|
|普通敌行为|四种|八种|
|精英机制|两种|四种|
|装备|武器、护甲、饰品、核心|维持四部位，扩效果|
|构筑|至少两条完整路线|近战范围、远程控制、持续伤害|
|行为装备效果|至少两个|支撑三方向|
|资源|经验、金币、一基础材料|保持简单资源结构|

数量是预算，不是完成度或平衡结论。完整流程：登录→主城→探索→战斗→正式奖励→拾取→换装→解锁→首领→回城→重登恢复。

### 1.4 区域设计

每区写明：教学职责、入口等级装备、主路支路捷径回环、安全点、怪物数量与组合、危险来源、整理机会、奖励方向、首领准备、失败改善和自动战斗限制。首区教移动攻击危险拾取；次区教组合与构筑；首领检验之前介绍的机制。手工地图为主，随机只用于组合、刷新与奖励。

### 1.5 战斗与构筑

连续二维坐标、固定逻辑步。移动、射程、碰撞、危险和拾取共用世界单位。技能具备目标、形状、射程、前摇、效果时点、恢复、冷却、消耗、移动施法、打断、状态、自动条件。手动和自动调用同一指令入口，不绕过限制。

近战范围侧重聚怪、生存与爆发；远程控制侧重距离、穿透和追击限制；持续伤害侧重叠加与区域控制。取舍必须在战斗中可见。装备效果要改变实际行为，新增效果同时有执行器、schema、说明生成和验证。外观不改变属性。

### 1.6 自动控制

手动负责移动目标技能；半自动负责移动接管，系统普攻技能拾取；全自动先由玩家选已开放的区域和范围，再寻路接敌施法避险拾取。默认半自动，全自动主动开启。

限制：仅获准区域；不自动过剧情门槛或进入首领；移动输入降为半自动；手动技能走同一队列；避险不承诺必胜；不自动耗稀有材料、分解或换装。初始活动半径十二导航单元。

状态：等待→选目标→寻路→接敌→战斗→拾取→返回。死亡、授权失效、无法到达、背包阻塞、控制丢失和网络异常停止。连续路径失败先换目标，再回中心，仍失败则停止并给出可执行提示。

### 1.7 界面交互

地图占主要空间。HUD 展示生命资源、技能冷却和不可用原因、目标、小地图、安全点、操作模式、自动状态、网络异常和奖励。普通怪不常驻详表；精英首领展示血条和机制。危险以形状、前摇、音效共同表达，不只依赖颜色。

自动设置包括中心范围、目标优先、技能优先、是否接精英、拾取筛选和停止条件，不做脚本编辑器。持续展示当前动作，停止显示原因及恢复入口。

背包详情包含部位品质属性、当前装备差异、效果条件、穿戴条件、装备锁定分解。不能只用战力箭头代替关键效果比较。换装：比较→确认→暂停→尾批结算→服务端操作→更新属性→恢复；提交中防重复，失败保持原装备。

强化显示当前值、成本、实际变化；服务端预览，正式操作重新核对。首领主动进入，先处理尾批；失败显示原因和回城/重试，不扣正式装备和经验。

背包成长设置打开暂停本地核心，授权仍按真实时间到期；恢复必要时续期。输入框不移动角色，面板不穿透点击，Esc 关闭最上层。关闭面板不恢复因死亡、网络或主动停止关闭的自动。后台暂停，无补帧收益，无离线收益。

### 1.8 新手流程

主城移动交互→低压自动攻击→手动技能→躲危险→首件有用装备→比较换装→小范围自动→停止恢复→首领。通过地图和短提示教，不用连续弹窗讲完全部系统。

## 二、架构与模块联动

### 2.1 技术路线

TypeScript + Phaser 4.2.1/WebGL；DOM/CSS 系统面板；Vite/pnpm workspace；Tiled 地图；Node24 LTS/Fastify5；PostgreSQL18；Electron 桌面适配；Vitest/Playwright/真实数据库。锁文件固定版本。模块化单体，无第一版微服务、帧房间、Kafka 和多层缓存。Tiled 世界组织不替代运行时流式加载。

### 2.2 工程与依赖

apps/web、apps/api、apps/desktop 独立入口；共享 contracts 请求响应与运行校验、rules 纯计算、simulation 无渲染核心、content 结构与公开产物、asset-manifest 动画锚点图集版本。共享规则不共享资产写权限。

客户端模块：应用状态、输入指令、自动控制、世界、导航碰撞、战斗、遭遇激活、表现、面板、网络协调、本地缓存。核心不依赖 UI/HTTP/DB/图片。

服务端模块：身份会话、角色控制、角色状态、世界进度、授权、收益校验、奖励、资产成长、命令事务、内容版本、审计运维。

### 2.3 联动

|操作|客户端|服务端|
|---|---|---|
|出城|切世界加载|进度检查授权|
|战斗|控制导航核心表现|批次校验结算|
|装备掉落|确认后地面展示|生成保存奖励|
|拾取|距离与命令|归属容量入包|
|换装|暂停尾批更新核心|结算装备事务推导|
|强化|预览确认|核消耗扣款强化|
|解锁|交互命令|前置检查写进度|
|恢复|回执快照|正式状态未领取奖励|
|接管|旧端停止|撤旧控制建新控制|

区分正式状态、即时状态、表现状态、待确认报告。命中→死亡事件→表现→报告→检查→奖励→回执→正式镜像。动画结束不决定发奖，面板不改钱包。

## 三、端服、协议与恢复

### 3.1 必须在服务端

身份归属、设备控制、等级与正式构筑、余额经验、装备实例、技能成长、世界进度、私有掉落、成本预览与执行、遭遇授权、结算去重事务、有效版本、恢复审计。客户端不能上传余额或装备属性覆盖资产。

### 3.2 客户端

输入自动策略、导航碰撞、获准怪物激活、AI、施法命中临时伤害生命状态、动画音效地图UI、缓存与待提交队列。正式属性消费服务端解析结果。

### 3.3 信任边界

服务端校验区域、怪物来源、刷新、额度速率、重复、构筑版本和控制权。不能仅凭报告证明每次移动命中死亡；签名不是执行证明。不支持该信任模型下的竞技排名、交易或其他玩家承担的结果。

### 3.4 契约

CharacterSnapshot：角色、版本、等级经验、余额、装备技能进度、未领取奖励。CombatPermit：控制、区域、构筑规则版本、轮次、开始到期与额度。CombatReport：命令、授权、序号、模拟步、击杀来源、预期版本。CommandReceipt：命令、结果、资产变化、奖励、新版本、错误。PendingReward：来源归属结果领取状态。GrowthPreview：条件成本变化与版本。

UTC 时间，时长注明毫秒或逻辑步；距离导航单元；数量整数；稳定 ID；配置注明类型单位范围缺省消费位置。client/protocol/rules/assets/db 分版本。

API 能力：会话、角色、控制获取续期接管、公开内容、区域授权、报告结束回执、奖励查询领取、装备卸装锁分解、成长预览强化技能升级、任务据点解锁。写操作 command_id+版本；归属来自认证。Cookie 来源/CSRF 检查，密码安全哈希，开发账号独立。

### 3.5 授权刷新

服务端登记遭遇、轮次、冷却额度；奖励来源唯一为角色+区域+遭遇+轮次+怪物。地块卸载、重进、刷新不生成新的奖励身份。首领完成与奖励同事务。

### 3.6 结算

每两秒或二十击杀先到者提交；首领结束离区换装提交尾批。先身份归属、回执指纹，再控制授权版本和全批校验；事务锁角色，写来源奖励经验货币进度流水回执版本。整批成功或失败。

同 ID 同内容返原回执；同 ID 不同内容拒绝；新 ID 重复来源不能发奖；成功回执不因规则更新失效。失效控制仍可查本人旧回执，不可新增写入。

### 3.7 掉落成长

金币经验结算后入账；装备服务端生成保存未领取，再地面显示，再领取检查容量。满包保留奖励并停止自动积累；重连恢复，不静默短时销毁。具体装备属性不得本地虚构。

换装升级：暂停→尾批确认→成长操作→快照新构筑→授权→恢复。自动升级在批次边界，不能同批混参数。每角色单成长写在途，报告、拾取、成长同队列，预览内容可并行。

### 3.8 恢复

最多两批未确认，超限暂停。异常保留原 ID 内容、暂停、查回执重试、读快照、恢复奖励、更新授权。IndexedDB 不是资产权威。主动退出处理尾批；强退或清缓存可能丢未确认尾段，不承诺全部零丢失。接管撤旧控制，旧镜像不得覆盖新状态。

### 3.9 存储

独立账号角色控制、余额版本、装备实例装配、技能、进度、授权来源、奖励、回执流水和发布版本。流水余额同事务，装备通过状态转换。新版上线数据需正常迁移备份，不随更新清空。

## 四、资源与技术实现

### 4.1 资源基线

角色94、怪物169、动画身份263、材料282、宝石189、消耗品185、状态157、NPC77、场景162。不是已实现内容数量或许可证明。

动作来源/替代：待机151/112、移动182/81、攻击260/3、受击157/106、死亡158/105、技能219/44、胜利154/109。替代可能为静态或其他动作。当前小规模 Godot 界面不证明世界链路成立。

### 4.2 生产

分类直接、适配、有限替代、补充、暂不用；记录来源许可状态、本地适配、哈希尺寸帧率动作朝向脚底碰撞图集内存用途缺口。先组合验证再扩。发布核对实际使用资源许可。

选择角色→核动作→统一脚底→按可见像素缩放→身体武器同步→左右翻转→文字不翻→图集与边缘→真实地图。旧转换器会改旧表，不运行整套，仅读导出与复用解码思路。预览大图不是战斗动画。

补齐地面道路、墙岩、树建筑、地标、据点入口、地面危险、拾取标记、音效、音乐环境。整背景仅作远景或房间，不放大当世界。先做道路墙树建筑敌群掉落组合样板。

### 4.3 地图

32×32导航单元分块。地面装饰碰撞遮挡出生遭遇交互触发连接安全点入口声音层。首区四乘四分块为预算，不以空地面积定义大。邻近加载、边缘预载、远景卸载、遭遇摘要保存；加载失败保留可用位置。

静态导航、动态避让，处理窄道目标失效危险代价活动边界传送失效。脚底排序，大物件拆底座前景，遮挡淡化不改碰撞。

### 4.4 核心表现

三十Hz核心、渲染插值目标60FPS。实体标识位置速度碰撞属性技能状态投射区域指令随机事件遭遇。固定种子稳定目标排序；视觉随机不影响核心。未知效果构建失败。

Phaser 世界，DOM 系统面板，同状态输入焦点。cast_started/hit_resolved/status_changed/entity_died/reward_confirmed 驱动表现。飘字合并、音效粒子上限、保留危险和范围。按键、音量、震屏和特效设置不改规则。

### 4.5 性能预算

M4/16GB/Chrome/1280×720；二百敌、三百飞行物；30Hz逻辑；目标60FPS、P95≤20ms；两小时无持续泄漏；20Mbps冷启动目标12秒。一百单人会话实际频率，4核8GB参考服务端，结算P95≤300ms不含公网。均待实测。先热点→空间索引→池→图集裁剪分块→远处无效工作→重复状态。不减少真实行为假达标。

### 4.6 桌面

P1 验证 Electron 本地包，共核心服务端；隔离沙箱关闭Node、IPC白名单。Steam票据服务端验证。商店、账号关联、安装包、平台要求独立验证，不把启动当发布。

## 五、实施验收运维

P0规则交互内容契约资源测试记录；P1真实世界六技能三模式资源桌面；P2账号授权奖励装备成长恢复首领全流程；P3三地区构筑敌人经济调优；P4发布桌面容量长跑备份监控。开发数据明确标记，正式构建不得假后端。

P1按核心→角色→组合地图→碰撞导航遮挡→战斗→自动→HUD暂停→地块→桌面性能顺序。P2按身份库→控制快照→版本授权→报告资产→拾取→成长→世界首领→故障→真实全流程。

调优记录问题证据→原因→配置→前后值→预期→影响→验证。共享核心固定种子模拟，记录耗时生命死亡技能资源装备等级经济奖励自动失败。模拟不替代真实理解试玩。

必测：地图往返、模式接管、堵路、密集危险、重复请求、同ID异内容、并发资产、回包丢失、尾批换装、等级边界、满包、刷新、设备接管、后台、首领重试、规则更新、DB故障、备份恢复、两小时。真实DB和真实浏览器，不用旧测试代替新链路。

独立dev/test/prod；静态资源/API/schema/content分别发布；哈希资源、协议检查、固定授权版本、旧结算窗口；回滚检查DB兼容。监控身份控制授权结算重试拒绝事务重复客户端资源队列异常收益，不记凭证。

QA本轮所有权临时文件成功失败清理，只留最终证据；保护旧源码存档改动包和cloudrealm，不跟随链接；报告实测前后字节。新版用自己的工具。

风险：空大地图以遭遇路线控制；自动失去决策以构筑危险控制；本地作弊以来源额度防护并限制应用；素材不足标缺口选完整动作；风格先组合；结算批量有界；重复刷新稳定来源；换装统一版本；内容固定预算；桌面早测；验收实际流程而非文件测试数。

第一版通过：真实探索战斗、三模式接管、清楚的新手危险失败、三构筑差异、服务端正式资产、可靠恢复去重接管、素材来源记录、性能与容量结论、Web桌面真实验证、文档代码配置证据同版本。当前文档是目标，完成状态以独立验收记录为准。
