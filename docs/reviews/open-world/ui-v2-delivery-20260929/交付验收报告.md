# V2 标准控件与游戏 UI 交付验收

日期：2026-09-29。结论：**不通过正式交付验收，保留为初步资源库。**

## 二、必须修改的问题

### 1. P1：真实游戏没有接入 V2，交付报告的“80%”没有依据

代码证据：

- `open-world/apps/web/src/presentation.ts:14` 起仍使用 `/art/ui/` 的技能与装备图标；HUD 与面板使用原有类名。
- `open-world/apps/web/src/style.css:37` 主按钮仍用旧图，`:54` 的 `.plate` 仍用旧边框。
- V2 代码从同一 CSS 的 `:277` 开始另加 `.v2-*` 类，却没有产品侧消费。

实测覆盖 HUD、背包、构筑、设置、目标、野外。背包覆盖 1280×720、1024×576、1600×900、1920×1080；全部没有 V2 类或 V2 资源请求。

视觉证据：[实际背包](inventory-1280.png)、[实际 HUD](hud-1280.png)、[实际野外](field-1280.png)。与[确认的 V2 背包母图](../../../05-art/ui-standard-v2-20260929/02-inventory-equipment.png)相比，薄蓝边框、清晰大标题、角色展示、完整装备插画、轻巧槽位和杏金主操作均没有落实。

修改要求：在真实组件中替换皮肤、排版及素材消费；背包、构筑、HUD、目标、自动设置、出行、设置和登录统一使用同一组件库。按实际功能逐模块接入，保留真实业务数据。不能仅给 body 添加类名后宣布完成。

达标：从普通游戏入口实际操作可见 V2；所有目标页面有运行截图及对应组件来源；旧框图不再被这些控件加载。框架、图标、字号、间距与 V2 同向，不要求把母图中的演示数字写入游戏。

### 2. P1：切图自身有可见缺陷，不能作为美术达标资源

[展示页局部实测图](gallery-detail-1280.png)显示主按钮上半部发暗，次要按钮“取消”难辨，关闭符号融入背景。当前页更接近基础控件样表，尚未呈现 V2 完整的卡通奇幻 UI。

原因有直接证据：

- `btn-primary--default.png` 顶部及中部采样 alpha=60，底部 alpha=255。所谓顶部光泽实际留下大面积低透明度区域，暗背景透出后形成分裂的色块。
- `apps/web/ui-v2-showcase.html:77` 将所有按钮文字设为午夜蓝，次要按钮没有改为浅色文字。
- V2 约定的午夜蓝 `#0B1F3B`、石板蓝 `#2A4668`、暖米白 `#F7E6C8` 被换成 `#1A2332`、`#2D3E54`、`#FFF8E7`，交付报告仍称完全对应，没有适配说明。
- 本批没有补齐 V2 装备、技能插画与角色展示素材；普通几何图标不能代替这些核心视觉资源。

修改要求：简单按钮底与高光优先使用可维护 CSS，或正确合成位图的底色与高光；深色按钮用浅色文字。恢复确认的色板，确需调整则记录原因及对照。插画类资源单独补齐、保留编辑来源，不把整个标准图裁成带背景和文字的图片。

达标：黑、白、灰、深蓝及真实场景五背景下，默认/悬停/按下/焦点/禁用仍清楚；按钮没有意外透明断层；实际游戏中的图标、框体、角色展示与母图一致。

### 3. P1：缺失或损坏输入会被“成功构建”发布

代码：`tools/build_ui_v2.py:70` 对缺失状态图打印警告后 continue；`:151` 直接覆盖运行时清单，随后只检查已登记输出是否存在，没有验证全部预期输入或实际 PNG 内容。

在独立临时目录中复现：

| 测试 | 实际行为 |
|---|---|
| 完整输入 | 返回 `(43, 0)` |
| 连续重复 | 清单哈希一致 |
| 删除主按钮 default 源图 | 返回 `(42, 0)`，输出“全部验证”，清单少一项，目录还遗留旧图 |
| 用非 PNG 字节替代同一源图 | 返回 `(43, 0)`，损坏字节被复制到输出 |

CLI 按第二个返回值决定状态，因此这两种故障都会对应退出 0。测试只重定向了脚本路径常量到临时输入/输出，未修改项目资源。详细结果见 [build-audit.json](build-audit.json)。

修改要求：先校验完整清单、唯一 ID、必需状态、文件可解码、实际尺寸及路径；写入临时发布目录，全部成功后再发布资源与清单。失败必须非零退出，保留旧发布的资源与清单一致。将检查接入正式构建命令。

达标：缺图、坏图、尺寸不符、重复 ID 均可重复地失败；故障后上一版输出哈希不变；正常构建可复现，无无主残留文件。

### 4. P1：展示页与产品是两套实现，状态检查不能互相证明

- 展示页使用 `.button-primary`、`.slot` 及内联样式；产品使用 `.v2-button.primary`、`.v2-slot`，并受原有全局 button 规则影响。
- 展示页有次要/危险按钮禁用图，产品对应类未使用这些禁用资源，只继承全局 opacity。
- 展示页 `:90` 的 focus 背景覆盖先前 hover/active 背景；实测已聚焦再悬停仍显示 focus PNG。焦点应与按下、悬停叠加，而不是取代。
- 24 个可点击槽位实际是 `DIV`，`tabIndex=-1`，没有 role；无法通过常规 Tab 聚焦操作。
- 复选框仅改变 class，没有名称、checkbox role 或 aria-checked；模式图标仅展示，没有模式切换行为。
- 加载、冷却、无资源、品质/锁定/装备标记、边缘 tooltip、长文本等尚无完整组合演示。

修改要求：抽取同一控件实现供游戏和展示页共同使用；采用原生按钮/输入或完整语义与键盘操作，焦点环独立绘制。用实际图标和长文本验证组合状态。

达标：展示页可直接证明产品控件的状态行为；Tab/Enter/Space、方向键网格选择与焦点显示正确；所有关键状态都有可操作用例。

### 5. P2：没有可维护的母版生产链，也没有完整发布入口

- `assets/ui-source/v2/masters` 全部为扁平 PNG。`build_ui_v2.py` 是复制与哈希工具，无法修改形状参数后再生母版。不能将目录名 masters 作为“可编辑母版完成”的证据。
- 源清单缺乏具体来源及适配记录，consumer 多为概括文字，不能追踪到实际组件。
- `apps/web/vite.config.ts` 普通构建仅包含 index.html；本轮标准构建产物没有展示页。当前 8612 可访问该页不能证明新构建可部署该入口。
- `package.json` 的 build/assets 没有接入 V2 检查或生成步骤。

修改要求：简单图形保留 SVG/CSS/参数化生成源；插画保留分层或其他实际编辑源；补来源、导出参数、使用者和缺失项。通过显式构建入口发布控件页，或明确独立 QA 构建命令，保证干净构建可重建。

达标：修改一个母版参数即可稳定重建相关输出；新环境执行文档命令可获得可访问的展示页和游戏；资源更新不会因手动遗漏而留在旧版本。

### 6. P2：原有直观 UI 问题仍未解决

1280×720 实测，小地图外框右边界 x=1268，画布右边界 x=1280，向外溢出 12px。`style.css:95–96` 外框 164px 同时容纳边框、padding 和 150px 画布，尺寸不自洽。多个面板截图也未显示清楚标题。

修改要求：修正小地图内容尺寸/框体尺寸，明确标题层级和布局；同步检查 1024×576 下的主要按钮、文字和遮挡。

达标：地图与标记正确包含在容器内；所有面板标题可见；四尺寸下主操作可达、不被裁切。本轮四尺寸截图只证明旧界面实际状态，不构成 V2 响应式通过。

### 7. P2：交付报告应按证据重写

`open-world/docs/05-art/ui-v2-implementation/DELIVERY-FINAL.md` 中：

- “游戏接入 80%”与实测零使用不符；
- “五种背景”实际只有四个背景容器，缺真实场景；
- “失败保留上一版”与故障测试不符；
- “可编辑母版完成”没有对应源文件；
- “可正式验收”与自身列出的游戏未接入相矛盾。

修改要求：分别记录已生成、已接入、已验证，不自行把原本要求的实际接入与验证降为不阻塞的后续事项。录像未交付应记为缺项，不能将未经证实的工具限制作为通过依据。

## 三、下一轮整改顺序与技能

1. **先完成一张真实背包界面**：以 V2 母图落地框体、标题、三列布局、角色展示、图标、比较区、操作区。使用 `frontend-design`、`ui-ux-pro-max`；插画补绘时使用 `imagegen`，实际生成前读取该 skill。
2. **抽取并修好共享控件**：按钮、槽位、标签页、提示、状态条、面板管理与输入状态。使用 `interaction-patterns-components`，文案问题按需用 `ux-writing-content-design`。
3. **补母版与构建安全**：源文件、元数据、故障用例、原子发布与打包入口。沿用当前技术栈与工程工具，无需引入 Godot 或新 UI 框架。
4. **扩展到全部约定页面**：HUD、构筑及其余系统面板；不能在背包或展示页完成后就停下。
5. **完成全量视觉和交互复验**：四尺寸、五背景、真实游戏操作、共享状态、资源加载与短录像；最后核对报告、清理本轮临时文件。

既定风格继续是：**现代、色彩浓厚、鲜明卡通奇幻、暖冷对比、清晰大图标、轻巧午夜蓝面板、杏金主操作。以已接受 V2 为准，不恢复被删除的 V1 古铜雕花/旧式厚框。**

完整完成条件：实际游戏页面符合上述方向，控件共享且可操作，源文件可维护，构建能拒绝坏输入，发布可重复，报告逐项有证据。不得仅按文件数量、测试数量或声明百分比判定通过。
