# V2 最新实现：验收与视觉差异报告

日期：2026-09-29。

**结论：整体交付不通过。首要原因是实际 UI 与用户确认的 V2 参考图明显不符。** 本轮已经修复的工程问题可以单独关闭，但不能替代美术与页面构图验收。

本轮是在上一轮“修改方式”之后重新检查当前代码、临时构建和浏览器实际行为。用户在复验中再次指出“这个 UI 和参考图完全不同”，与本轮目视结果一致。

## 1. 首要问题：没有把参考图的视觉语言落实到游戏

对照：[V2 背包标准图](../../../05-art/ui-standard-v2-20260929/02-inventory-equipment.png) / [当前实际背包](bag-1280.png)。

| 维度 | 已确认参考图 | 当前实现 | 整改方式 |
|---|---|---|---|
| 装备美术 | 有材质、明暗、轮廓设计的武器护甲插画 | 六件装备仍是简单多边形、圆环、色块符号 | 重做为风格一致的正式装备插画，保留可维护来源；几何符号只可标为占位，不能计作美术完成 |
| 角色展示 | 角色是左列视觉主体，装备围绕角色组织 | 1280 下立绘较小，右侧装备位挤到背包边界 | 按参考图重定左列比例、立绘可见尺寸和装备位置，保证独立空间 |
| 窗口质感 | 薄双层描边、细腻明暗、明确分区和有限高光 | 基本为单一深蓝圆角底，缺少参考图的层次 | CSS 可以继续使用，但需实现相应层次、分区、边缘和光照表达；不要求所有框体都改成位图 |
| 背包与详情 | 图标有足够展示空间，详情由装备插画、属性及效果主导 | 网格很密，右侧大图只是放大后的几何符号 | 配合正式插画重新分配三列宽度和文字层级 |
| 构筑 | 技能顺序、库、详情与保存区清楚，可并行浏览 | 720px 高度直接改成上下堆叠，保存区在首屏之外 | 优先保留库与详情关系，局部滚动，保存操作固定可见 |
| HUD | 紧凑边缘布局，以世界和角色为主 | 仍沿用多块较大的矩形信息板 | 按 HUD 母图调整体积、位置、间距和信息密度 |
| 外观一致性 | 头像、立绘、战斗角色属于统一视觉系统 | 蓝发立绘/头像与场景中的橙发战斗角色不一致 | 明确当前角色外观映射，统一展示身份；不必照搬参考图角色身份，但不能各页面各用一个角色 |

颜色已回到指定色板，部分技能图标明显优于旧版本；这只是已完成的局部。**“使用相同色值”不等于“实现同一画风”。**

后续必须以真实运行页面与母图的并排目视对照为门槛，比较资产质量、比例、信息层级、框体与留白。不能再把替换背景色、增加角色 PNG 或资源数量作为主要通过依据。

## 3. 仍需关闭的具体问题

### P1：背包布局真实重叠，低高度操作区缺乏保障

位置：`apps/web/src/style.css:185` 起的 `.bag-v2`、`.doll-stage`、`.grid24` 和末尾媒体查询。

1280×720 下，护甲装备槽与背包第一格实际矩形重叠 **4px × 41px**。角色列的内部最小宽度高于低高度媒体查询给它的可用宽度；网格和槽位固定尺寸也没有统一约束。

1024×576 下改成整页单列，首屏只有角色和背包网格，详情和操作需继续滚动。构筑在 1280×720 下保存区 y=697–756，而面板底部 y=704；1024×576 更明显。操作可通过滚动找到，不属于按钮不存在，但未满足约定的清楚、固定可见保存区。

修复：以实际内容最小尺寸决定分栏；限制角色展示宽度；建立明确的局部滚动区和固定操作区。为布局增加槽位互不重叠、保存按钮可见的实际浏览器断言。

### P1：技能勾选后，草稿界面没有同步

位置：`apps/web/src/main.ts:168–171`。

真实操作：保存一次构筑后重新打开，取消勾选“旋风斩”。复选框变成未勾选，但 `.savebar` 仍是 `saved`，上方装配栏仍包含 `whirl`。内部 draft 更新了，页面没有重新渲染。

修复：勾选变更后同步渲染装配栏、详情和保存状态，并保留正确焦点；不要只更新 localStorage。回归必须通过 checkbox change 路径，不能仅测试“提前/延后”按钮。

### P1：快速切换背包时，装备预览回调抛错

位置：`apps/web/src/presentation.ts:310–323`。

两次浏览器运行都捕获：`TypeError: Cannot read properties of null (reading 'seq')`。关闭背包会清空 `currentPreviewToken`，异步 then/catch 却继续读取全局 token 并使用非空断言。

修复：每次请求捕获独立的局部 token，完成时验证该 token 是否仍有效；不要用可能已被下一次请求或关闭面板替换的全局变量来判定当前响应。catch 同样处理取消与失效，过期响应不得改写新装备详情。

验证：延迟预览响应、快速换装备及打开关闭面板，浏览器无异常，旧响应不会覆盖新详情。单独纯函数测试通过不能证明 DOM 联动正确。

### P2：确认弹层没有独立焦点范围

位置：`apps/web/src/main.ts:25`。

分解确认内“取消”按钮按 Tab 后，焦点跳到背包的关闭按钮，已离开确认框。当前循环检查整个 `#modal`，没有限定最上层确认层。

修复：焦点管理以最上层活动弹层为范围；确认框提供 dialog 语义，开启时移入焦点、关闭时返回触发分解的入口。Esc 分层修复应保留。

### P1：展示页“状态齐全”仍不代表状态可用

位置：`apps/web/src/showcase.ts`、`style.css`、`ui-components.ts`。

实测：

- 页面高度 2079px，视口 720px，body overflow:hidden；真实滚轮向下滚动后 scrollY 仍为 0。下部内容只能被自动化强制滚入，不能据此说普通用户能浏览全部。
- Tooltip 的 hidden 已变 false，但 computed display 仍是 none，尺寸 0×0，实际不显示。
- 网格方向键可以将焦点移动到“格子2”，按 Enter 后选中数仍为 0，没有选择处理。
- “禁用”槽位只有 is-off 类，disabled=false、aria-disabled 为空；其语义没有禁用。
- 加载、已装备等样本主要是状态名称或类名，不能证明实际反馈完整。
- 所谓第五个场景背景仍是纯色，不是真实场景背景。

修复：为展示页设置独立滚动容器；让 Tooltip 使用同一个可见性与定位实现；状态应有实际数据和行为；接入真实场景底。验收必须使用真实鼠标/键盘，不把程序性 scrollIntoView 的成功当作正常滚动通过。

### P1：构建仍可成功发布缺少必需 ID 的资源集

位置：`tools/build_ui_v2.py:26–96`。

已修复“清单列出的文件不存在”，但未校验“清单本身缺少消费者必需项”。独立沙箱实测：

- 从清单删除 skill-cut 条目：成功发布 23 项。
- 将 assets 改为 []：成功发布 0 项并替换上一版。

`art()` 会在实际使用缺失 ID 时抛错。仅验证输入列表自身合法，不能保证客户端所需资源完整。

修复：由实际内容目录和 UI 消费需求产生必需 ID 集合，校验集合覆盖；不要用“至少 20 个资源”替代。故障测试覆盖删除条目与空集合，失败时上一版哈希保持不变。

### P2：发布回滚仍可能留下新清单配旧文件

位置：`tools/build_ui_v2.py:109–133`。

本轮只在独立临时目录注入旧版本清理失败：新资源和新清单已经发布，删除 `.rollback` 时抛出 OSError。异常分支回滚了资源目录，却没有恢复清单，留下一个清单引用不存在文件的结果。

修复：明确提交点。提交前失败恢复资源与清单；提交完成后的旧版本清理失败作为独立清理问题，不执行单边回滚。或采用版本目录与一致的发布指针。补充发布中途和清理失败用例。

这是注入故障暴露的恢复问题，不是本轮常驻服务已经损坏。

## 4. 下一轮视觉整改的具体方向

1. 保留已修好的标题、边界、清单与基本焦点逻辑。
2. 将六件几何装备图替换为符合 V2 的正式插画，保持统一质感与光照。不要再把“新画过”直接等同“达标”。
3. 按 V2 背包重新设计三列比例、角色展示、装备位、网格和详情，先检查真实 1280×720 成品，再适配其他尺寸。
4. 构筑保持技能库与详情的清楚关系，保存区固定可见；修复勾选后的状态联动。
5. HUD 缩减空面板面积，统一头像、立绘与战斗角色的身份呈现。
6. 面板样式补上参考图的分区、层次和边缘表达。CSS 是可行工具，问题在实现质量，而非必须切成整张图片。
7. 完成以上视觉工作后，继续关闭异步预览、展示页和构建剩余问题，不能只修美术或只修测试。

目标依然是现代、浓厚色彩、鲜明卡通奇幻、轻巧午夜蓝面板、暖冷对比、清晰装备与技能插画。保留 V2，不恢复 V1，也不更换一套无关的参考图。
