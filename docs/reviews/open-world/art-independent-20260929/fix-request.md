# 深渊行者美术与 UI 整改：最终可执行文档

版本：V2｜日期：2026-09-29｜状态：待实施、待视觉验收。

**用户最新美术偏好：色彩更浓厚的卡通画风，类似《魔兽世界》。** 本文采用此偏好，替换此前“低饱和自然环境”的方向。参考其奇幻卡通表达，不改变现有二维斜视角、左右朝向、单人在线与客户端/服务端职责。

以下全文可一次复制给实现者。

```text
《深渊行者》美术与游戏界面完整整改任务

一、目标和现状

本轮首要目标：把画面做成风格统一、色彩浓厚、具有厚实卡通体积感的奇幻动作游戏。用户喜欢类似《魔兽世界》的画风；以此作为美术方向。保持现有二维斜视角、角色左右朝向与在线成长架构，不因画风调整改成3D或多人共享世界。

当前视觉验收未通过。实测问题包括：菱形棋盘地形、几何树房、银灰厚边框、游戏内面板缺标题、小地图越界、装备图标身份错误。此前报告中的“无棋盘格”“HUD已改为1px细线”“所有图标符合身份”“7/10完全通过”不能沿用。

本轮修改的是美术资源、表现、界面和布局。成长通关、接口数量、测试通过率及色板token数量不作为美术达标证据。

二、美术方向和必须使用的关键词

中文关键词：
色彩浓厚、鲜明卡通、厚实奇幻、类似魔兽世界的美术气质、夸张比例、厚重轮廓、手绘材质、强明暗体积、暖冷对比、丰富区域色彩、史诗冒险、清晰战斗、游戏化界面。

英文关键词：
stylized high fantasy; rich saturated colors; chunky silhouettes; exaggerated proportions; hand-painted textures; strong value grouping; warm-cool contrast; epic adventure; readable combat; illustrated fantasy UI; Warcraft-inspired visual direction.

所有概念图、素材筛选、生成提示、绘制说明和视觉评审都使用这些关键词，并注明二维斜视角、统一光照、实际游戏尺寸和用途。不能只在文档标题加入关键词，实际素材仍沿用原型几何或低饱和灰绿方案。

具体表现：
1. 形体厚实：树干、岩石、建筑、武器和护甲具有明显体积与夸张轮廓，避免细碎、单薄、均匀圆点式造型。
2. 色彩丰富：区域具有鲜明主色与辅助色；草地、道路、屋顶、角色和魔法不混成同一片灰绿。
3. 手绘材质：使用成组明暗、适量纹理、边缘磨损和受光面，视觉细节在实际尺寸下仍清楚。
4. 光照统一：首个样板统一左上光源、暖亮部和偏冷暗部；接地阴影让角色、树石和建筑站在同一个空间。
5. 清晰优先：浓厚色彩不等于所有物体都最亮最饱和。背景、人物、危险和奖励按用途分配明度与饱和度。
6. 界面来自世界：使用雕刻石材、古铜、木材、皮革、卷轴和符文的卡通化表达，所有组件属于同一套材质语言。

三、初始色彩与字体规则

首个样板采用以下基调，作为绘制起点，需在组合场景中确认：
- 森林主色：#3D7C48，浓郁林地绿。
- 草地受光：#83AE42，明亮黄绿。
- 道路/木石暖部：#B77C43，暖赭石。
- 奖励/主要强调：#E3AC45，琥珀金。
- 魔法/水域：#3D88BD，鲜明蓝。
- 遗迹/深渊：#7852A1，奇幻紫。
- 危险：#D85E43，红橙。
- UI深底：#243641，深蓝墨色；正文采用清楚的暖浅色。

这是区域与功能色，不要求八种颜色同时铺满每一屏。林地可以绿、暖土、蓝魔法为主；深渊可以紫、冷石、橙火为主。保持同一笔触、造型和光照，允许不同区域有强烈身份。

生命、灵力、敌方危险、选中与稀有奖励各有稳定语义，并配形状或符号，不只靠颜色区分。当前区域背景不得抢走人物和危险提示。

正文先用现有可读的中文字体。标题与游戏字标另做厚实、清楚的奇幻处理；只使用有许可依据的字体或绘制字形。正文不使用难读装饰字。

四、场景与地图模块

使用level-design及game-design-fundamentals。

处理内容：
1. 替换scene.ts/drawChunk里的纯色菱形地面，使用草地、泥地、石路、边缘过渡与破损变化。逻辑网格保留，视觉网格不得明显暴露。
2. 道路具有自然宽度、转角、分岔和沿边植被，不采用连续台阶式锯齿作为主要造型。
3. 树木有粗树干、大树冠和成组亮暗叶片；岩石有受光面、暗面和厚实轮廓；建筑有屋顶、墙、门窗、基础和材质关系。
4. 场景具有前景边缘、中景战斗与远处地标。通过树石、旗帜、灯火、石门和遗迹建立地点身份。
5. 先制作营地出口—战斗空地—遗迹入口的短路线，不先铺满三个区域。
6. 摄像机不能持续看到地图绘制边缘外的大块纯色。用自然边界、远景或合理视野构图处理，不能隐藏可通行区域的问题。
7. 外观摆放与碰撞、导航、交互位置保持一致；美术缩放不改变世界坐标单位。

落地：apps/web/src/scene.ts、packages/content/maps/、环境图集及资源清单。

达标：隐藏HUD后，画面本身是浓厚卡通奇幻场景；道路和入口可辨、有空间层次；没有棋盘地面和纯几何树房观感。

五、角色、敌人与动画模块

使用game-design-fundamentals，按统一风格板检查。

处理内容：
1. 从现有资源中选取一个角色和首批四类敌人，检查其轮廓、体积、色彩与新环境是否协调。
2. 偏Q版角色可以复用，但不因为已有资源而强行固定全部新画风。允许选择更厚实的角色、强化武器与护甲，或记录必要重绘任务。
3. 统一脚底锚点、受光方向、色温、阴影、轮廓清晰度和实际显示比例。
4. 普通、精英、首领通过轮廓、体型、装备或附属造型区分；颜色变化只是辅助。
5. 检查待机、移动、攻击、施法、受击和死亡；左右翻转时文字与血条不翻转。

落地：角色图集、asset-manifest/catalog.json、scene.ts的角色表现。

达标：动画无明显跳位或漂浮；角色与环境像同一作品；敌群中能定位主角并识别敌人类别。仅凭“旧代码未改”不得填写锚点已验证。

六、战斗特效和掉落模块

使用game-design-fundamentals；需要新栅格概念与贴图时使用imagegen，随后人工/工程适配。

处理内容：
1. 为六个样板技能补齐前摇、释放、轨迹、命中和消散。
2. 使用有厚度、方向与节奏的卡通光效、斩击、火焰、冰与符文，减少只用圆点和细圈表达所有技能。
3. 玩家技能可以鲜明浓厚，但敌方危险具有稳定边界、前摇与作用时点；与地面保持亮度差。
4. 限制重叠特效和伤害数字，不能让角色与敌群淹没在一片高亮中。
5. 掉落有清楚的物品/奖励身份和短获得反馈。正式装备属性仍由服务端生成，表现不能提前虚构正式结果。
6. 表现消费战斗事件，不用动画结束发奖励，不改变伤害、射程或资产结算。

达标：短录像中能看出六技能的用途与命中；角色、危险、敌群变化和掉落保持可辨，具有割草反馈。

七、战斗HUD模块

使用frontend-design、ui-ux-pro-max及interaction-patterns-components。

处理内容：
1. 实际替换当前26/20px的银灰panel-frame外壳，制作厚实卡通奇幻UI套件。使用克制的古铜、石材、皮革或雕刻细节，文字区域保持干净。
2. 厚实来自造型、材质和层次，不是让每个信息框都增加大边框。
3. 顶左集中头像、生命、灵力与关键状态；主目标压缩为一条核心提示；底中技能栏是战斗操作中心。
4. 手动/半自动/全自动与技能栏视觉关联，显示实际行为和停止原因，不保留独立大信息盒子。
5. 小地图和系统入口属于次级信息；减少文字堆叠和等权矩形。
6. 主要控件覆盖普通、悬停、按下、选中、禁用、等待与键盘焦点状态。

落地：presentation.ts、style.css、UI图集与manifest。

达标：实际画面采用新材质体系，第一视觉焦点是角色和战斗；玩家能迅速找到生命、技能、目标与模式；没有旧银灰边框残留。

八、背包、装备与构筑模块

使用frontend-design、ui-ux-pro-max及interaction-patterns-components。

处理内容：
1. 背包采用左角色与四槽位、中物品、右比较与主要操作；角色装配和选中物品是视觉中心。
2. 道具槽位使用同一材质；降低空槽位对比，品质、锁定、已装备与强化标记保持一致。
3. 装备比较同时展示属性和效果得失，不用总战力箭头代替构筑理解。
4. 构筑面板突出当前装配和顺序；技能库次级分组。装配、升级与排序在视觉上区分，减少等权卡片和密集按钮。
5. 确认层与父面板同画风；危险操作清楚，反馈和恢复入口可操作。
6. 确定title后才生成标题栏，背包、构筑和远行等标题必须可见。

达标：一眼能看懂当前装备、选中物品和当前构筑；面板无空标题、越界和被边框压住的文字；主要状态明确。

九、图标、资源清单与来源模块

使用frontend-design检查风格与身份；用资源构建工具核对。

处理内容：
1. gear-bow.png与gear-blade.png目前字节完全相同，穿云弓实际显示剑。替换为真实弓图，并核对来源与哈希。
2. skill-lance.png与skill-bolt.png目前相同。核对设计语义并处理视觉身份；不能用复制已有图片伪装完成新素材。
3. 按同一画风规范绘制武器、护甲、饰品、核心、技能和系统入口；统一描边、光照、背景与透明边距。
4. 24×24原图放大不等于高清素材。先查高分辨率原图；没有时重绘或生成后适配，在实际48—56px等显示尺寸评审。
5. 每个实际使用ID记录来源、许可、原尺寸、目标尺寸、哈希、动作/切片、锚点和适配内容。
6. 区分直接复用、需要适配、需要新增和本阶段不使用。不直接混用画风冲突的素材包。
7. 正式资源缺失或身份错误不能静默回退为文字；构建校验必须指出缺项。

落地：packages/asset-manifest/、tools/build_assets.py、apps/web/public/art/。

达标：文件存在、加载成功、内容身份正确、画风一致四项同时成立；所有正式使用资源有记录。

十、登录、地图、任务、首领与设置模块

使用frontend-design、ui-ux-pro-max、ux-writing-content-design；场景入口采用level-design。

处理内容：
1. 登录制作浓厚奇幻卡通主视觉与游戏字标，账号表单融入构图，与游戏内UI同材质。
2. 地图标记在世界和小地图中一致；据点、入口、敌群和首领具有清楚的形状与色彩。
3. 小地图按实际内容宽度布局，目前四个尺寸向右越出8px，必须消除。
4. 首领入口具有专属场景与造型；首领血条、危险和胜负画面与整体画风一致。
5. 任务突出主目标，正文简洁；设置和提示复用同一UI套件，不再各做一套。
6. 检查1280×720、1600×900、1920×1080；若支持1024×576，另做低高度布局或明确最小窗口限制。

达标：启动、营地、野外、背包、首领像同一作品；地图无溢出，标题和操作不被遮挡。

十一、实施批次

A. 修正确认状态与美术方向文档。将浓厚卡通、类似魔兽世界等关键词写入资源与绘制任务，移除冲突的低饱和目标。
B. 先交一张风格板：角色、敌人、树石建筑、地面、UI框、按钮、图标、特效同板展示；标明实际可用资源与需要制作项。
C. 完成一段营地出口到遗迹空地的真实视觉样板，包含战斗和完整HUD；先解决地形、角色/环境一致性和UI外壳。
D. 样板视觉通过后扩展主要面板、六技能与其他区域。未通过时调整样板，不继续批量铺内容。
E. 进行多分辨率、动画与全部实际资源身份检查，再给出本阶段视觉验收结果。

十二、交付与通过标准

交付：
- 美术风格板及完整关键词。
- 真实资源、来源与适配清单。
- 同机位战前、战斗中、掉落三张实机截图。
- 背包、构筑、登录与主要分辨率截图。
- 15—30秒实际运行录像；不要用概念图或渲染视频冒充游戏实现。
- 本轮修改位置、已完成项、未完成项、验证结果及回退说明。

通过标准：
1. 色彩浓厚、厚实卡通、手绘材质和夸张奇幻形体实际可见。
2. 世界、角色、UI与特效属于同一套美术语言，区域色彩丰富且有身份。
3. 无测试棋盘、纯几何树房观感、旧银灰框、错误图标、文字占位和空标题。
4. 隐藏HUD后世界仍有道路、场所、地标和层次；打开HUD后角色与战斗是第一焦点。
5. 敌群与特效出现时，主角、危险、敌群变化和奖励可辨。
6. 所有支持尺寸无面板/小地图越界或遮挡主要操作。
7. 完成实际视觉评审后逐项填写通过状态；不使用无定义的完成百分比。
8. 视觉与功能分别验收。成长通关、编译、测试和资源数量不能替代美术验收。

保留用户存档、源码、未提交改动、既有交付包和cloudrealm；只清理本次QA临时文件，并报告实际清理体积。
```
