# 远行界面整改 · 2026-09-30

原问题：示意图中的风景变成文字占位，面板大量留空，地区选择与筛选没有实际行为，副本栏混入野外地区，详情始终显示首个地区。

现在采用实际生成的草原／森林／裂谷插画，地区缩略图、卡片和详情共用对应素材。面板补齐罗盘、蓝色缎带、角饰、蓝金边框、选中描边、渐变字幕层、独立锁定标识、详情分隔和有层次的出发按钮。图片来源、完整提示词和可复现资源构建见 `open-world/assets/ui-source/travel/source.json`，使用内置 imagegen；构建没有截取概念图来充当整张交互界面。

地区选择、探索／副本切换、开放状态筛选、全局搜索、分页和右侧详情均有实际行为。当前地区的副本来自现有首领地图，锁定条件来自已确认快照。首领仍需清剿六名敌人、步行到结界并按 E 确认。菜单浏览不修改资产、奖励或解锁进度。

当前实际内容是三个地区，每区一个野外入口和一个首领试炼。单条结果扩大为风景主卡，多条结果采用六项分页。18 地区的截图是明确标记的布局压力样本，未加入正式内容或用户数据库；1280×720 下六项全部可见，1024×576 下网格独立滚动，分页和详情操作区保持可见。

最终正常发布构建通过；33 项规则／界面状态回归通过。`node tools/accept-travel-browser.mjs --static` 另外直接验证打包后的静态页面与真实 API，四尺寸截图为 `release-travel-*`，结果为 `release-result.json`。1024×576 的详情文字不再被弹性布局压出半行。服务已重新启动，游戏页面和代理 API 健康检查均返回 200，登录自启保持开启。

真实 PostgreSQL／浏览器操作经过注册、建角、前往远行之门、E 开门、浏览锁定地区、切换副本、筛选、搜索、键盘操作和实际进入原野。出发请求使用真实接口，额外延迟用于核对禁用和加载态。浏览器没有页面错误。截图与逐项结果见 `result.json`；临时数据库停止并清理，常驻库未写入测试账号。角色世界地形与本轮地区预览插画分别维护，这次整改针对远行菜单。

恢复／重建：先在 `open-world` 执行 `pnpm service:stop`，再 `pnpm build`，最后 `pnpm service:start`。游戏入口为 http://127.0.0.1:8612/ ，刷新后重新打开远行界面。
