## 阻塞问题与修复要求

### 1. P1：旧装备预览覆盖当前装备数值

位置：`apps/web/src/presentation.ts:297`。

复现：选择守望轻甲 A，延迟 A 的真实预览响应；选择穿云弓 B 并先返回 B；最后返回 A。详情标题仍是穿云弓，服务端总攻击预览却由正确的 `21 → 19` 被改成 `21 → 21`。旧失败响应同样可污染当前面板。

修复：每次查询记录物品 ID、角色 revision、面板实例/请求序号；更新结果前逐项匹配。取消旧请求或丢弃过期结果，成功和失败均走相同守卫。

达标：A/B/C 快速切换、旧响应延迟、旧请求失败、关闭后重开都不会覆盖当前选中物品；正式属性与最新服务端预览一致。

### 2. P1：分解单击直接执行，不可恢复操作没有确认

位置：`apps/web/src/main.ts:98`，`apps/web/src/presentation.ts:293`。

复现：选择未装备且未锁定的穿云弓，点击分解一次，立即发送一次正式分解命令；背包从 6 件变成 5 件，没有确认步骤。

修复：增加有物品名称、特殊效果、分解所得及不可恢复说明的确认流程。所得读取真实服务端预览；不要在 UI 猜值。默认焦点放取消，确认时再提交，等待期间防重复。

达标：第一次点击只打开确认；取消不发写请求；确认只提交一次；失败保留物品与选择上下文。

### 3. P1：HUD 子节点仍频繁重建，键盘焦点丢失

位置：`apps/web/src/presentation.ts:163`、`:208`、`:215`；`apps/web/src/main.ts:29`、`:43`、`:119`。

复现：将焦点放在半自动按钮，等待 650ms，按钮已断开 DOM，焦点丢失；系统入口也被换成新节点。关闭背包后焦点落在 BODY。虽然技能按钮稳定，但“HUD 稳定 DOM、焦点不丢失”的实施声明不成立。

修复：角色、目标、模式、系统入口、恢复按钮均稳定挂载；按字段更新。只在成员列表确实变化时重建对应列表。打开面板时保存触发控件，关闭时恢复该控件或其稳定后继，不能被关闭操作的内部按钮覆盖。`bindTips()` 使用一次性绑定或事件委托，不能每轮对持久节点叠加监听器。

达标：键盘连续导航和停留不会被定时更新打断；点击/按键能稳定触发；关闭面板回到触发控件；悬浮/焦点提示的监听器数量不随运行时间增长。

### 4. P2：按键绑定保存后，技能槽仍显示旧按键

位置：`apps/web/src/presentation.ts:182`、`:188`、`:228`。

复现：把技能 1 改绑成 Q，本地设置是 `KeyQ`，技能槽角标仍显示 `1`。原因是角标只在技能 ID 列表变化时更新。目标详情、附近交互提示也继续硬编码 WASD/E/空格/B/K。

修复：所有键位文案来自唯一绑定表，角标按字段更新。检测重复绑定和保留键，提供取消与恢复默认。

达标：改绑后槽位、tooltip、附近提示、教学与实际输入一致，刷新后仍一致。

### 5. P2：关闭构筑面板静默丢弃草稿

位置：`apps/web/src/main.ts:21`、`:43`、`:96`。

复现：移除一个技能后，装配数从 4 变成 3；提示存在未保存调整。按 Esc 关闭再打开，恢复为 4，没有保留或放弃选择。

修复：将草稿与正式快照分开，关闭时保留草稿或明确选择放弃；保存失败不能当成功关闭面板。升级导致面板重绘时也保留草稿与焦点。

达标：未保存、保存中、失败、成功四种状态明确；关闭和重开不会意外丢失调整。

### 6. P2：面板标题为空，边框与内容排版不合格

位置：`apps/web/src/presentation.ts:263`，`apps/web/src/style.css:87`、`:103`、`:179`。

实际问题：`head` 在 title 赋值前生成，背包/构筑等可见 h2 为空，尽管 aria-label 正确。小地图固定 150px 画布超出其 172px 面板扣掉边框和内边距后的内容区；背包容量说明跨入右侧详情栏；主按钮九宫格显示为狭窄条纹，内边距不足。多个面板反复使用粗顶框，占据较多空间。

修复：内容确定后生成标题；统一计算九宫格边框与内容尺寸；小地图按内容区适配；背包网格列使用可收缩尺寸、说明正常换行；主按钮重新核对切片、边框宽度与文字留白。

达标：四档视口标题可见、图文不越框、不跨栏、无误裁切；按钮的文字、正常/焦点/按下状态清楚且稳定。

### 7. P2：HUD 占比不符，缺少尺寸适配

本次统一计算 vitals、tracker、minimapbox、modebar、skillbar、sysbar 的 boundingRect 面积之和除以视口面积（不含提示、奖励与 tooltip，不扣透明部分）。

| 视口 | 常驻边界占比 |
|---|---:|
| 1280×720 | 22.01% |
| 1600×900 | 14.09% |
| 1920×1080 | 9.78% |
| 1024×576 | 34.39% |

1280×720 超过原方案的 20% 初始目标，也与实施记录的 18–19% 不一致。该目标是布局预算，不能单独决定审美；画面仍能看到战斗，但小窗口被大量固定框占据。

修复：收紧框体与空白；目标与模式渐进展开；按视口重排、调整小地图和辅助区域，而非仅靠字变小。明确支持的最低窗口尺寸并检查长角色名、停止原因与首领状态。

达标：720p 达到目标或记录经实际视觉评审接受的新预算；正文与辅助文字不为压占比而缩小；小窗口仍能看清危险、自己和技能。

### 8. P2：世界视觉与战斗反馈仍未整改

证据：`flow/05-battle-busy.png`。道路、地标、建筑仍是测试色块，菱形棋盘强烈；敌人空间和表现缺少区域特色，血条、文字与危险提示未完成密集战斗分层。

修复：按现有素材实际可用情况做一张组合场景，统一比例、锚点、遮挡与道路；再落实遭遇编排、掉落图标、普通血条筛选、飘字合并与并发预算。缺失的穿云弓装备图标和星矛技能图标列入补齐清单。

达标：玩家能从画面辨认主路、障碍、目标和危险；密集战斗不遮住角色与危险时点；不能仅换 HUD 颜色就宣布游戏画面已整改。

## 模块范围判定

- 资源与图标、HUD、背包、比较、技能构筑：**部分通过**。
- 模式、自动设置、目标、小地图、系统入口：**部分通过**，稳定性/状态说明/布局仍需修复。
- 登录、面板管理：**部分通过**；模态 Tab 与暂停通过，焦点恢复与部分表单语义没有完整通过。
- 首领准备、死亡反馈、新手教学：**基础实现，不足以确认模块达标**；未验证实际失败原因归因和真实新玩家理解。
- 场景、掉落、飘字、遮挡、密集战斗反馈：**未完成本轮整改**。
- 分辨率：本轮补了四档边界实测，**不能据此判定响应式视觉完成**。
- 两小时稳定性、Windows 实机、正式部署、真实新玩家试玩：**未验证**。

## 下一批建议

先修三项 P1（预览关联、分解确认、稳定 DOM/焦点），同时修标题与键位；随后处理草稿、比例、九宫格和面板排版；最后以真实组合场景完成世界与战斗反馈。修复后重跑对应复现路径，并用同一构建截图复验。不要以既有 33 项测试通过代替这些 UI 验收。
