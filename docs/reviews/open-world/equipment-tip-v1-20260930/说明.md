# 装备 Tips 第一版 · 2026-09-30

第一版已接入背包装备格。提示是独立的蓝金信息卡，包含装备插画、名称与强化等级、装备／锁定状态、基础与强化加成、生效攻击／护甲、特殊效果，以及替换后角色攻击／护甲的变化。样例卡与四尺寸实机截图见本目录。

数值通过只读鉴权接口 `/api/gear/:id/tip` 返回，装备贡献与正式角色构筑共同使用规则层的 `gearContribution`。客户端不实现另一份强化公式。接口只允许查看自己的行囊装备，不发奖、不换装、不扣费。提示响应按装备 ID 和角色 revision 校验；缓存有版本和时效，晚到回包不能覆盖新宿主。

提示归属采用宿主级 pointer／focus 状态，鼠标移动到按钮内部子元素不会误关闭；可以把鼠标移入提示阅读。选中装备重绘后恢复焦点，鼠标离开时恢复仍有效的键盘焦点提示。第一次 Esc 收起 Tips，第二次关闭背包。提示绑定 `aria-describedby`，随缩放／滚动重新定位，优先放在装备网格外侧，空间不足时按视口边界调整。

同时修正背包右侧对比：使用已有服务端换装预览，而不是把两件装备的基础数值当作角色收益。强化 +3 的穿云弓样例显示攻击 7＋6＝13、护甲 0＋3＝3；替换基础苍风之刃后角色攻击 21→25、护甲 4→7。

验证：25 项真实数据库测试和 21 项核心回归通过。开发构建与打包后的页面分别验证四个尺寸、状态与数值、图标内部移动、提示可悬停、鼠标／键盘归属、选择后焦点、Esc 层级和晚到回包；无页面错误。`result.json` 与 `release-result.json` 保存原始结果。验收默认只输入账号；强化／锁定样例只初始化在独立临时数据库，完成后已停止并删除，未写入常驻玩家库。

Windows 本次一体构建的图片重发布阶段受到资源目录占用阻塞。25 个已有 UI 文件已逐一核对运行清单与原始来源哈希，再执行相同的 Vite 发布步骤并通过静态产物验收。运行服务已恢复并加载新 API／界面，页面与代理 API 健康检查均为 200。

复现：在 `open-world` 中执行 `node tools/accept-equipment-tip.mjs`；已有发布构建可追加 `--static`。第一版装备信息卡入口为背包格子，其他装备入口后续可复用这个组件与提示控制器。
