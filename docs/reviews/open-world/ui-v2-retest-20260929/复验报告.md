# V2 UI 整改复验报告

日期：2026-09-29。结论：**有实际改动，但完整整改验收仍不通过。**

本轮不能继续沿用上次“游戏完全未接入”的判断：当前游戏已加载 `/art/ui/v2/` 下的新面板、主按钮、装备栏槽位与关闭按钮。但这次实现主要是旧页面换色及局部换图，没有完成用户要求的 V2 页面重构、共享组件、统一生产链及实机交互验收。

## 一、本轮实测范围

- 常驻 8612 首页和展示页；首页实际面板已引用新路径。
- 当前源码单独构建，在独立临时 PostgreSQL、临时角色及随机 API 端口运行；没有写入用户常用账号。
- 四尺寸：1280×720、1024×576、1600×900、1920×1080。
- 每种尺寸实际打开 HUD、背包、构筑、设置、目标、自动设置、出行；另外检查野外画面。
- 检查标题、资源请求、小地图边界、焦点与关闭行为；对构建做缺图及坏图故障测试。
- TypeScript 检查和 Vite 构建成功。浏览器未捕获 pageerror。建号过程中的未登录 401、角色尚未创建 404 不判为资源错误。
- 本轮没有将数值成长、战斗性能或完整资产事务判为已验证；重点为 UI 和指定构建缺陷。

## 三、仍阻塞交付的问题

### P1-01：真实画面仍停留在局部换色、换框，没有落实 V2 核心构图

对照 [本轮背包](bag-1280.png) 与 [V2 背包标准图](../../../05-art/ui-standard-v2-20260929/02-inventory-equipment.png)：

- 角色仍是很小的旧战斗图，未形成左侧角色与四装备部位的展示关系。
- 中间背包继续使用棕色旧槽位，左侧装备槽却已换深蓝，同一页面出现两种皮肤。
- 右侧没有独立装备大图，比较与效果层级仍较弱。
- 标题空白、细碎旧图标、宽度及字号关系未按 V2 重构。
- 构筑仍是原有多列列表，未落实 V2 中选中技能详情与清晰保存区的关系。

代码定位：`open-world/apps/web/src/style.css:198–200` 附近，`.slotbtn` 使用新图，`.cell` 仍使用 `/art/ui/item-slot.png`。`presentation.ts:14–15` 仍从旧图标目录读取技能、装备；这些资源是否可复用应以画面质量决定，不能仅修改目录名当成新美术。

修改要求：完成真实背包、构筑与 HUD 的布局、层级和插画适配，再扩展系统页面。完整替换应替换的旧槽位和框体；不要通过铺一层新的背景色宣布页面完成。

通过条件：实际运行页面具备 V2 的轻巧蓝色面板、清晰大图标、角色展示、装备大图、明确标题与主操作，且数据与交互真实。无需照搬母图演示数值或指定相同角色身份。

### P1-02：六类系统面板标题为空，是确定的渲染错误

四个尺寸下，背包、构筑、设置、目标、自动设置、出行的 `.panel-head h2` 都是空字符串。虽然 dialog 的 aria-label 正确，视觉标题仍然缺失。

原因：`presentation.ts:249` 初始化 `title=''`；`:261` 先将它插入 `head` 字符串；`:262` 之后才按页面赋值 title。之后拼接的是已经生成的空标题。

修改要求：确定 title/body 后再生成头部，或以统一面板组件接受最终标题。

通过条件：六类面板均出现正确的可见标题，四尺寸验证；增加一个覆盖真实渲染顺序的针对性用例，不能只检查代码里存在标题文字。

### P1-03：小地图所谓“修正为 140”没有解决溢出

1280×720 实測：外框右边界 x=1268，画布右边界 x=1280，仍向右溢出 **12px**。

原因：`style.css:97–98` 附近把外框宽度从 164 改成 154，同时把画布从 150 改成 140，但依旧没有把两侧 20px 边框和 6px padding 纳入内容宽度计算。全局 box-sizing:border-box 下，可用宽度只有 102px。

修改要求：统一外框、边框、内边距与画布的尺寸模型；可使用细边框及自适应画布，不要继续同时缩小两边的固定值。

通过条件：四尺寸下实际 bounding rectangle 和目视检查均无外溢；标记被正确包含。

### P1-04：资源生产链出现分叉，之前的故障保护没有修复

当前同时存在：

1. `assets/ui-source/v2` → `build_ui_v2.py` → `/art/ui-v2/` → `ui.v2.json`，43 张旧交付图片；
2. `create_v2_components.py` → `/art/ui/v2/`，11 张新控件图片；主游戏改用这套；
3. 展示页仍消费第 1 套，游戏与展示页不是同一实现。

本轮与上次的源目录哈希、43 张输出目录哈希完全一致。新的 11 张控件没有进入 `ui.v2.json`，标准 package build/assets 也没有纳入新生成步骤。因此“清单验证成功”不能证明游戏正在用的资源完整。

故障复测仍失败：

| 输入 | 返回与结果 |
|---|---|
| 完整输入 | `(43, 0)`，重复构建一致 |
| 缺少主按钮源图 | `(42, 0)`，仍报告全部验证成功 |
| 主按钮替换为非 PNG 字节 | `(43, 0)`，损坏文件仍复制到输出 |

`build_ui_v2.py:70–72` 仍跳过缺图；`:151` 后仍直接覆盖清单且只检查文件存在。以上故障在本轮独立临时目录复现，未破坏工程素材。

修改要求：收敛到一个输入清单、生成入口、运行时清单和资源解析入口；先检查完整输入、解码、尺寸和必需状态，在临时目录完整生成、验证后发布。失败非零退出且上一版保持一致。展示页与游戏共用实际实现。

通过条件：游戏所用资源全部可追踪；缺图、坏图、尺寸错误等都会阻止发布；干净构建能重建当前游戏及展示页。

### P1-05：新增验证脚本会误报“旧资源为零、接入完成”

本轮执行 `tools/verify_v2_integration.py` 返回 0，并声称旧版资源残留 0。

但 `:47` 用旧路径计数减去新路径计数：旧槽位 1 次、新槽位 1 次相抵为 0。这两条路径不是包含关系，不能相减。浏览器和源码均证实 `.cell` 仍用旧图。

另 `:64–84` 的代码检查无论分支是否打印失败，最终都返回 True。检查文本出现 140 也无法证明布局正确。

修改要求：分别检查旧资源引用；错误分支必须影响退出码；加入浏览器 computed style、边界及实际资源加载断言。把此脚本限定为它真正能证明的静态条件，不得以它代替风格验收。

通过条件：保留一个旧槽位或制造边界溢出会被对应检查识别；检查失败明确非零退出。

### P2-06：共享控件、焦点恢复与展示页缺项仍未完成

- 实测背包按 Esc 关闭后焦点落到 BODY，没有返回触发入口。普通 Tab 循环可用不代表整个焦点流程完成。
- 展示页仍只有四个背景，缺真实场景背景。
- 24 格展示网格仍为不可聚焦 DIV；复选框没有名称、checkbox role 或 aria-checked。
- 展示页仍有旧按钮透明断层与深色文字问题；修复另一目录的主按钮没有修复这套资源。
- 普通 Vite 构建产物仍不含 ui-v2-showcase.html。

修改要求：共享组件后只保留一套状态实现；关闭面板恢复到重新渲染后仍存在的入口，可记录稳定入口标识而非只保存将被替换的 DOM 引用。补齐实际五背景、键盘及状态用例，并明确展示页构建入口。

通过条件：游戏与展示页一致；打开、Tab、关闭、再次操作的焦点链完整；展示页由标准命令构建后可访问。

### P2-07：过程图片进入 public，旧交付声明未纠正

新目录中包含 `button-primary-sample.png`（1355×721，980149 字节）和 `panel-sample.png`（100×100，13520 字节）。这是自动提取样本，约 970 KiB，本轮未发现游戏消费，却随 public 进入标准构建。应移出正式发布资产目录，按来源和任务归属决定保留或清理。本轮验收不擅自删除此前文件。

`open-world/docs/05-art/ui-v2-implementation/DELIVERY-FINAL.md` 仍保留“80%”“可正式验收”等旧结论，README 仍描述 `.v2-*` 的旧接入方法，与当前新目录路径不同。

修改要求：把实验样本与正式资源分开；更新使用文档、来源及生产流程；按逐项实际状态重写报告，不重复无依据百分比。
