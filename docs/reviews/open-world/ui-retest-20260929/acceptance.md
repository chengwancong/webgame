## 必须修复的问题

### P1-01 装备预览旧响应覆盖新装备，关闭时有运行异常

复现：选择守望轻甲，延迟它的真实接口响应；随后选择穿云弓并让弓的响应先返回。弓的正确预览是攻击 **21 → 19**，轻甲迟到后却变成 **21 → 21**，还错误标注“已装备”。选择名称仍是穿云弓。

原因：`presentation.ts` 预览回调读取共享的 `currentPreviewToken`，旧请求也使用最新请求的 token；并把当前 DOM 标记改写为该 token，相当于让旧响应冒充当前响应。关闭面板把 token 清空后，晚到回调仍对它执行 `previewStillCurrent`，产生空值错误。

整改：每次请求捕获不可变的局部 token；把该 token 放到本次新建的预览节点。回调只检查身份，不得替旧节点或旧响应重新盖章。成功、失败、切换装备、变更版本、关闭面板都用同一取消规则。禁止对可空 token 使用非空断言绕过检查。

达标：A/B 乱序成功、旧请求失败、关闭再打开、装备变更、版本变化全部保持正确选择；既无串数据也无永久加载和页面异常。必须使用实际 `renderPanel` 的端到端测试，不能仅运行 helper 单元测试。

证据：[预览串数据截图](final/preview-race.png)、[最终原始结果](final/result.json)。位置：`apps/web/src/presentation.ts:297`、`apps/web/src/preview-guard.ts:11`。

### P1-02 分解确认残留到其他系统面板

复现：背包选择穿云弓 → 分解 → Esc → 出发远行 → 点击野外区域。点击等待 30 秒失败，原因是 `.confirm-overlay` 拦截指针事件。此前关闭的是整个背包，但没有清除确认状态；新远行面板再次挂上了分解确认。

整改：建立明确的弹窗层级。Esc 先取消最上层确认，再处理父面板；确认绑定背包及具体装备，离开所属面板时结束该状态。打开确认时焦点进入取消按钮，关闭后返回分解入口。提交失败或等待确认时保持正确上下文，不无条件清除状态。

达标：确认取消、Esc、关闭父面板、切换目标、切换面板均无残留；焦点不能穿到确认层背后；分解只有明确确认后提交一次。确认中展示来自当前服务端预览的具体材料所得，不能只有“实际所得为准”。

证据：[复现实验结果](verified/result.json)、[确认截图](final/salvage.png)。位置：`apps/web/src/main.ts` 的 Escape/open 与确认状态；`apps/web/src/presentation.ts:346`。

### P1-03 保存失败提示玩家恢复，却把恢复入口放在遮罩后

复现：技能面板修改装配，阻断实际保存请求。界面保留面板并显示“保存等待确认，请恢复连接后重试”，但恢复按钮位于 HUD，被模态面板拦截。必须先用 Esc 关闭面板才可恢复；最终专项验证这一绕行可恢复成功。

整改：等待确认状态在当前面板提供可操作的恢复入口、保存状态及返回路径。恢复应查询或重试原 `command_id`，不要重新创建一次保存。保留待提交构筑，按原回执和新快照判断成功、拒绝或继续等待。普通按钮保持禁用原因清晰。

达标：请求未到服务端、已经提交但回包丢失、明确业务拒绝三种路径均能在当前面板处理；无重复保存、草稿丢失和“点击不到的恢复操作”。

证据：[等待确认截图](final/pending.png)、[最终原始结果](final/result.json)。

### P1-04 服务端拒绝据点记录，客户端提示成功

较早版本实际注入一个不存在的据点标识，服务端明确返回“据点不存在。”，随后 UI 却显示“据点已记录，失败后可在这里继续。”。最终版仍保留相同调用逻辑：`if(result)`。

原因：`write()` 的返回值已改为 `success/rejected/pending/busy` 字符串；后三者同样是 truthy。该项的服务端拒绝实测来自较早版本，最终版属于相同代码的复核，未再次进行专项请求注入。

整改：所有消费者按明确状态判断，成功提示只能出现在 `result === 'success'`。检查拾取音效、分解确认关闭和其他副作用，避免失败时仍播放成功反馈或销毁上下文。

达标：拒绝、忙碌、网络待确认均不显示成功；快照中的正式安全点不变；业务失败原因保留。

证据：[较早版本原始结果](independent-result.json) 的 `checkpoint_rejection`。位置：`apps/web/src/main.ts:119`。

### P2-01 可见标题为空，键盘焦点再次丢失

最终版背包 `h2` 内容为空。原因是先以空 `title` 构造 `head`，再在面板分支赋标题。HUD 虽保留了一些容器，却仍反复重建其按钮子节点；模式按钮和系统入口都不是稳定节点，键盘焦点丢失。

整改：确定面板标题后生成标题栏；DOM 的可见标题与 ARIA 标签一致。HUD 只更新文本、数值和属性，操作按钮仅在结构发生变化时重建。覆盖模式、系统入口、路线、暂停和恢复入口。焦点样式不能依赖每帧重新聚焦补救。

达标：所有面板标题可见；连续多轮 HUD 更新后节点、焦点和键盘操作保持；屏幕阅读名称与可见名称一致。

### P2-02 视觉、布局与素材仍未达到正式游戏 UI 标准

最新实际截图仍有明显问题：标题栏为空且装饰条占据头部；小地图画布越出面板右边界；世界地面主要是重复几何块面，缺少道路、地标和前景层次；穿云弓与星矛等资源使用文字回退。人物和部分图标已接入，不能据此认定资源管线与游戏界面完成。

较早固定版本在 1280×720 的六个 HUD 外接矩形面积合计约占 22.52%，1024×576 约占 35.19%，四个测试尺寸都出现小地图越界。该数值是外接矩形面积代理，包含透明区域；最终版本布局有修改，**不把这些旧数值算作最终性能或布局测量**。最新截图仍能直接看到小地图边界问题。

整改：先统一边框资源的九宫格切片、标题/内容安全区和按钮状态，再调整信息层级与分辨率适配。用容器实际内容宽度约束地图；为低高度屏幕折叠次要信息。补齐正在使用的装备/技能图标映射和占位状态标识。制作一个道路、墙体、遮挡物、敌群、掉落共同出现的组合场景后再扩大地图面积。

达标：1280×720、1600×900、1920×1080 无越界、遮挡主要操作与标题缺失；若继续支持 1024×576，必须有可用布局或明确最小窗口限制。所有正式使用资源均有正确映射，正常玩家页面不出现开发占位文字。密集战斗中角色、危险范围和拾取标记可分辨。

证据：[最新野外画面](final/field.png)、[最新背包画面](final/preview-race.png)。

1. 先冻结一个源码与资源构建版本，完成预览、确认层、恢复入口和命令状态修复。
2. 用实际面板与真实 API 重跑乱序、关闭、业务拒绝、请求未送达和回包丢失；页面异常必须为零。
3. 再验收稳定节点、标题、分辨率与正式资源映射。
4. 跑完整新玩家成长路线，并单独验收真正的浏览器、桌面和交付环境。

每个修复项需要提交实际修改位置、复现步骤、修复后的结果及截图；本轮不建议继续扩大内容规模。

## 完整成长流程最终结果

最终固定版本的真实浏览器流程通过：野外战斗、穿云弓装备与技能构筑、已提交报告回包丢失后的恢复、三个首领、回城领取及退出重新登录。重新登录后保留等级 4、金币 720、三个首领记录与装备。该正常路径未出现页面异常；专项乱序/关闭测试仍出现上述运行错误，两者不矛盾。

结果：[浏览器流程原始记录](final/gameplay/browser-result.json)。这只说明成长流程可用，不改变美术与 UI 未通过的结论。
