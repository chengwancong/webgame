## 优先问题

### 1. [P1] 战斗核心不能编译

位置：`client/combat/battle_core.gd:73`。

`state_snapshot()` 调用了不存在的 `rounded()`。在 README 指定的 Godot 4.7 中，直接检查即报 `Function "rounded()" not found in base self`，并导致 BattleRunner 和 headless 脚本的依赖编译失败。可见场景也引用同一模块。

证据：`20260927-m0-evidence/core-parse.log`。注意本次 Godot `--check-only` 在输出该错误时返回了 0，检查器必须同时识别错误输出和预期成功回执，不能仅看进程退出码。

处理：使用已定义且单位明确的取整／精度处理；重新执行编译检查和实际小战斗，不只搜索替换函数名。

### 2. [P1] 战斗检查在初始化失败后不能停下，会迅速写满日志

位置：`client/tests/battle_core_headless.gd:30`、`client/app/battle_runner.gd:11`、`Makefile:11`。

核心创建失败后，测试仍进入依赖 `runner.tick()` 的循环。tick 无法推进，因此 `MAX_TICKS` 不能为这条错误路径提供退出保证。`make check` 无外部超时、输出上限或隔离日志路径。

本轮以外部 18 秒超时运行 `make check`，没有得到正常测试终局，生成了 **2,948,333,568 字节**的本轮日志，随后发生磁盘空间不足，初始检查编排也未能写下汇总。已停止相关运行、保留小型错误节选并删除本轮日志。不能再次直接运行同一入口期待它自己退出。

处理：初始化显式返回成功／失败；测试有不依赖业务 tick 的最大迭代数，外层有进程超时及日志上限；所有 QA 日志放入本轮临时目录，检测到编译错误立即结束。

### 3. [P1] 声明依赖不能启动服务端

位置：`server/infrastructure/db.py:10`、`server/requirements.in`、`server/requirements.lock.txt:17`。

代码导入 `psycopg_pool.ConnectionPool`，但依赖声明、锁文件和现有 `.venv` 均没有 `psycopg-pool`。原始环境运行 `import server.main` 得到 `ModuleNotFoundError: No module named 'psycopg_pool'`；测试也在收集阶段失败。

本轮只在临时目录提供 `psycopg-pool==3.3.3`，用于进一步检查未修改的应用代码。没有安装进项目 `.venv`，也没有据此把原始环境标为通过。

处理：补齐直接依赖和锁文件，从干净环境执行 setup／启动／集成检查。`make setup` 目前还使用任意 `python3`，与 README 的 Python 3.12.14 锁定声明不一致，应显式选择或验证解释器版本。

### 4. [P1，真实账号接入前] HTTP 接口没有建立账号身份与角色归属边界

位置：`server/api/http.py:21`、`:52`、`:65`；`server/application/accounts.py:20`。

角色创建直接接受请求体中的 `account_id`，读取角色也不要求认证。重复注册同名账号时，无论密码是否匹配都会返回既有账号 ID。API 中没有登录／会话验证，因此保存了密码哈希并不等于已经完成身份系统。

在本轮一次性 PostgreSQL 中，仅使用本轮新建的测试账号复现：

- 同账号名＋不同密码：201，并返回原账号 ID。
- 没有登录凭据，为该账号创建角色：201。
- 没有登录凭据，读取该角色：200。

这是当前接口可复现的行为，不是对已部署外部服务的攻击，也不是声称发生了真实玩家数据泄露。若它只用于 M0 内部实验，必须明确限制用途；接入真实玩家前应由认证会话推导账号，逐次验证角色归属，不能把客户端提供的账号 ID 当身份。

### 5. [P1] 并发重复命令返回 500，幂等只覆盖了顺序重发

位置：`server/application/commands.py:21`。

事务先查回执，再执行角色创建，最后插入唯一回执。两个同时到达的同 ID 请求可以都读到“无回执”；第二个请求在插回执时触发唯一约束异常，当前没有转为读取已提交结果的路径。

使用真实 PostgreSQL 和原应用函数，在生产创建回调前增加同步屏障，让两次查询同时看到空回执，结果为 **201 和 500**。随后重发返回 201；数据库最终只有一个角色和一条回执。

因此这里是“并发重复请求没有稳定返回同一结果”，不是重复创建了两份资产。数据库事务回滚生效是已验证的正面结果。

处理：在明确账户／命令范围内串行化，或对唯一冲突结束当前事务后重新读取已提交回执；保留不同请求体使用相同 ID 的冲突拒绝。增加真正并发的数据库测试。

### 6. [P2] 文档中的启动命令不可复现

位置：`README.md:20`、`Makefile:17`、`tools/migrate.py:6`。

- `make db`：实际返回 `No rule to make target 'db'`，Makefile 没有该目标。
- `make migrate`：在没有外部 PYTHONPATH 的正常环境中，返回 `ModuleNotFoundError: No module named 'server'`。以文件路径直接执行 tools/migrate.py 时没有建立仓库包导入入口。

处理：统一可从仓库根执行的命令，明确数据库生命周期和 DSN 传递；用一个干净终端按 README 逐条验证。已有 `tools/dev_db.py` 文件不等于文档启动链已接通。

### 7. [P2] 数据库验证可全部跳过并返回成功

位置：`tests/server/test_first_write.py:10`、`Makefile:23`。

补足临时依赖后，未设置 ABYSS_DSN 时四项测试全部跳过，pytest 返回 0。CI 入口没有启动隔离 PostgreSQL，也没有要求集成测试实际运行。当前 `make check` 尚且被战斗错误阻断；修复编译后若不改这里，仍可能没有数据库验证却得到成功退出码。

补充验证中，提供真实隔离 PostgreSQL 后，现有四项测试全部通过。它们覆盖顺序重发、请求体冲突和普通读取，不覆盖鉴权、并发重复、真实重启或浏览器通信。名为“restart equivalent read”的测试只是同一客户端进程中的一次 GET，不能充当恢复验收。

处理：将必须运行的集成检查与可选本地测试分开；CI 缺数据库配置时明确失败，自动管理本轮数据库，检查实际执行数量与关键用例。
