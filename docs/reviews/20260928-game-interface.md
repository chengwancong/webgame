# 可见游戏路径实现与验证（2026-09-28）

本轮补齐了此前技术样例缺失的游戏表现。玩家可完成：城镇注册/登录 → 角色准备 → 开场遭遇 → 胜负结算 → 返回或再次挑战。当前仍为单场战斗原型，未完成奖励、装备和持续成长，不能按完整游戏签收。

**后续纠正：** 本文下方截图使用了错误选择的旧生成角色与敌人，现仅保留为修改前对照。当前版本已改用用户提供的小小忍者资源；最新截图、素材清单和验证见 [资源接入纠正](20260928-user-art-correction.md)。本文的 164 项资源统计属于修改前版本。

## 已实现

- 城镇和战场使用现有 2D 素材；英雄与敌人显示移动、攻击、受伤、倒下和胜利动作。
- 场景显示真实目标、敌方生命、角色生命、技能伤害与剩余冷却；伤害飘字与结算统计来自实际战斗事件。
- 技能按钮与 1/2 键提交真实核心指令；空格暂停、自动技能切换与 0.5×/1×/2× 播放可用。取消返回保持原暂停状态，结算时禁用背景操作。
- 登录和角色读取使用真实 API；重试重新读取服务端 BattleSpec。表现层消费状态与事件，动画不决定命中。默认自动策略及战斗数值未改变。
- 桌面横屏 1280×720，比例缩放，最低原生窗口 960×540；本轮未完成移动端界面适配。

设计记录：`../03-presentation/playable-interface.md`。素材来源、字节与 SHA-256：`../../client/assets/art/source-records.json`，164 项哈希核验通过。素材用于本地内部试玩，保留上游待审阅发行状态。

## 验证结果

- 标准 `make check`：44 passed、0 failed、0 skipped，报告 `ok=true`。包含真实 PostgreSQL/API、账号与事务、Web 导出、真实浏览器流程、可见与 headless 战斗一致性，以及新增表现层控制回归。
- 定向检查：暂停、手动技能、冷却、结果面板，加上终局与核心失败检查，11 项通过。新增用例在真实场景上调用实际核心，不用假数据替换施法逻辑。
- 实际 Web 试玩：键盘输入注册/登录、出发、暂停、取消返回、切换自动技能、手动横扫、完整胜利、返回准备和再次挑战。浏览器错误记录为空。
- 默认战斗：39 tick、20 个事件、胜利、击败 2 个敌人，造成伤害 82、承受伤害 16，与实际结算一致。手动横扫另有真实 `cause: sweep` 事件记录。
- 原生 Godot 已启动且启动日志无错误，但本轮未完成原生 UI 的全流程验收，不能用启动结果替代原生操作验收。

首次完整运行显式指定 `ABYSS_CHECK_REPORT` 后，嵌套故障注入测试仍读取默认报告路径，导致 43 通过、1 失败。确认该报告路径冲突后，使用未覆盖该变量的标准 `make check` 重跑，44 项全部通过。原始说明保存在 `20260928-game-interface/verification-notes.json`。

证据：该目录下 `check-report.json`、`check.log`、`default-trace.txt`、`manual-skill-trace.txt`、`browser-errors.json` 与 `native-startup.log`。
