# 首条可见游戏路径

本轮目标：玩家登录后看到自己的角色与当前遭遇，进入可见战斗，观察接近、攻击、受伤、倒下，操作真实技能，查看战斗结果并返回准备界面。

视觉使用用户提供的小小忍者原工程资源的离线 PNG 转换成果。角色、怪物、武器、城镇、战斗背景、技能图标和命中特效来自同一资源体系；此前接入的旧 `bright_anime_v2` 生成角色与背景已替换。画面是界面主体，控制区依附场景边缘，也不添加未实现的金币、背包或奖励按钮。

主题色：深海蓝 `#1b3145`（边框与信息底）、羊皮纸 `#f5edd8`（面板）、旧金 `#d3aa63`（主要操作）、翡翠 `#43b69b`（生命）、朱红 `#be6253`（危险）、墨色 `#283949`（正文）。正文复用 Noto Sans SC，标题增加字号和留白，不另引入字体依赖。

布局：桌面横屏 1280×720，整体缩放并保留比例，原生窗口最低 960×540。

```text
登录：城镇全景 + 左上游戏标题 + 右侧冒险者登录面板
准备：城镇全景 + 左侧角色/真实战斗参数 + 右侧当前遭遇/出战
战斗：顶部目标/敌人数/暂停，中央角色战场，底部生命/技能/自动模式
结果：战场仍可见 + 中央胜负/伤害/击败数 + 返回准备/再次挑战
```

复核：检索出的通用游戏产品建议包含网站展示与 3D 效果，不适用于本作 Godot 2D 游戏；仅采用信息层级、对比度、焦点和操作反馈原则。最终风格由现有游戏美术决定。

工程边界：场景只消费 BattleSpec、核心快照及事件，动画不决定命中和奖励。自动模式默认保持既有输入策略；手动施法、暂停、演出速度只影响输入或播放，战斗核心继续显式步进。返回准备保留本次登录与角色镜像，再次挑战重新请求服务端开场数据。

战斗结果只报告本场事实；奖励和成长尚未实现，界面明确说明。素材来源及哈希见 `client/assets/art/source-records.json`；动作序列、脚点、朝向、身体和武器层映射见 `client/assets/art/actors.json`。本构建用于本地试玩，未将完整人物库和物品库算作已实现内容。
