# 开发交付与发布准备

本记录给出本地已实现路径与生产准备条件，不代表已对外发布。

## 本地可玩交付

安装锁文件依赖，导入已有用户资源，执行 `pnpm build`。正常产物为 `apps/web/dist/`，包含本地字体、图集和客户端；不存在stress入口。API可直接服务该目录。`pnpm dev`则运行Vite代理与独立数据库。两种入口使用相同业务接口，不使用QA账号夹具写入。

当前 Mac 可以使用 `pnpm service:install` 安装登录自启与退出重启的后台预览；管理、系统权限、数据保留和运行限制见 [本机常驻服务](local-dev-service.md)。它与前台 `pnpm dev` 二选一，不代表生产部署。

桌面 `pnpm desktop` 加载本地dist，API默认127.0.0.1:8611，可用AW_DESKTOP_API指定。现有验收只证明当前Mac实际Electron窗口可以加载本地文件与界面，不是已导出的Windows安装包、Steam版本或签名发行包。

## 生产首次发布步骤

1. 创建专用生产PostgreSQL18数据库及受限账号，与开发、测试、旧版隔离。保存备份与恢复入口。
2. 部署锁文件构建的Web资源与API源，校验源版本、协议、规则、资源版本和数据库版本。
3. 配置 `NODE_ENV=production`、`AW_DATABASE_URL`、`AW_ORIGINS=https://实际游戏域名`；API绑定内部地址，由HTTPS反向代理转发。缺少生产来源时当前程序拒绝启动。
4. 在测试环境完成真实Cookie、来源策略、注册/重登、权限、幂等和备份恢复。日志只记录关联标识，禁止打印密码/Cookie/DSN凭据。
5. 在约定硬件执行100会话报告、20Mbps冷启动、两小时连续运行；对实际公开服务补齐认证限流、监控和异常响应。
6. Windows实机、桌面安装资源路径、沙箱策略、控制权与网络恢复通过后再生成对应交付包。Steam另行接入服务器票据验证，不接受客户端SteamID证明身份。
7. 发布前核对本次所有素材许可与实际图集哈希；不将尚未确认许可的开发资源直接作为商业发行素材。

尚未执行生产数据库创建、域名/HTTPS配置、公开部署和Steam后台操作。

## 备份与回滚

开发QA工具实际使用pg_dump/pg_restore，在本次临时集群中的另一数据库恢复并核对结果；不向玩家数据库恢复。生产备份应在独立受控存储中，先恢复到新库验证，再切连接。严禁为验收清空正式库。

内容发布先记录版本。扩展数据库采用可兼容的分步变更；若旧API不能读新结构，就不能仅回退API。当前没有完成在线滚动升级/旧规则结算窗口与回滚演练，必须作为首次生产前的验收项。

## 运行与清理

新版 `.runtime/dev/data` 保留开发成长；QA `.qa/run-*`带所属PID与工具标识，停止本次API/数据库后删除，成功与失败均执行。停止无法核实时保留并报错，不将残留计算为释放。符号链接不跟随处理。

旧Godot导出、存档、旧数据库与cloudrealm不在新版清理范围。最终截图、数值对照、验收JSON和正常Web产物保留。执行 `pnpm check` 后查看cleanup.bytes_before/after与ok，不以退出码或测试数量单独代替验收。
