# 《深渊行者》UI整改方案

日期：2026-09-28｜状态：整改设计，未实施｜对象：open-world Web / Electron 客户端。

本轮交付整改方案和HUD布局示意，未修改正在运行的游戏。此前的功能验收只证明操作与数据闭环，不能证明视觉设计合格。本次将界面体验作为独立验收项。

## 1. 当前问题与整改目标

依据实际截图world-battle.png、inventory-restored.png、desktop.png，以及style.css、presentation.ts、scene.ts和main.ts审查。

|问题|具体证据|对玩家的影响|整改|
|---|---|---|---|
|视觉像网页卡片|角色、余额、任务、模式都用类似浅色圆角块|注意力分散，难以感知战斗主次|紧凑游戏HUD，明确角色/技能/任务/系统四个区域|
|世界与UI缺少共同风格|高饱和侧面角色搭配淡绿格纹与奶油卡片|角色像贴在测试地图上|保留角色，采用克制的深色面板与素材线框；场景单独统一|
|技能不可识别|四格使用✦/◈/❖/✧，缺少技能视觉语义|难以快速定位和记忆技能|真实技能图标、快捷键、状态遮罩和说明|
|入口过多且同权重|右下按钮换行，回城、设置、战利品等挤在一起|频繁操作和低频功能混杂|稳定四入口，战利品并入背包，自动设置靠近模式控件|
|常驻信息过多|WASD说明、区域副标题、余额和任务大块常驻|挤占视线，重要危险反而不突出|教学按阶段显示；区域名称短时出现；目标收为两行|
|背包像文字目录|装备列表没有图标，比较藏在一句长文本里|难以扫视重复、槽位、效果变化|装备槽+图标网格+明确对比详情|
|场景可读性不足|均匀菱形棋盘、怪物整齐点阵、背景装饰少|移动空间、道路和地点缺乏记忆点|淡化格纹，区分路径/障碍/地标，重排遭遇空间|
|反馈层级冲突|名称、地面奖励标签、飘字与人物接近|密集战斗容易挡住角色和危险|分层、筛选、合并，重要警告有固定区域|
|DOM刷新策略粗糙|renderHud整块innerHTML每180ms替换|有焦点、悬浮提示和持续操作被中断的风险|一次挂载、按字段更新，动画独立驱动|
|面板键盘规则不足|覆盖层阻断鼠标，但没有完整对话框语义和焦点管理|Tab可能到达背景控件，退出后焦点丢失|面板焦点范围、背景不可交互、Esc与焦点恢复|

目标是让玩家先看见自己、敌人和危险，再读取生命和技能，最后查询成长系统。服务器成功返回不是界面通过的替代证据。

## 2. 推荐视觉方向

方向：与现有卡通侧面角色相容的冒险RPG界面。世界保持明亮、可探索；HUD采用深墨灰、细金属边与少量暖金强调。角色、技能图标保留颜色，面板退到背景。

这是本次建议，尚未经过用户视觉验收。不要把整张地图压暗，不做霓虹科幻风，不给每个区域套同一种大圆角卡片，也不靠大面积装饰堆砌所谓游戏感。

|用途|初始色值|规则|
|---|---|---|
|HUD底色|#202A30|文字后必须有足够稳定的底，透明度依据最亮地图检验|
|面板内层|#2B383E|以空间和细分隔线分组，不重复套大量卡片|
|正文|#F0E9D8|数值、技能名、操作说明|
|次级文字|#B9C4C3|仅用于辅助信息，不承担危险或禁用原因|
|选中/重要操作|#D3B16C|限制用量；选中还需描边/标记|
|生命/危险|#C95B57|同时使用生命图形、区域边界与提示符|
|技能资源|#63A6CA|与生命明确区分，标注图形和数值|

字体继续使用已有Noto Sans SC。常规正文14–16px，辅助信息原则上不低于12px，面板标题20–24px，数字使用等宽数字特性。具体可读性以720p和实际字体渲染确认。标题装饰只用于登录或面板标题，不能影响读数。

窗口边框可使用已有素材做九宫格适配，角部尺寸保持稳定；不把一张小窗口PNG直接拉伸成大面板。图标与按钮必须有正常、悬浮、按下、焦点、禁用、等待状态。

本地风格检索返回像素和科幻HUD，均不适合当前素材，未采用其配色/字体/模板；本方向来自截图及真实资源审查。交互资料仅用于焦点、反馈和渐进展示原则。

## 3. 战斗HUD重新布局

以1280×720、键鼠优先设计；720p是第一张验收画板，再做1600×900和1920×1080。不是把1920版整体缩小。

```text
┌──────────────────────────────────────────────────────────┐
│ 头像/等级/生命/灵力         临时区域名或Boss条      小地图   │
│ 当前目标两行                                   地点/方位 │
│                                                          │
│                                                          │
│                角色、敌人、危险和掉落                       │
│                   战斗视觉保留区                           │
│                                                          │
│                 [E] 附近交互提示                          │
│     当前模式/停止原因        1  2  3  4       背包 构筑     │
│                           技能快捷栏          目标 设置     │
└──────────────────────────────────────────────────────────┘
```

### 角色信息：左上

头像采用实际外观预览资源，不截取一张随机攻击帧。姓名/等级置于同一行，生命条主显示，灵力条次显示。精确生命值保留，但不用重复两套标题。护盾单独覆条或数字标记，不与最大生命混合。

异常状态只展示有影响的当前状态，剩余时间和来源在焦点提示中显示。钱包、材料、装备容量移至背包；获得金币时播放简短奖励反馈。

### 目标：角色信息下方

默认一个标题、一行进度或方向。点击展开详情。WASD/技能说明按教学阶段出现，完成后退出常驻区域。“前往结界”保持可发现，但做成目标内的路线操作，不能与战斗主操作抢同样的视觉权重。

### 小地图：右上

地图、名称和方位整合；安全点、首领、交互点和当前位置使用不同图形并提供图例。危险和未解锁状态不能只靠颜色。移动目标方向持续显示，详细世界地图属于后续独立面板，不假装现已有完整探索系统。

区域大标题仅在入区短时出现；首领条占上中固定位置，普通地图不常驻一个大标题。

### 技能：下中

四个固定槽位，图标48–56px，实际按钮区域不小于48px。快捷键放角落，冷却采用统一遮罩+剩余秒数。不可用原因须区分：冷却、灵力不足、射程不足、暂停、死亡与等待确认。

不在每格常驻长技能名和消耗说明。悬浮或键盘焦点显示技能名、效果、耗蓝、冷却、射程和当前不可用原因；新手首次装配可显示短名称。快捷键必须从实际绑定读取。

### 自动模式：技能旁

紧凑展示当前模式、正在做什么、展开设置的入口。三模式可展开切换，当前模式同时以文本和选中标记表达。停止原因就地显示可执行操作，例如“背包已满 → 整理背包”；网络暂停与玩家主动关闭必须区分。

活动边界平时弱显示，配置时强化显示；边界不能与伤害预警相同颜色和线型。不开启复杂脚本界面。

### 系统入口：右下

固定为背包、构筑、目标、设置四个可读入口，带一致图标与可见名称。待领取装备放背包的“待领取”页和角标。回城置于地图/地点交互或展开菜单，保留可发现性，不塞进主技能栏。

普通消息靠边；断线或控制权失效需要固定状态条和恢复操作。普通奖励不弹中心模态框。

## 4. 背包、构筑与其他面板

### 4.1 背包

采用游戏内整理面板，打开时明确暂停战斗。桌面参考布局约960×560，可随视口调整。

- 左：角色外观与武器、护甲、饰品、核心四槽。选中槽位筛选对应物品。
- 中：24格图标网格，支持部位筛选、排序、选中和锁定标识；待领取作为同一面板的页签。
- 右：选中装备详情、与当前装备逐项对比、关键效果变化、穿戴/强化操作。

比较必须有“当前 → 更换后”与增减符号。特别列出效果失去/获得，例如“失去飞行物穿透”；总属性增加不能掩盖效果损失。当前数据没有品质/随机词缀字段，本轮不能凭UI颜色虚构稀有度或额外属性。

强化展示服务端成本和正式变化；未取得预览时显示读取中或失败，不能用默认成本代替。装备操作等待期间禁用重复提交并保留选中、滚动和面板位置。失败保留原装备、余额和可恢复的操作上下文。

分解与装备/强化分开。已装备或锁定物品解释为什么不能分解；不可恢复的分解给出明确二次动作或短确认，不对普通选中/换装反复确认。

### 4.2 技能构筑

上方四个装配槽，下方技能库；每个技能用实际图标、简短机制与状态。支持点击装配/移除，调整施放优先顺序提供按钮，拖动只作辅助。必须能用键盘完成。

升级与装配是两种动作，空间上分开。当前实际伤害读取已解析快照；未装配技能先展示机制及公开基础参数。若需要展示任意技能的升级伤害预览，须提供服务端只读预览，不能在UI复制成长公式。

草稿装配、服务器已保存构筑、正在提交状态明确区分。关闭未保存草稿提供保留或放弃路径。

### 4.3 自动设置

将范围/中心、目标策略、技能优先、拾取/停止条件分组，默认先显示最常用的范围与精英接战。尚未实现的策略不能画成可用功能。低血停止/拾取过滤需要对应自动执行器和行为验证，单独列开发任务。

### 4.4 首领与失败

进入面板显示实际首领外观/名称、已见过的机制、进入和返回操作。待尾批确认有明确状态，不重复进入。

失败页突出返回据点/重新准备；当前没有完整伤害归因时，不伪造“主要死因”。先展示可证实的最后危险或伤害来源，记录能力补齐后再展示完整分析。

### 4.5 登录与营地

登录采用游戏标题界面：实际可用背景或组合场景、游戏标识、简短主操作，表单为次级区域。不要整屏空色加巨大登录卡。背景依据实际资源做适配，不能用一张宣传画证明游戏世界已完成。

营地有NPC、锻造/远行地标和短交互提示。系统操作通过空间入口与快捷键同时可达，不把营地做成菜单背景。

## 5. 战斗可读性与场景整改

这部分与HUD并行，是独立美术/关卡任务，不能算成“改了CSS就完成”。

1. 取消显眼棋盘格，把导航格与视觉地面分离。道路通过连续纹理、边缘和地标辨认。
2. 保留现有角色，不替换成与用户提供资源无关的人物。按可见身体高度、脚底锚点和武器范围统一比例，不以透明画布大小缩放。
3. 场景与角色先做一张组合样板。已有生成场景道具偏另一种幻想风格，必须检查线条、光照、色彩和透视；不因“已有文件”就全量混入。
4. 整齐排列的出生点改为路径旁的遭遇组，主路、支路、安全点与首领准备区形成节奏。这会触及Tiled内容，须单独做战斗与成长回归。
5. 玩家轮廓、地面危险边界、精英标记优先于飘字、奖励名牌和装饰。拥挤时合并飘字，普通怪血条按交战/选中显示。
6. 危险圈边界来自真实形状与时点。预警与命中阶段区分，添加方向/形状提示；减少特效模式仍必须保留危险。
7. 掉落先显示图标/光柱，近距离或选中时才显示物品名，避免每个装备永久铺开文本。只有服务端确认的装备才能显示具体属性。

## 6. 现有资源如何落地

本轮已确认以下目录与清单存在，且已查看窗口框、技能图标及场景道具预览。存在不代表全部适配或许可已确认。

|资源|实际位置，相对于旧game工程|处理方式|
|---|---|---|
|窗口框、槽位、页签|assets/imported/pockie_media/windows/|九宫格/平铺边框，先验证角部与内容区|
|按钮三态、输入框、进度条|assets/imported/pockie_media/ui/|按状态映射，补键盘焦点和禁用态|
|技能图标|assets/imported/pockie_media/skills/|逐个按机制匹配；whirlwind可作旋风斩候选，其余不得仅按旧文件名硬绑|
|装备图标|assets/imported/pockie_items/|按四槽及当前底材映射，处理留白与比例|
|功能图标|assets/icons/ui/|核对是否与所选界面风格一致，避免混用多套轮廓风格|
|资源来源|pockie_media/manifest.json、pockie_items/manifest.json|保留原源文件、哈希、适配和授权核对记录|
|场景候选|assets/sprites/environment/abyss_scene_props/|属于之前生成的道具包，先做兼容性样板，不冒充原Pockie场景|

新版资源清单增加UI映射、显示尺寸、状态、切片边距、原生分辨率、来源和哈希。小图标不直接放大到模糊的大图；不足时检查原资源可否重新导出，仍不足才补制，并统一笔触。

资源优先级：角色原资源保留 → 技能/装备/系统图标 → HUD/窗口框 → 一处营地和一处野外组合 → 其余区域。新资源不得反向写入旧游戏业务表。

## 7. 工程落地与模块联动

|位置|整改职责|联动边界|
|---|---|---|
|apps/web/src/style.css|提取颜色/字体/间距/层级token与分辨率布局|只影响视觉，不另写成长规则|
|apps/web/src/presentation.ts|按HUD/背包/构筑/提示拆视图组件|消费快照、预览和本地状态，发出操作意图|
|apps/web/src/main.ts|面板管理、输入焦点、暂停原因、提交屏障|保持尾批→写命令→新构筑边界|
|apps/web/src/scene.ts|血条、危险、掉落、遮挡与场景表现|只消费模拟结果，绘制不决定伤害和奖励|
|packages/asset-manifest|UI/图标映射、资源状态与版本|公开资源；不包含私有奖励规则|
|packages/content/maps|确需调整的空间、地标与遭遇|单独配置任务与回归，不能在scene另留坐标副本|
|API / contracts|仅在新增预览或缺少真实展示字段时扩展|服务端仍持有资产、消耗、奖励和成长|

关键实现要求：

- HUD节点稳定挂载，按变化更新条值/文字/图标；冷却视觉随帧更新，不能每180ms销毁全部按钮和小地图。
- 面板具备dialog语义、初始焦点、可见焦点、Tab范围、Esc优先级，关闭后回到原触发控件。背景键盘与指针输入都阻断。
- tooltip支持悬浮及焦点，不能跟随每次HUD刷新消失；屏幕边缘自动调整位置。
- pending与disabled分开。无资源/未解锁使用正常禁用提示，不显示“正在等待”光标。
- 配置的快捷键用于实际提示；不要设置页改绑后HUD仍显示旧键。
- UI动画不解除死亡/网络/后台/主动暂停。确认等待中不可重复装备、强化或进入首领。
- 不乐观增加正式金币/装备；可先给操作反馈，成功结果以服务器回执为准。
- 不为这轮UI整改换引擎、引入整套大型组件框架或重写服务端。

## 8. 实施顺序与交付门槛

|批次|工作|必须交付/通过后再扩展|
|---|---|---|
|A：定视觉|素材筛选、UI token、战斗HUD与背包高保真图|1280×720两张图，使用真实素材；本次布局图只是结构示意|
|B：HUD切片|稳定DOM、技能图标、模式/目标/系统入口、焦点与暂停|一处地图内真实战斗和自动接管视频/截图，验证鼠标键盘|
|C：系统面板|背包四槽+网格+比较、构筑、强化、待领取与异常状态|获得装备→比较→换装→强化→重登恢复完整流程|
|D：场景与反馈|一处营地、一处野外组合、危险/掉落/血条层级|密集战斗可读；样板通过后才扩到其他地图|
|E：统一验收|登录/营地/首领/失败、分辨率、压力与回归|统一版本的正式截图、试玩记录、API与纯核心验证|

不承诺未经拆分评估的固定工期。优先A/B/C；D作为明确的场景制作批次，不能因HUD换色宣布整个世界画面完成。

## 9. 验收标准

下面是本轮整改的目标与检查方法，均不是已经测得的成绩。

|项目|通过标准与方法|
|---|---|
|视觉焦点|首次看战斗图先能找到玩家和主要威胁；真实用户观察，不用自动测试冒充主观验收|
|世界可见范围|1280×720普通战斗，中心约60%宽×60%高区域无常驻大面板；HUD不遮挡角色及附近危险|
|HUD占用|以常驻组件可见边界测量，目标屏幕面积不高于20%；不靠降低文字可读性实现|
|技能识别|四技能有不同语义图标，玩家可说出对应功能；冷却、缺资源、超射程有区别|
|装备判断|不看总战力也能理解属性变化与关键效果损失；已装备、锁定、选中同时可辨|
|反馈|操作后立即呈现按下/等待状态；网络等待显示明确原因；失败原资产不变|
|键盘|Tab能完整操作面板，不进入背景；Esc层级正确；输入框不移动角色；恢复焦点正确|
|对比与颜色|普通文本对比目标≥4.5:1，大文本与必要图形目标≥3:1；实际最亮/最暗场景测量；危险另有形状提示|
|尺寸|1280×720、1600×900、1920×1080，以及桌面最小窗口无控件重叠/裁切；窄窗口采用紧凑布局，不把所有内容简单缩小|
|状态覆盖|正常、悬浮、焦点、按下、选中、等待、禁用、空、错误、成功均有样例|
|核心完整性|30Hz规则与服务端资产保持正确；换装尾批、重复请求、恢复和控制接管仍通过|
|性能|在同硬件/种子/内容版本比较，200敌人/300飞行物场景P95帧耗时≤20ms；新HUD不能频繁重建或重复绑定事件|

文字对比目标参考 [W3C Contrast Minimum](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)；面板键盘交互参考 [W3C Dialog Modal Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)。这只列整改依据，不声称当前游戏已满足整套规范。

前后对照必须用同一区域、角色、视口和类似战斗压力。仅截一张静止主城、只报测试数、或只改配色都不算整改通过。
