# 初版数值模型与验证

版本：core-1 / ow-1。工具直接导入 simulation.World 与服务端 resolveBuild，替代时间、输入与表现，不另写战斗模型。

问题：三种初步构筑在选定等级和装备下，能否产生有限的首领结果，是否出现无法生效的技能或资源循环？当前不根据机器人胜率推断真人难度。

单位：世界距离为格；30Hz步骤；HP/伤害/经验/金币为整数；灵力连续恢复但消耗整数。伤害参数由服务端解析：技能基础伤害×(1+正式攻击/45)×技能等级倍率，最后取整。HP=180+等级×18；经验门槛=等级×85。普通金币/经验/材料为6/10/1，精英18/24/2，首领120/100/8，值为待调初稿。

构筑是情境关系：近战范围、远程控制、持续区域，不能以单一DPS排序替代范围、生存和移动。

场景：三构筑×等级1/3/5×种子11/23/47/71/101，共45次；上限180模拟秒。自动策略full-auto-v1，普通武器/护甲/核心已装配。记录生命、灵力、耗时、结果和停止原因。

已知校验：手动与自动同入口；技能消耗与冷却；穿透命中第二目标；链伤、燃烧、护盾；暂停无推进；相同种子指令同状态。均在核心回归中执行。

`pnpm balance` 输出JSON；`pnpm balance -- --hp=0.75`、`--hp=1.25` 做配对敏感性，不改正式源。初稿选择不因单个种子胜利而定稿。正式接受需加入低投入、失误、无治疗、经济成长场景，并观察真实新玩家。

明确遗漏：该工具不模拟服务端随机掉落、玩家背包整理、任务理解和网络；未评估三条完整成长路线长期资源分布；当前不是最终平衡签收。
